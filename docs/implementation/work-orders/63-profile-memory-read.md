# Work Order 63 — Profile 记忆读取面（只读、有界、零凭据）

状态：**READY_FOR_EXECUTION**（2026-09-17 由 P17 修订的"记忆查看"需求派生；实现未开始）。
依赖：与 51–60 **共用一次 wire 重锁**；与 **45**（原生 home 是事实来源）同源。
配对前端单：桌面工作树 **P17 修订**（"记忆"分区）。

## §0 目标

让 profile 设置里能**查看该角色的记忆**：harness 自己维护的记忆/指令文件（各家形态不同，如
`CLAUDE.md`、`AGENTS.md`、`.hermes/` 下若干、`.config/opencode/AGENTS.md` 一类）。
**只读、有界、零凭据**；**只列声明过的路径**，不做全盘扫描。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 声明驱动** | 每家的**记忆路径**由**注册表声明**（新增声明字段，例 `memory_paths`），服务端不硬编码品牌；未声明的家 → **不显示记忆分区**（前端按可用性隐藏） |
| **G2 有界** | 单文件上限、条目数上限、总字节上限；超限**类型化失败**并给原因，不静默截断 |
| **G3 零凭据** | 读取路径先过第 45 的**凭据扫描**规则：命中即**拒绝返回该文件**（类型化），**文件内容零日志/零证据** |
| **G4 只读** | 只从该 profile 的**原生 home**读；**不写**、不新增文件、不改权限位；符号链接**不跟随** |
| **G5 来源诚实** | 返回 `path` 与 `digest`；文件不存在 → 该项**缺失**（不是空字符串）；家不存在 → 类型化原因 |
| **G6 不退化** | wire 锁定值不变（同批重锁）；45 的三条规则（只读配置/tmpfs 遮蔽/受保护路径）不放松 |

## §1 现状与做法

- 记忆文件的实际位置**逐家不同**（Claude Code 的 `CLAUDE.md`、Codex 的 `AGENTS.md`…）——
  与 59（hook 模型）同样的取证纪律：**阶段 A 逐家实测**，写进注册表声明，**不用品牌分支**；
- 只读面复用**已有的读路径**：本机放置直接读、WSL 走既有通道（**Rust/Worker 协议不动**），
  与 45 的审计读同族；
- **与"指令资产"（60）区分**：指令是**我们注入**的只读投影；记忆是**harness 自己写**的文件。
  两者在 UI 上分两个分区，**不得混为一谈**。

## §2 硬性规则

- **零写入**、**零凭据内容**、**零宿主绝对路径进记录**（locator 只在执行侧解析）；
- 声明未覆盖的文件**不读**（不做"顺手把家列一遍"）；
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用。

## §3 六件套 DoD 与报告

实现 / 定向测试与反例（超限、凭据命中、符号链接、缺失文件、无 home）/ 逐家实测证据（路径与形态）/
回归计数 / status 分账 / 清理证据。
报告含：注册表新增字段与逐家值、字段与类型化码表、与指令资产的分界说明、两仓摘要（若重锁）、未做项。
