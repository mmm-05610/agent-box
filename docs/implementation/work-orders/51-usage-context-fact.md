# Work Order 51 — 用量/上下文事实端到端（真实数据，禁止估算）

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 批准；实现未开始）。
依赖：50（能力层吸收）之后；**阶段 B–D 与 47/48 串行**（同一批通道与 wire 文件）。
依据：2026-09-16 只读排查（下表）与前端的 P08（它已有一个"无数据即未知"的容器在等这个面）。

## §0 目标

让"上下文百分比"这类数字**从后端来、且只报真实值**：harness 原生报什么就转发什么，
没报就**未知**；**禁止估算**（用户明确）。前端 P08 的容器只负责显示。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 逐家观测** | 每家给出"原生侧到底报不报用量、报在哪、单位是什么、上下文窗口从哪来"的**第一手结论**（命令 + 观察）；不报的家如实标注 |
| **G2 中立事实** | 桥/驱动把原生用量映射成**一条中立事件**（不含品牌词）；**缺的字段就缺失**，不许补猜、不许用转写长度代替 |
| **G3 Server 记账** | 该事实进入 turn/session 投影（事件账本 + 会话上"最新值"），重放/翻历史时一致 |
| **G4 wire 重锁** | 合同变更走完流程：TS 与生成工件摘要**两仓同步**、严格事件 schema 用例通过、28 方法集不被动摇（新增面不改既有方法语义） |
| **G5 诚实显示** | 不报的家在前端显示"未知"（由 P08 的容器承接）；反例测试：任何路径都不得产出估算值 |
| **G6 不退化** | 全量套件 + 四家全链门（显式 bundle 口径）+ 45/47 的门不退化 |

## §1 现状（第一手，动手前复核）

- **全链没有用量**：`plugins/agent-box-harnesses/third_party/harness_remote/**` 与
  `deploy/opencode/driver-native.mjs` 里 `usage`/`token` 零命中；Server
  `execution/sidecar.py` 的 `_forward()` 只认 `agent_message_chunk` / `message_delta` /
  `permission_request` / 退出；wire 里 `usage`/`tokenCount`/`percent` 零命中。
- **ACP 带，但"不稳定且可选"（更正）**：早先本单写的是"ACP 协议本身不带用量"——**那句是错的**：
  当时 grep 的文件路径不存在、错误被 `2>/dev/null` 吞了。按 vendored schema
  （`.../@agentclientprotocol/codex-acp/node_modules/@agentclientprotocol/sdk/schema/schema.json`）
  第一手核对：`PromptResponse.usage` 存在，注释为
  "**UNSTABLE** … Token usage for this turn (optional)"，类型为 `Usage`（可为 null，
  且标了 `x-deserialize-default-on-error`）。
  → 结论改成：**协议位置有，但标着不稳定、且可空**；ACP 系各家**是否真的填**、以及填什么字段，
  是阶段 A 必须给第一手证据的事（**不许**按 schema 有就假定会用）。
- **可能有的家**：Codex（app-server 有 token 类通知，我们的适配器**目前没读**）、
  OpenCode（每个 message 可能带用量，driver 是否拿到未验证）；Hermes / dsh / qwen / claude-code 未查。
- **分母要单独找**：百分比需要"上下文窗口大小"。它多半**不在 harness 的用量事件里**，而在
  部署的模型文档（例如各家的 models 目录）或 harness 的模型元数据里——**逐家确认**，缺就显示未知。

## §2 阶段

- **A 逐家观测（无代码改动）**：对注册表里每家跑一轮（假端点即可，**零真实模型**），
  记录：原生是否报用量 / 报在哪一层（协议事件、会话文件、app-server 通知、server API）/
  字段与单位 / 窗口大小的来源。产出 `docs/server-round1/fullstack/usage-observation.md`（逐家表 + 证据）。
  **这一步决定这个面长什么样**，不得跳过。
- **B 中立事实 + 映射**：在 sidecar envelope 增加一条中立事件（参照 `message_delta` 的做法：
  事件名是中立的，各家映射进它），字段只包含观测到的（例如 `inputTokens` / `outputTokens` /
  `contextWindow?` / `contextUsed?`）；缺失即缺失。驱动侧（`driver-native.mjs` 一类）同规则。
- **C Server 记账**：`_forward()` 增加该事实 → 写进 turn 事件账本与会话投影（"最新用量的值 +
  它是哪一轮的"），保证 `history.snapshot` 重放与实时两条路径一致。
- **D wire 重锁**：按观测结论选择最小变更（推荐：**新增一个事件 kind** 用于实时 + 在会话/轮次
  投影里带"最新值"以便后加入的客户端直接读到）。走完两仓同步：TS 与生成工件的新摘要、
  严格 `EventFrame` schema 用例、`wire-review.md` 记录。**跨仓写权按 42 的条件**（双门 + 已释放租约）。
- **E 交前端**：把合同与样例值交给前端（P08 的容器转正）；前端消费若有形状问题，**追加一张前端单**。

## §3 硬性规则

- **只转发真实值**：没有就未知。**禁止**估算、禁止用转写长度/字符数代替、禁止用别家数回落。
- 事件名与字段**中立**：不得出现 harness 品牌词（各家的原生字段名只在映射那一处出现）。
- 事件负载是**严格 schema**：新增字段/事件必须同时更新两仓的合同与生成工件，并让既有严格用例继续通过。
- **不改既有 28 方法的语义**（只允许新增面）。
- 真实模型调用：本单默认零（假端点足够观测结构与字段）；确需真实调用按用户当次授权口径、逐笔记账。
- 凭据只作 locator；不读真实 `~/.codex` 等登录态；不 reset/stash/clean、不 merge main、不 push。
