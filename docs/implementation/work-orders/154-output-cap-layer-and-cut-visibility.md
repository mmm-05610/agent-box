# Work Order 154 — **「你只能一次输出这么多吗」**：量出输出上限配在**哪一层**，并让「被砍断」**可见**（`ACC-R5-9`，**用户亲口撞到**）

## Objective

**来源：`ACC-R5-9`（A 线验收第 5 轮`round-5.md` §5；**用户本人在界面里连发三句**：「what？」、「说完」、**「你只能一次输出这么多吗」**）＋ ops 第 167 轮开单。**

**A 的第一手定量（不是猜测）**：每一轮助手回复**都被砍断**，长度依次 **87 / 89 / 77 / 96 字符**；**四次终态全部 `completed`、`reason` 全部 `None`**；
**第 3 轮模型先道歉**（"抱歉，我上一条回复出错了…正确输出应为："）**然后又砍在同一量级** ⇒ **一处稳定的输出上限**，**不是模型随机**。

**ops 一手补一条关键读数（不是猜）**：**部署模板里写的是 8192**——`plugins/agent-box-harnesses/deploy/pi/models.json:14` 的 **`"maxTokens": 8192`**。
⇒ **`ACC-R5-9` 观察到的 ~90 字符（≈60–70 token）上限并不来自这一层**（或至少不只来自它）⇒ **上限配在哪一层，今天没人量过**。
**这就是本单的第一格**（A 原话：「`122` 族 ＋ **新增一格**「上限配在哪一层」（pi harness／provider 记录那一层，**A 只报现象不猜实现**）」）。

**为什么这是本单里**最重**的一格**：**用户在验收时亲口撞到**，而且它同时打在**闭环第 ④ 步**（"收到回复"——**被砍断的回复不算真回复**）与**第 ⑤ 步**（"失败可见"——**今天连"砍了"都不说**）。

## 与前单的关系（`R-0076 ④`：**别并格，也别分裂**）

| `122`（`TRUNCATION_VISIBLE_PARTIAL`） | 「砍断**要可见**」 | 沿用它的口径；**本单不改它的定义**，只把**用户实例上真实发生过的那一次**变成可复现的读数 |

**硬约束**：**不许**把"上限是 8192 所以没事"当结论（实测砍在 ~90 字符）；**不许**把「砍断不可见」并进 `108` 的格子（`R-0076 ④`）。

- 若量出的那一层是 **pi 适配器/上游**（不在本仓）⇒ 同样写清并交回（这类只能靠产品面的"上限可见/可配"来兜）。

## Requirements

### Requirement: 「上限配在哪一层、值是多少」必须有一行可判定的答案；「被砍断」必须可见

#### Scenario: 量出生效层（正例，本单主目标）

**WHEN** 走一遍真实请求路径（单内 `parallel_units: locate-layer`）
**THEN** 账上有一行：**生效值＝X，来自第 N 层**（含每一层的**观测方法与原始输出**；模板层的 **8192** 与实测 **~90 字符**必须同时解释清楚）

#### Scenario: 用户实例上那一次可复现（正例）

**WHEN** 用与 `ACC-R5-9` 同形的输入（一段**明确要求长输出**的提示）跑一轮
**THEN** 要么**拿回完整输出**，要么**该轮带可见的"被砍断"标记**（码 ＋ 人话），**不得**是 `completed` ＋ `reason: None` ＋ 内容被砍

#### Scenario: 被砍断可见（反例，必须）

**WHEN** 把上限压到极小（例如 32 token）跑一轮
**THEN** 该轮**可见**地标示"被砍断"；**WHEN** 把那个标记去掉 ⇒ **门红**

#### Scenario: 不放宽（反例）

**WHEN** 上限未触及时
**THEN** **不得**出现"被砍断"标记（不误报）；终态仍 `completed`

#### Scenario: 不是"模型随机"（正例）

**WHEN** 同一输入重复三次
**THEN** 砍断位置**稳定在同一量级**（与 A 的 87/89/77/96 同形）⇒ 证明是**配置层**而非采样
