# Work Order 53 — 用量聚合与导出（通用统计面；成本没有真实来源就未知）

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 批准"通用项直接派单"；实现未开始）。
依赖：**51**（用量事实）之后——没有事实就没有可聚合的东西。
**通用性**：只依赖"用量事实 + 控制面记录"，**不涉及 profile / 多 harness 概念**（按模型/会话/时间聚合，
不碰各家差异）。

## §0 目标

把账本里的用量事实变成**可查、可聚合、可导出**的统计面：按模型 / 会话 / 时间范围，
token 计数；**成本只在有真实单价来源时才出现，否则一律"未知"**（禁止自造价目表、禁止估算）。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 可核对** | 聚合结果与账本逐条**可对上**（同一时间范围的手工求和 = 聚合值；差异为零或给出解释） |
| **G2 未知路径** | 缺数据（某家不报用量 / 不报成本）时，返回"未知"而不是 0 或估计值；有反例测试 |
| **G3 成本来源** | 若做成本：**单价来源必须显式且可审计**（写进记录或配置，标注来源与生效时间）；没有来源 → 该项不返回数值；**不得**内置任何硬编码价目 |
| **G4 导出** | 导出为稳定格式（CSV/JSON 之一），**不含任何凭据内容**，且与查询结果一致 |
| **G5 边界诚实** | 聚合窗口/条数有上限；超限或数据不完整时**如实标注**（例如"该会话有 N 轮无用量数据"） |

## §1 范围与做法

- **数据来源**：51 落到账本里的用量事实 + 现有会话/模型记录；**不改** 51 的字段语义。
- **位置**：控制面（SQLite 侧的只读查询 + 聚合），**不改** 既有 28 方法的语义。
- **wire**：新面（查询/导出）**优先并入 51+52 的那一次重锁**；若时机不允，再单独重锁并同样走两仓同步。
- **成本**：先只做 **token**；成本作为**可选字段**，只有在"单价来源"落地时才填——
  单价属于**模型级**（provider-model 记录）而非 profile 级；放在哪、谁维护、如何标生效时间，
  在本单的 §1 里写成一句话决定并留证。

## §2 硬性规则

- **禁止估算与硬编码价格**；未知即未知。
- 导出与聚合结果**零凭据**；查询范围不得跨 profile 泄漏（会话→profile→workspace 的既有边界照旧）。
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用（用既有账本数据即可）。

## §3 六件套 DoD 与报告

实现 / 定向测试与反例（未知路径、超限、导出一致性）/ 与账本的对账证据 / 回归计数 /
status 分账 / 清理证据。报告含：聚合口径（时间怎么切、跨天怎么算）、成本来源决定、
两仓摘要（若重锁）、未做项。
