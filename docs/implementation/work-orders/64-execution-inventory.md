# Work Order 64 — 运行中执行清单面（"后台程序"卡的数据面）

状态：**READY_FOR_EXECUTION**（2026-09-17 用户批准派单；实现未开始）。
依赖：与 51–60 **共用一次 wire 重锁**（新增一个只读查询面）。
配对前端单：桌面工作树 **P20**（"后台程序"卡）。

## §0 目标与边界（先把"能报什么"定死）

**要报的是"我们启动的执行"，不是"这台机器上的所有进程"**——后者既不诚实（拿不到全貌）
也没必要。清单的每一行必须能被我们自己的记录解释：

| 字段 | 来源 | 拿不到时 |
| --- | --- | --- |
| `executionId` / `turnId` / `sessionId` | Server 自己的执行账本 | 必有 |
| `profile` / `harness` | 同上 | 必有 |
| `placement`（`local`/`wsl`/`ssh`） | 解析结果 | 必有 |
| `state`（`queued`/`running`/`stopping`） | 同上 | 必有 |
| `startedAt` / `elapsedMs` | 同上 | 必有 |
| `workspace`（**不含宿主绝对路径**，用记录里的 workspace id 或规范化名） | 同上 | 必有 |
| `pid`（执行侧进程号） | **本机**放置：通道直接有；**WSL**：Worker 已报才有 | **null**（不猜） |
| `adapterPid`/子进程数 | 只有真的拿到才报 | **null** |

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 只为己有** | 清单里**只有我们启动的执行**；**没有**"系统进程列表"这种拿不全的东西 |
| **G2 与账本一致** | 清单与执行账本（turn 状态/队列）**逐条对得上**；完成后**及时消失**（不是缓存残影） |
| **G3 拿不到就 null** | `pid` 一类执行侧事实，拿不到即 `null` + `reason`；**不得**用 0、-1 或猜的值 |
| **G4 有界** | 条数上限；超限**类型化失败**并给原因 |
| **G5 零泄漏** | 不含宿主绝对路径、不含凭据、不含工作区文件内容；事件与证据零凭据 |
| **G6 不退化** | wire 锁定值不变（同批重锁）；全量套件与四家全链门不退化 |

## §1 现状与做法

- **Server 侧已有**：执行账本（`execution`/`turn` 状态、队列、dispatch 记录）、placement 解析结果
  （`resolve_placement` 返回 `local`/`wsl`/`ssh`）→ 清单的**主干字段全部现成**，本单只是**把它读出来**。
- **执行侧 pid**：本机通道用 `Popen.pid`（已有）；WSL 侧**仅当 Worker 已透传**才填，
  否则 `null` + `reason="PID_NOT_REPORTED"`。**不改 Worker/Rust 协议**（若未来要 pid，
  那是 Worker 的单独一单）。
- **不做**：机器级进程列表；沙箱内 harness 派生的孙进程清单（拿不到就不报）。

## §2 硬性规则

- 只读查询，**不干预**任何执行（不得 cancel/暂停/杀进程）；
- 与账本同源，**不许另建一套影子状态**；
- 严格遵循 §0 的"拿不到即 null"；
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用。

## §3 六件套 DoD 与报告

实现 / 定向测试与反例（无运行中执行 → 空清单而非报错；完成后消失；pid 缺失 → null；超限类型化）/
真机证据（本机与 WSL 各一次，含 pid 有/无两种）/ 回归计数 / status 分账 / 清理证据。
报告含：字段与来源、`reason` 码表、与账本一致性证据、两仓摘要（若重锁）、未做项（机器级进程视图明确不做）。
