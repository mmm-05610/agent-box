# Work Order 62 — 工作区 Git 状态面（只读、有界、类型化）

状态：**READY_FOR_EXECUTION**（2026-09-17 由 P20 的 Git 卡需求派生；实现未开始）。
依赖：与 51–60 **共用一次 wire 重锁**（新增一个只读查询面）。
配对前端单：桌面工作树 **P20**（Git 卡，字段已在 P20 §数据 里声明）。

## §0 目标

让产品能看到**工作区的 Git 状态**：分支、改动文件数、增删行、领先/落后。
**只读、有界、类型化拒绝**；拿不到就给类型化原因，**不猜、不缓存过期值冒充现状**。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 字段与语义** | 恰为 P20 声明的六个字段：`branch` / `changedFiles` / `additions` / `deletions` / `ahead` / `behind`；**各自可为 null**（拿不到就是 null，不是 0） |
| **G2 有界** | 单次查询有超时与输出上限；**大仓库不得拖垮**（超限**类型化失败**并给原因，不静默截断成假数字） |
| **G3 只读** | 只读命令（如 `status --porcelain=v2 --branch` 一类），**不得**写工作区、不得触发网络（`--no-optional-locks` 一类纪律按实际需要） |
| **G4 执行侧** | 工作区在跑它的那台机器上（WSL/本机/ssh）→ 由**该侧**执行；WSL 走既有 `wsl.exe` 通道（**不改 Rust/Worker 协议**），本机直接 `subprocess`；**不出现宿主路径进文档/记录** |
| **G5 非仓库即 null** | 工作区不是 git 仓库 / 没有 git → **类型化原因 + 全 null**，不是"全 0" |
| **G6 不退化** | 既有 28 方法语义与 wire 锁定值不变（新面走同一次重锁）；全量套件不退化 |

## §1 现状与做法

- wire 里**没有**任何 git 面（28 方法）；本单新增一个只读查询（建议形状：给 session/workspace 上下文，
  返回上表六字段 + 一个 `reason`）。
- 执行侧三选一（**按 placement**）：`wsl` → 既有 `wsl.exe --exec` 通道（connector 已有该能力，
  见 `_effective_user` 的用法）；`local` → `subprocess`；`ssh` → 由 44 的 provider 收口（本单不碰）。
- **不改 Worker 协议**（Rust 不动）：git 查询是**只读、幂等**的，走连接器即可。
- 与 54（每轮变更集）**不是同一件事**：54 是"这一轮改了什么"（执行前后快照差集），
  本单是"工作区现在相对 HEAD 是什么状态"（含分支与领先/落后）。两者可并存。

## §2 硬性规则

- **禁止写**：任何 git 命令不得改动工作区（不 stage、不 stash、不 fetch）；
- **禁止猜**：拿不到就给 reason（`GIT_UNAVAILABLE` / `GIT_NOT_A_REPOSITORY` / `GIT_TIMEOUT` / `GIT_OUTPUT_LIMIT`）；
- 输出解析**只认机器可读格式**（porcelain v2 或等价），不做人类可读文本的正则；**解析失败类型化拒绝**；
- 不 reset/stash/clean、不 merge main、不 push；不读真实凭据；真实模型零调用。
