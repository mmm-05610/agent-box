# Work Order 56 — 订阅（官方登录）作为一等凭据：**独立托管 + 按轮次热切换**

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 裁定：登录**不住原生 home**，要**单独拎出来管理**且**支持热切换**）。
依赖：与 51/52/53/55 **共用一次 wire 重锁**；材料化/回收依赖 45 的"home 由我们物化"机制。
配对前端单：桌面工作树 **P12**（账号列表、绑定、**热切换**、登录引导、状态）。

## §0 目标与两条硬要求（用户裁定）

1. **登录态独立托管**：账号的登录态**不放在 profile 的原生 home 里**，而是作为**受管资产**存在控制面
   （`<data_root>/accounts/<account-id>/`，内容进 SecretStore（DPAPI）加密保存），与 home 分离。
2. **热切换**：同一个 profile 可以**换账号**，且**按轮次生效**——下一轮材料化的是所选账号的登录态，
   不需要重启任何 CLI（我们的模型里每轮都是**新进程 + 新物化**，所以热切换是天然成立的）。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 类别与托管** | 订阅/官方登录与 api-key 并列；账号**资产独立存放**（不在任何 home 里）、**加密保存**、记录里不含令牌 |
| **G2 物化** | 每轮**按当前绑定**把该账号的登录态物化成 harness 期望的形态（**可写**，不是只读投影——harness 可能刷新它）；位置与形态逐家观测得出 |
| **G3 回收（本单的新机制，必须显式）** | 轮次结束把（可能被刷新过的）登录态**回收**到账号资产：**有界**（大小/文件数上限）、**只收声明的那些文件**、**每账号一把锁**、并发冲突**类型化**（不得静默后写覆盖先写）、**零日志/零证据** |
| **G4 热切换** | 同一 profile 换账号后**下一轮**即生效（有第一手证据）；**并行轮次**各自用自己绑定的账号，互不串 |
| **G5 零泄漏/零越界** | 任何界面/日志/证据/argv 里**零令牌**；**不读**用户本机 `~/.codex` 等宿主登录态；**不代填**、**不抓取** |
| **G6 扫描边界** | 45 的凭据扫描按"注入值精确匹配"，**不误伤**物化进去的登录态；这条写进代码注释与测试 |

## §1 设计与代价（如实写清，别含糊）

- **存储**：账号资产 = 一组文件（各家形态不同，逐家观测），整体进 SecretStore（DPAPI）加密；
  控制面记录只存 `accountId` / 归属家族 / 账号标识 / 状态 / 最后验证时间。
- **物化**：轮次开始时把该账号资产写到 harness 期望的位置（**在家**里，但**来源是受管资产**）——
  与只读配置投影**并列**，但**可写**，因为 harness 会刷新它。
- **回收 = 本单引入的第一条"写回"路径**（我们此前**零写回**）。它必须有明确边界，否则会毁掉
  "配置永不回写"的纪律：
  - **只回收声明的文件**（逐家清单），**不回收**其它任何东西；
  - 有界（单文件/总大小/文件数上限），超限**类型化失败**并保留旧资产（不半途替换）；
  - **每账号一把锁**：同一账号的并行轮次在回收时**串行**；抢不到锁 → 类型化冲突，**绝不**静默后写覆盖；
  - 先写临时再原子替换；替换前后摘要写进**记录**（不是证据，避免内容外泄）；
  - **零令牌进日志/事件/证据**。
- **热切换的语义**：绑定是**产品决定**（profile 默认 + 会话/轮次覆盖）；因为每轮是新进程，
  切换在**下一轮**生效——这是"热"的准确含义，不承诺"同一轮中途换号"。
- **必须逐家观测的风险**（阶段 A 的产出，**不许**先写代码再发现）：
  ① 登录态是**单文件还是多文件**；② 是否**绑定机器/安装**（换执行环境就失效）；
  ③ harness 是**原地刷新**还是只读；④ 各家的登录命令与是否需要交互。
  任何一条对某家不成立 → **该家如实标注"订阅不可用"**，不得假装支持。

## §2 硬性规则

- 令牌：**零日志、零 argv、零事件、零证据**；探测只回报布尔与账号标识。
- **不越界**：不读宿主原生登录态；不代填；不抓取；**不把登录态留在家里的持久副本**（每轮材料化、轮末回收，
  家里的那份是**工作副本**，不是事实来源）。
- 回收路径必须有反例：并发冲突、超限、非声明文件、写坏后不替换。
- 45 的三条规则（只读配置 / tmpfs 遮蔽 / 受保护路径）与 G1–G8 不得退化；能力不自报。
- 不 reset/stash/clean、不 merge main、不 push；探测不发起任何模型补全。
