# Work Order 54 — 每轮文件变更集（与 harness 无关的通用能力）

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 批准"通用项直接派单"；实现未开始）。
依赖：50 之后；B–D 与 47/48 串行（同一批通道文件）。
**通用性**：**不依赖任何一家的工具事件**——用执行侧工作区在轮次**前后**的有界快照做差集，
所以不涉及 profile / 多 harness 概念。

## §0 目标

每轮结束给出"**这一轮改了哪些文件、各 +N/−M**"（就是桌面上那张 `+102 −0` 卡的数据）。
按**执行侧文件系统**取，不解析任何 harness 的工具负载 → 各家一致、可复现、可审计。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 与真实改动一致** | 构造一轮真的改文件的用例：变更集**恰好**列出那些文件与行数（新增/修改/删除各自正确） |
| **G2 有界与诚实** | 快照与差集有上限（条目/字节/单文件大小）；超限**如实标注截断**，**不得**给出"看起来完整"的结果 |
| **G3 不越界** | 只覆盖**声明的工作区**（与既有工作区边界一致）；不跟随符号链接；不读特殊文件；**凭据零命中**（构造反例） |
| **G4 轮次归属** | 快照绑定在具体 turn 上（前后各一次，失败/取消也要有可解释的结果：失败=不完整、取消=部分） |
| **G5 不退化** | 全量套件 + 四家全链门 + 45 的门不退化；两个通道（WSL / 本机）都要有证据 |

## §1 现状与做法

- 现状：**没有**任何"每轮改了哪些文件"的事实（工具事件里可能带编辑负载，但我们不上行；
  且各家格式不同——所以本单**故意不走工具事件**）。
- 做法：在通道层（WSL 经 Worker 的既有读面 / 本机直接）在 attempt **前后**各取一次
  **有界清单**（相对路径 + 大小 + 摘要，忽略声明外的目录），差集得出变更集；
  行数按文本文件计（二进制/超大文件只报"变更"不计行数，并标注）。
- 记录：写入该 turn 的记录（记录类对象）；**暴露给 UI 的合同**优先并入 51+52 的那一次重锁，
  否则单列并同样走两仓同步。

## §2 硬性规则

- **不解析 harness 负载**（本单的通用性全靠这一点）。
- 有界 + 截断记账；**不跟随符号链接**；不读特殊文件；**先完成，再更新**（不做无界全树哈希）。
- 凭据：变更集内容与证据里**零凭据**；命中即按既有规则处理并记账。
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用（构造用例即可）。

## §3 六件套 DoD 与报告

实现 / 定向测试与反例（截断、符号链接、特殊文件、凭据命中、取消轮次）/ 两个通道的真机证据 /
回归计数 / status 分账 / 清理证据。报告含：变更集的字段与上限、截断语义、与既有工作区边界的一致性、
两仓摘要（若重锁）、未做项。
