# Work Order 58 — 资产层落地：Skill Hub / MCP Hub（+ hooks/commands 如实声明）

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 要求做统一 skill/MCP hub；实现未开始）。
依赖：与 51/52/53/55/56/57 **共用一次 wire 重锁**；设计母体见
[原生目录落地设计](../../server-round1/native-home-storage-landing.md) §9（资产与配置分离）。
配对前端单：桌面工作树 **P15**。

## §0 目标

把 skill / MCP 定义做成**与配置分离的受管资产**：统一存储（内容寻址、带修订与摘要）、
**按家族物化成只读投影**、按 profile **绑定启用**、可**从外部来源同步**（目录式），
并且**永不回写用户的原生配置**。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 统一存储** | 资产带 id / revision / **tree digest** / 来源；skill 用 **Agent Skills 格式**（`SKILL.md` + frontmatter `name`/`description` + 同目录资源），MCP 用**标准 server 定义**（`{name, transport: stdio{command,args,env} \| remote{url,headers-ref}}`） |
| **G2 逐家物化** | 按注册表声明的**槽位**物化（`slots` / `skill_target` / 各家 mcp 配置位置与键名）；产物是**只读投影**；**不支持的家如实声明**，不假装 |
| **G3 绑定** | profile **引用**资产（id + revision）并启用/停用；执行时物化；换绑定**下一轮生效**（与 P11 的 G6 同一条纪律） |
| **G4 零回写** | **不写**用户的原生配置文件（`~/.claude*`、`~/.codex/**`、`opencode.json`…）；所有写入只发生在**我们自己的**投影/目录 |
| **G5 凭据只引用** | MCP 的 `env` 值若来自凭据，**只存引用**；物化时按既有一次性投影规则注入；**零日志/零证据** |
| **G6 探测有界** | "这个 MCP server 能不能起来/握手"是一次**有界、可取消、类型化错误**的探测（与 55 同形状）；**不写配置**、不发补全 |
| **G7 外部来源** | 可从外部来源（如 skills 仓库/社区目录）**同步到本地资产库**（目录式，参照 Applite 的"目录优先 + 异步标注"）；来源与摘要固定；**不静默换源** |
| **G8 不退化** | 既有投影/工件语义与上限不变；全量套件与四家全链门不退化 |

## §1 参照（本轮取证）

- **Skill 有跨家标准**：`github.com/anthropics/skills` —— 每个 skill 是**独立目录 + `SKILL.md`**，
  YAML frontmatter **只要求两个字段**：`name`（小写、连字符）与 `description`（说明"做什么、何时用"）；
  正文是给 agent 的指令；目录里可带脚本与资源；仓库内含 **`./spec`（Agent Skills specification）**，
  并指向标准站点 **agentskills.io**。→ **我们按这个格式存**，各家按自己的槽位物化。
- **MCP 本身就是标准**：客户端配置以 `mcpServers` 映射声明本地 server，每项
  `{command, args, env}`（stdio）；另有远端 server 形态（url/headers）见 MCP 文档。
  各家差异**只在文件位置与键名拼法**（`mcpServers` / `mcp_servers` …）。
  → **我们存标准形态**，物化时由**逐家适配器**翻译成该家的文件位置与键名。
- **hooks 没有成熟收敛**（各家事件模型与开关差异大，且有"仅允许受管 hooks"这类厂商开关）→
  **不统一**，本单只做**如实声明**（见 §3）。
- **commands（提示片段）**：各家是 markdown + 可选 frontmatter 的不同目录约定，收敛**可行但语义要分清**：
  **我们的斜杠菜单**（前端命令面板）与 **harness 的斜杠命令**（发给模型的文本）**不是一回事**，
  后者可当**资产**存（复用 skill 的存储/物化机制），逐家声明支持。

## §2 设计要点

- **存储**：`<data_root>/assets/<kind>/<asset-id>/<revision>/`（内容寻址 + tree digest），
  记录里存 id / revision / 来源 / 摘要 / 名称与描述（skill 取自 frontmatter）。
- **物化**：复用**既有运行时工件与投影机制**（只读绑定 + 摘要校验），逐家按槽位落地；
  目标路径来自**注册表声明**，不是硬编码在我们这边。
- **绑定**：profile 记录引用资产 id + revision；`enabled/disabled` 是产品状态。
- **来源同步（Hub 的"目录"）**：可配置若干来源（仓库/目录索引），同步为**本地目录**（列表立即可画），
  安装/更新是**用户动作**（沿用 57 的纪律：不自动更新、不静默换源、失败不落地）。
- **探测**：MCP server 的握手探测照 55 的边界（超时、上限、可取消、零凭据）。
- **不做**：hooks 的统一模型；写用户原生配置；任何"猜测式"的格式翻译（翻译规则必须逐家写清并有测试）。

## §3 硬性规则

- **零回写**：只写我们自己的投影与资产库；用户原生配置**只读**（事实上连读都按既有边界：不读其登录态）。
- **诚实声明**：注册表没说支持某槽位的家族 → UI 上显示"该家不支持此类资产"，**不产生假的物化**。
- **凭据只引用**；物化注入按既有一次性投影；**零日志/零证据**。
- **来源可审计**：同步来的资产必须带来源与摘要；**不静默换源**、不自动更新。
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用（探测不发补全）。

## §4 六件套 DoD 与报告

实现 / 定向测试与反例（非法 frontmatter、摘要不符、不支持的家、凭据只引用、
"绝不写原生配置"的守卫测试）/ 真机证据（至少两家：一家物化 skill、一家物化 MCP）/
回归计数 / status 分账 / 清理与费用账（0）。
报告含：资产格式与文件布局、逐家物化位置与适配器规则、来源同步与摘要、绑定与生效时机、
类型化码表、两仓摘要（若重锁）、未做项（尤其 hooks）。
