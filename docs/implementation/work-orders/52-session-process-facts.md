# Work Order 52 — 会话过程事实（思考 / 工具 / 计划 / 模式），与 51 共用一次 wire 重锁

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 批准"zcode/codex 同款会话区"；实现未开始）。
依赖：50 之后；**与 51 同批执行（共用一次合同重锁）**；B–D 与 47/48 串行（同批文件）。
依据：2026-09-16 对 ACP schema 的第一手核对（见 §1）。

## §0 目标

把会话区需要的**过程事实**从各家原生上行到产品：**思考块、工具调用（开始+更新）、计划、模式变更**，
以及由事件时间戳得到的**时长**。前端（P09）只负责渲染，**不许自造事实**。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 逐家观测** | 每家给出"实际发出哪些过程事件、字段是什么、终态怎么表示"的第一手结论（**定义里有 ≠ 各家真的发**）；不发的家如实标注 |
| **G2 中立事实** | 桥/驱动把它们映射成**中立事件**（不含品牌词、字段只含观测到的）；`tool.update` 从"只有失败一条"扩成完整生命周期（开始/进行/结束/失败），并保留既有那条失败语义不变 |
| **G3 时长** | 轮/阶段/每个工具与思考段的时长**由事件账本的时间戳推出**（不新增估算字段）；无法推导的组合如实缺失 |
| **G4 合同** | **与 51 合并成一次 wire 重锁**：TS 与生成工件两仓同步、严格事件 schema 用例通过、28 方法语义不动 |
| **G5 不退化** | 全量套件 + 四家全链门 + 45/47 的门不退化；前端 P09 的"只渲染已到达事实"反例继续通过 |
| **G6 隐私** | 工具参数与输出**可能含敏感内容**：写入账本前按既有凭据扫描规则处理；**证据里不出现真实凭据** |

## §1 现状（第一手，动手前复核）

- **上游有，我们丢**：ACP schema（`.../@agentclientprotocol/sdk/schema/schema.json`）的
  `sessionUpdate` 词汇表为
  `agent_message_chunk` / `agent_thought_chunk` / `tool_call` / `tool_call_update` /
  `plan_update` / `plan_removed` / `current_mode_update`，
  而我们的桥与 Server 只认 `agent_message_chunk`（`execution/sidecar.py:_forward()`），
  其余**全部丢弃**。
- 产品侧今天只有三条 turn 事件生产方：`message.delta`、`message.final`、以及**只报失败**的
  `tool.update`（`sidecar_backend.py`）。
- 前端已有可复用的呈现件（P09 用）：`components/assistant-ui/thread/message-parts.tsx`、
  `components/assistant-ui/tool/**`、`components/chat/activity-timer.ts`、`ansi-text.tsx`、
  `status-tail-only`、`markdown-text.tsx`。

## §2 阶段

- **A 逐家观测（无代码改动）**：对注册表每家跑一轮（假端点，**零真实模型**），记录它**实际发出**的
  sessionUpdate 种类与字段（含工具名/参数/状态/终态、思考块、计划、模式），以及**是否**在
  `PromptResponse.usage` 里填用量（与 51 共用观测）。产出
  `docs/server-round1/fullstack/process-facts-observation.md`。
- **B 中立映射**：在 sidecar envelope 增加中立事件（思考增量、工具开始/更新/结束、计划、模式），
  各方映射进同一套；工具事件**不携带品牌字段**，参数与输出按需裁剪（大小上限 + 凭据扫描）。
- **C Server 记账**：`_forward()` 落这些事实进 turn 账本；`tool.update` 扩展为完整生命周期，
  **既有"失败一条"的语义与码保持不变**；时长由账本时间戳推导（不新增估算字段）。
- **D 合同（与 51 合并）**：一次重锁同时覆盖 51 的用量面与本单的过程事实；两仓同步摘要 +
  严格 schema 用例 + `wire-review.md` 记录；跨仓写权按 42 的条件。
- **E 交前端**：把事件形状与样例交给 P09（前端按可用事实逐步点亮，不显示缺失的东西）。

## §3 硬性规则

- **事实只来自原生**：没有就不显示；**禁止**从前端或后端"编"过程步骤（不许把一次工具调用拆成多行、
  不许伪造进度）。
- **中立命名**：不得出现 harness 品牌词；原生字段名只出现在映射那一处。
- **隐私**：工具参数/输出进入账本前按既有规则扫描；证据与报告**零凭据**。
- 不改变 28 方法语义（只新增面）；不 reset/stash/clean、不 merge main、不 push；
  真实模型默认零（假端点足够），确需真实调用按用户当次授权口径、逐笔记账。

## §4 六件套 DoD

实现 / 定向测试与反例（缺失即缺失、失败语义不变、隐私扫描命中即拒）/ 逐家观测证据 /
回归计数 / status 分账（哪几家能亮）/ 清理与费用账。
