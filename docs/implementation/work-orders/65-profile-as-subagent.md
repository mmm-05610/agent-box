# Work Order 65 — 子代理：profile 调用 profile（MCP 工具桥）

状态：**READY_FOR_EXECUTION**（2026-09-17 用户批准机制；工具契约按原生子代理形态重写，实现未开始）。
依赖：**60**（profile 的授权与权限规则）、**58**（MCP 物化）先有面；与 51–64 **共用一次 wire 重锁**。
配对前端单：桌面工作树 —— ① profile 设置里的"**可调用哪些 profile**"授权分区；
② **P20** 的"智能体"卡接入。

## §0 目标

让一个 profile **把另一个 profile 当成子代理调用**：父 harness 通过一个**由我们提供的 MCP 工具**
发起，**Server** 按子 profile 的家族/home/模型/权限**起一次正常执行**，把**有界摘要**回给父轮次。

**取证（2026-09-17，原生子代理的收敛形态）**：

| 家族 | 工具形态 | 入参 | 关键语义 |
| --- | --- | --- | --- |
| Claude Code | 单一 `Task` | `{subagent_type, prompt, description}` | 类型表**写在工具描述里**；只回最终摘要；子有独立上下文 |
| **OpenCode** | 单一 **`task`**（`packages/opencode/src/tool/task.ts` + **`task.txt`** 描述模板） | `{description, prompt, subagent_type, task_id?}` | `task.txt` 的 usage notes：**fresh context 除非给 `task_id` 续接**、**子结果对用户不可见、父必须转述**、提示要"自包含 + 写清要回什么 + 说明是研究还是写代码"、鼓励**同一条消息并发多个** |
| OpenCode 权限 | `src/agent/subagent-permissions.ts::deriveSubagentSessionPermission` | — | 子代理**只继承父的 `deny` 规则与 `external_directory` 限制**（"父的允许规则只管父自己"）；`task`/`todowrite` **默认 deny**，除非子自身规则允许 ⇒ **深度限制是默认拒绝，不是计数器** |
| Roo | 单一 `new_task` | mode + message | 同上家族 |
| OpenAI Agents SDK | `Agent.as_tool()` | `{"input"}` + `tool_description` | 上下文默认不继承；`needs_approval`→`interruptions`；`is_enabled` 明确"**does not replace authorization**" |
| MCP 包装（反例） | `steipete/claude-code-mcp` 单一 `claude_code`；`jamubc/gemini-mcp-tool` `ask-gemini` | — | 前者默认 `--dangerously-skip-permissions`、3600s、自称"非 OS 级沙箱"——**我们逐条反着做** |
| Cline（少数派） | **一 agent 一工具** `use_subagent_<sanitized>`（`SubagentToolName.ts`，前缀 `use_subagent_`、64 字符上限、FNV-1a 消歧） | — | 从 `~/Documents/Cline/Agents` 的 YAML frontmatter（`AgentBaseConfigSchema = {name, description, tools, skills?, modelId?, systemPrompt}`）动态生成 ⇒ 工具表随配置变动、描述常驻系统提示 |

**结论**：名词收敛为 **"task/subagent"**（不是 "ask"）；形态取多数派（**单一通用工具 + 花名册在描述里 + 只回摘要**），
不取 Cline 的"一 profile 一工具"（与用户 2026-09-17 的否掉理由一致：工具表随授权变动、描述常驻）。
`ask` 的语义是"问一下、等回答"，与"派活、独立执行、回摘要"不符，弃用。

## §1 工具契约

**两个工具**（仍不做"一 profile 一工具"）：

| 工具 | 入参 | 返回 |
| --- | --- | --- |
| **`list_subagents`** | 无（可选 `query` 过滤） | **仅当前父 profile 被授权调用**的项：`name` / `description` / `harness` / 工作区 / **可用性状态**（不可用如实标注，含原因）；**输出有界**（条数与描述长度上限，超限记截断事实） |
| **`run_subagent`** | `subagent`（必填，= 原生 `subagent_type` 位）、**`description`（必填，3–5 词短标签，同原生）**、`prompt`（必填，**自包含**任务书）；可选 `task_id` / `model` / `permission` / `timeout` / `max_turns` | **一条有界最终消息** + `task_id`（可续接）+ 状态；失败为**类型化结果**（不吐裸 stdout） |

**`run_subagent` 的工具描述必须携带花名册摘要**（每项：`name` + 一句话描述），使模型**一次调用即可派活**，
不必先 list（原生形态：Claude Code / OpenCode 都不设单独的 list 工具，花名册在描述里）。
`list_subagents` 提供**完整细节**（技能、模型槽、当前是否在跑、工作区），供需要时查。
**零授权时两个工具都不物化**（默认无委派能力的 profile 不被塞两个永远失败的工具）。

**四条硬规则**：

1. **未授权项绝不出现**在任何输出里（不泄露存在性）；工具描述的摘要同受此约束；
2. `run_subagent` 遇到**未授权 / 参数非法 / 子 profile 不可用**时，**类型化失败并在结果里内联可用
   `name` 列表**（不展开描述、有界）——把"多一跳"的代价压到一次自纠正；
3. **可选参数只能收紧、不能放宽**子 profile 自身的约束（模型槽、权限规则、上限）——与 60 的
   "规则求解只允许收紧"同一条；`permission` 只能收紧；
4. **可见性由授权派生，但绝不替代授权**（Agents SDK `is_enabled` 的同款告诫）：即使模型从旧上下文
   发出调用，Server 仍在调用时**重新求解**并类型化拒绝。

## §1b 继承与深度（机制级，取代纯计数器）

按 OpenCode 的派生规则照做，把"≤2 层"做成**默认拒绝**而不是只靠计数：

- 子执行**继承父的 `deny` 规则与工作区/外部目录限制**（限制可继承；**允许集仍由子 profile 自己决定**）；
- 子的工具表里 **`run_subagent` 默认不出现**，除非**子 profile 自身的授权边**允许（⇒ 孙代委派结构上不可用）；
- 计数器（深度 ≤2、每轮 ≤4）**保留为第二层**，用于拦住同一轮里的扇出；
- 环检测（A→B→A）仍为类型化拒绝。

## §2 执行语义

- **谁执行**：**Server**（不是父 harness）——子调用就是一次**正常的执行**：自己的沙箱、自己的
  home/会话、自己的模型槽与权限规则；
- **上下文不继承**：只回摘要，不回整段转写；`prompt` 必须自包含（工具描述里明确要求写清"要回什么"、
  以及"是研究还是写代码/怎么验证"）；
- **`task_id` 续接**：`task_id` = **子执行的 native session 引用**（句柄，不是 profile 拥有的对象——
  与"session 不能被某个 profile 拥有"的用户裁决一致）。续接 = **用同一 session 再起一次执行**；
  **跨家族续接不可能**（session 属于家族共享存储）⇒ 类型化拒绝，**不静默新开一茬**；
- **结果转述**：子结果**对用户不可见**（原生语义），父轮次必须转述；摘要/转述与归属供 P20 的
  "智能体"卡呈现；
- **并发**：工具必须**可并发调用**（原生鼓励同一条消息发起多个）；每轮 ≤4；Server 端按并行执行处理，
  与 45 的"同 profile 并行不互相覆盖"共用一套保证；
- **归属**：子执行的**用量/费用记到发起它的那一轮**（接 51/53 的账）；
- **审批**：子代理的 `ask` 以**中断**形式浮到父轮次（复用既有审批事件与往返，不另造机制）；
- **取消传播**：取消父执行 → **连带取消**其全部子执行；
- **上限**：单次超时 **10 分钟**（反例参照：`claude-code-mcp` 默认 3600s）；**深度 ≤2**；
  **每轮子调用 ≤4**；三项均可在 profile 上覆盖；超限**类型化失败**；
- **默认作用域**：**只允许同工作区**的 profile；**默认允许跨家**（A 家调 B 家）。

## §3 硬性规则

- **绝不默认绕过权限**（反 `--dangerously-skip-permissions` 之道）：子执行一律走子 profile 自己的
  权限规则；`ask` 走审批往返；
- **零凭据泄漏**：子执行的凭据仍是它自己的一次性投影；父侧**看不到**子 profile 的凭据；
- **类型化**：未授权、深度超限、环、超时、子不可用、续接不可行各有码；**不静默降级**；
- **不做**操作系统级沙箱承诺之外的夸大宣传（沙箱能力以 47/48 的声明为准）；
- **不做后台模式**（OpenCode 的 `background=true` + 完成通知）：需要新事件 kind，而 wire 锁定；
  记为明确未做项，不悄悄用轮询冒充；
- 不 reset/stash/clean、不 merge main、不 push；本单**默认零真实模型调用**（用假端点验证桥与边界），
  确需真实调用按用户当次授权口径逐笔记账。

## §4 阶段

**A 授权模型**：父 profile 上的**显式授权边**（默认无）→ 记录字段 + 求解（谁能调谁 → 谁被物化）；
**B 工具桥**：我们的 MCP server（经 58 物化进父 harness）实现 `list_subagents` / `run_subagent`，
含描述里的花名册摘要与"零授权不物化"；
**C 执行与归属**：子执行走既有执行链；继承规则（deny 传播 + `run_subagent` 默认不出现）；
用量/审批/取消三项归属；深度与次数上限；环检测；`task_id` 续接与跨家族拒绝；
**D 合同**：与 51–64 同一批重锁（工具面 = 新的 MCP 定义 + 相关记录字段）；
**E 回归与收口**：反例（未授权/超限/环/超时/子不可用/参数放宽尝试/跨家族续接）+ status + 报告。

## §5 门

| 门 | 断言 |
| --- | --- |
| **G1 只列授权 + 零授权不物化** | `list_subagents` 输出**逐条可核对**：未授权的项**零出现**（含"不可用"状态项）；**零授权的 profile 上两个工具都不物化**（第一手证据） |
| **G2 参数只收紧** | 用可选参数尝试**放宽**子 profile 约束（含 `permission`）→ **类型化拒绝**（有反例） |
| **G3 归属正确** | 子执行的用量与费用**记在父轮次**上；审批中断浮到父轮次；取消父 → 子被取消（各一条反例） |
| **G4 上限与环** | 深度 >2、每轮 >4、A→B→A 环 → 各自类型化拒绝（有反例） |
| **G5 上下文隔离 + 结果转述** | 子执行**拿不到**父的转写；父只拿到有界摘要；**子结果不直接对用户可见**，父轮次完成转述（有第一手证据） |
| **G6 继承规则** | 父的 `deny` 与工作区/外部目录限制**确实传播**到子；子的允许集仍由子 profile 决定；**`run_subagent` 在孙代默认不出现**（有反例） |
| **G7 续接** | `task_id` 能续接同一子会话（有第一手证据）；跨家族续接 → **类型化拒绝且不新开** |
| **G8 并发** | 同一条消息发起 ≥2 个子调用都完成、归属正确、无互相覆盖（有第一手证据） |
| **G9 不退化** | 既有 28 方法语义与 wire 锁定值不变；八家既有门不退化 |
