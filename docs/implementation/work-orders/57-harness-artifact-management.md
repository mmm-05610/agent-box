# Work Order 57 — Harness 运行时工件的安装 / 更新 / 回滚（后端）

状态：**READY_FOR_EXECUTION**（用户 2026-09-16 点名"harness 二进制管理"；实现未开始）。
依赖：与 51/52/53/55/56 **共用一次 wire 重锁**；与 46（多家族并存）语义相邻。
配对前端单：桌面工作树 **P13**（程序管理 UI）。

## §0 目标

把"每家的 harness 程序"从**门脚本里的临时构建产物**变成**产品对象**：
可安装、可更新、可回滚、可验证、可呈现在 UI 上；**运行中的会话不受影响**。
**目录优先**：可用版本先同步进控制面（本地立即可画），已安装/可更新状态**异步标注**，不阻塞界面。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 清单可见** | 每家给出**已安装集**：family / version / treeDigest / 来源（来源 URL + 版本）/ 大小 / 条目数 / 安装时间 |
| **G2 目录与状态** | 可用版本**目录**可从上游索引同步进控制面（**不阻塞界面**）；已安装/可更新是**异步标注**出来的（不是猜的） |
| **G3 安装与更新** | 新版本**在执行侧**取得（下载或构建）、**重新推导摘要并校验**（沿用既有 tree digest v1）；**失败不落地**（原子替换 + 保留上一版） |
| **G4 回滚** | 保留上一版并**一键回滚**；"用哪一版"是**引用**，不是原地覆盖 |
| **G5 不打扰运行中** | 更新**不影响正在运行的会话**（版本目录 + 引用；第一手用例：更新时另一会话照常跑完） |
| **G6 完整性诚实** | 优先官方发布物 + 摘要（有签名就验签名，**验不了就如实标注"仅摘要固定"**）；**不静默降级**、不静默换源 |
| **G7 离线与失败** | 离线/镜像不可达给**类型化错误**与可读原因；**不得**假装成功；**不做自动更新**（更新是用户动作） |
| **G8 不退化** | 既有 `runtimeArtifactMounts` 语义（Server 形状校验透传 / Worker 重推导 / bwrap 只读绑定）与上限不变；全量套件与四家全链门不退化 |

## §1 现状（第一手）

- 工件今天已是**一等只读投影**：`runtimeArtifactMounts`（Server 只做形状校验透传 → Worker 在 WSL 内
  **重新推导 tree digest** → bwrap 只读绑定 `/runtime/artifacts/<name>`），跨 Python–Rust 的 tree digest v1
  （含 golden fixture），上限 32768 条目 / 1 GiB / 4096 字节路径。
- **但产物没有产品面**：Pi（node 闭包 317 包 / 64.9 MiB）、Hermes（隔离 Python 闭包 60 包 / 108 MB）、
  OpenCode（单文件二进制 184 MB）、Codex（20 包 / 320 MB）都由**各自 builder 在门里构建**、
  摘要固定、双构建一致——**门跑完临时目录即删**；"装在哪、装了几版、怎么更新"今天**没有答案**。
- 因此"安装/更新一家 harness"今天等于"重跑一次构建步骤"，**不是产品能力**。

## §1b 参照（本轮取证；用户点名 codeg，未取到，改为可用参照）

- **用户点名的 codeg**：两次检索（GitHub 搜索接口）**未取得可用结果**，**不拿猜到的项目当参照**；
  收到仓库/链接后在本节补一次对照。
- **Applite**（Homebrew 的 GUI，`milanvarady/Applite`，本轮取证）——**最可复用的交互模式**：
  ① **目录优先**：可用条目先落本地 SQLite 目录（从上游索引同步），"SQLite paints the UI immediately"，
  渲染**不等**任何 CLI 调用；② **异步标注**：`brew list` / `brew outdated` 的已安装与"可更新"状态
  **反应式补上**，"nothing blocks on the brew CLI"；③ 分类 + 搜索（FTS5）；④ 一键安装/更新/卸载；
  ⑤ **Brewfile 导入导出**用于迁移（逐项选择）。
  → **我们照此实现**：目录=各家的可用版本索引；已安装/可更新=我们的清单 + 对照；动作=安装/更新/回滚；
  导入导出=我们的记录（**不导入用户本机配置**，见 P11 的既有边界）。
- **Ollama**（本轮只取到仓库结构）：顶层出现 `manifest` / `model` / `fs` / `x/transfer`，并有
  `LLAMA_CPP_VERSION` 这类**版本钉住文件**；页面**未给语义**，故只作"版本钉 + manifest + 内容寻址"
  这一形状的旁证，**不作为规范**。
- **两个负面事实（同样重要）**：
  - **claude-squad**（多 agent 管理器）**不管程序安装**：FAQ 让用户"自己更新底层程序"；
  - **vibe-kanban** 假设 agent 已安装并已登录，且仓库已宣布 **sunsetting**。
  → 这一类应用**没人做 harness 程序的安装/更新**；我们做出来是**差异化**，但也意味着**没有现成实现可抄**，
    只能借包管理器/资产库的形状（Applite 的目录模式 + 版本目录与摘要钉住）。
- **Jan**（本轮取证）：引擎（llama.cpp 变体）的选择是**构建期**（`JAN_ENGINE_VARIANT`），不是运行时资产管理 →
  **不适用**（我们要的恰恰是运行时可变）。

## §2 设计要点

- **工件根**：由机器本地绑定给出（沿用 `--mount <token>=<path>` 规则，**宿主路径不进文档、不进记录**）。
- **版本目录 + 引用**：`<工件根>/<family>/<version>/`（内容寻址摘要校验）；"当前用哪版"是记录里的**引用**，
  所以更新=新增目录 + 改引用，**运行中不受影响**，回滚=改回引用。
- **目录（catalog）**：各家的可用版本索引同步进控制面（本地即可画）；**同步失败不阻塞界面**，
  只是没有"可更新"徽标。
- **取得方式**（逐家声明，不猜）：官方发布物（npm / GitHub release / vendor URL）优先；
  必须构建的家（如隔离闭包）走既有 builder。**下载与构建都有界**（超时、大小上限、可取消）。
- **完整性**：摘要**必须**重新推导并匹配声明；有签名则验签；没有就写"仅摘要固定"。
- **阶段 A 必答**：逐家确认**可取得的官方来源与版本标识**（发布物类型、有没有签名、镜像可用性），
  以及**该家是否会自我更新**（自更新的家要按我们的钉住方式处理：以我们安装的树为准，禁用或忽略自更新）。
  查不到官方来源的家 → **如实标注"只能本地构建"**，不得编来源。

## §3 硬性规则

- **不做自动更新**；安装/更新/回滚都是**用户动作**，且**不静默换源**。
- 失败**不落地**（原子替换、保留上一版）；任何"部分成功"必须如实报告。
- **原生状态兼容性**：同一 profile 的 home 在版本间共享，**可能不兼容**——本单只要求**如实呈现版本**与
  "最近一次生效版本"，兼容性由 harness 自己负责；出问题**记录**，不掩盖、不自动回退数据。
- 凭据与本单无关：安装/更新**不涉及任何凭据**；下载走公开来源。
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用。
