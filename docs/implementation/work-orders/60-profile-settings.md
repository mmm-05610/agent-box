# Work Order 60 — Profile 设置：角色即绑定点（权限规则 / 指令资产 / 资产绑定 / 克隆 / session 归属纠正）

状态：**READY_FOR_EXECUTION**（2026-09-16 用户逐条裁决；实现未开始）。
依据：[profile 设置参照与讨论稿](../../server-round1/profile-settings-reference.md) §5–§7。
依赖：与 51/52/53/55/56/57/58/59 **共用一次 wire 重锁**；需 55（provider/model 记录）与 58（资产）先有面。
配对前端单：桌面工作树 **P17**。

## §0 目标

把 profile 做成**唯一的资产绑定点**：角色 = 家族 + 模型槽 + 账号/凭据 + 技能/MCP/hook + **指令** +
**逐工具权限规则**；并且纠正两件语义：**session 不属于 profile**、**换家族只能克隆不能就地切**。

**验收（第一手证据）**：

| 门 | 断言 |
| --- | --- |
| **G1 绑定点** | 一个 profile 上能看到并编辑：模型槽、凭据/账号引用、技能/MCP/hook 勾选、**指令资产引用**、**权限规则**；改完**下一轮生效**（与 P11 G6 同一条） |
| **G2 权限规则** | 采用**逐工具规则**：键（`read`/`edit`/`bash`/`task`/`external_directory`/`webfetch`/**`skill`**/…）各取 `ask`/`allow`/`deny`，支持 glob→动作、**最后匹配生效**；`ask` 由**既有审批往返**实现；"完全访问/默认/计划"是**预设**（逐工具可覆盖）。不支持的键/动作 → **类型化拒绝** |
| **G3 指令资产** | 指令与 skill/MCP 并列，走同一套资产存储与只读物化；注册表 `instruction` 槽位不支持的家**如实声明** |
| **G4 session 归属纠正** | 数据与呈现都改成"**session 属于工作区/产品；profile 是当前绑定**"；会话带**按轮的 profile + revision 归属**；**不存在**"某 profile 拥有的会话"这种表述与查询 |
| **G5 克隆（跨家族）** | 只能**克隆**出另一个家族的 profile；克隆**尽量拷贝并翻译**，**逐家声明可迁移/不可迁移项**；**session 类资产不迁移**；克隆后的新 profile **不假装继承**旧的原生会话 |
| **G6 换绑定后的原生连续性** | 按 [讨论稿 §7.3](../../server-round1/profile-settings-reference.md) 的分档执行：**文件式 journal** 家族可把**该会话自己的**原生文件搬进新绑定的 home（留可审计事实）；**共享 DB 式**家族如实重启并在界面明说；**不许假装续接** |
| **G7 不退化** | 既有 `profiles.*` / `sessions.*` 方法语义与既有会话不退化；全量套件与四家全链门不退化 |

## §1 现状（第一手）

- `server_sessions.profile_id` = **当前绑定**（一个指针）；`server_turns` **每轮**记 `profile_id` +
  `profile_revision` + `native_generation`（归属已按轮）；wire 上已有 `sessions.switchProfile`（同事务发
  `config.changed`）。
- 配置按轮冻结（`effective_config_object_digest`），控制项由 `config.describe` 描述（`enum`/`model_slot`）。
- 注册表已声明槽位 `[provider, permission, instruction, mcp, skill]`、`skill_target`/`skill_env`。
- **缺**：逐工具权限规则、指令资产的产品面、资产绑定清单、克隆路径、以及 §0 的 G4/G6 两条纠正。

## §2 阶段

- **A 记录扩展**：profile 增加权限规则集、指令资产引用、资产绑定清单（技能/MCP/hook 的 id+revision+启用）；
  为克隆留 `origin_profile`（谁克隆的、当时的 revision）；
- **B 权限求解**：把规则求成该轮生效的权限集合（`ask`/`allow`/`deny` + last-match-wins），
  与控制项一起进冻结配置；`ask` 与既有审批往返对接（不得绕过既有审批语义）；
- **C 归属纠正**：会话列表/详情/事件按"session 属于工作区、轮归属 profile"重述；
  去掉一切"profile 拥有 session"的查询与文案；
- **D 克隆**：同家族克隆（结构相同、直接拷）与**跨家族克隆**（逐家翻译表 + 不可迁移项清单 +
  session 类资产不迁移）；克隆结果**必须**标出"这是克隆、来源是谁、什么时间"；
- **E 换绑定的连续性**：按 §7.3 分档实现（文件式搬文件并记账；共享 DB 式如实重启）；
- **F 回归与收口**：不退化 + status 分账 + 报告。

## §3 硬性规则

- **零回写**：克隆与换绑都只动**我们的记录与投影**，不写用户原生配置；
- **不假装**：克隆/换绑定都不许假装继承了原生会话；不可迁移项**逐条列出**；
- **权限不得放开**：规则求值只允许**收紧**既有能力（不得因规则让某工具获得它本来没有的权限）；
  `deny` 优先级最高，其次 `ask`，`allowed` 需显式；
- 与 50 的能力规则一致：**声明 ∩ 观测**，能力不自报；
- 不 reset/stash/clean、不 merge main、不 push；真实模型零调用。
