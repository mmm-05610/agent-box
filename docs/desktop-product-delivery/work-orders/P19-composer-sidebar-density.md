# P19 — 输入条与侧栏：向参考稿对齐（密度与控件内容，非重写）

基线：P10/P18 之后。**转写区维持现状**（用户 2026-09-17 裁定："能用但朴素是 Hermes 自己的风格，
留着也行"——**AI Elements 换皮降级为可选项**，仅在某个部件明显逊色时按件采纳）。
本单只对齐**两个面**：**输入条的控件排布**、**侧栏的信息密度**。

## 参考稿解剖（用户给的两张图，逐元素）

**输入条（单个圆角容器）**：

```text
┌──────────────────────────────────────────────────────────┐
│ <文本区：多行，占主体>                                      │
│                                                          │
│ [+ 菜单]  [🛡 完全访问 ▾]        [◦环] [模型 ▾] [推理档 ▾] [↑] │
└──────────────────────────────────────────────────────────┘
```

- **同一容器**内：文本在上、一行控件在下（已是 P08 的结构）；
- 左侧：`+`（附件/菜单）+ **访问模式 chip**（"完全访问"——后端权限控制项声明后启用；
  未声明时**显示为不可用或隐藏**，不许假）；
- 右侧：**上下文用量环**（`Unknown` 直到 51 供数）、**模型 chip**（`模型名 ▾`，P08 已做）、
  **推理档 chip**（后端无此控制项 → 隐藏，不放假档位）、**发送**。

**侧栏（信息密度是第一要求）**：

```text
[新建任务  Ctrl+N] [搜索  Ctrl+K]        ← 动作行（P10 已做）
[自动化]（折叠段）                        ← 已有 cron 段
[# 分组 | 项目] [展开/收起] [筛选]         ← 分组切换（P10 已做）
项目                                     ← 组头
  ◠ 项目A                                ← 项目行（图标 + 名）
    · 任务1                    8分        ← 会话行：标题 + 相对时间 + 状态点
    · 任务2                    2天
  ◠ 项目B
    · 任务3            ● 16小时             ← 状态点（运行中/未读/已归档）
─────────────────────────────
[头像] [名字 · 档位]        [手机] [⚙]     ← 底部账户行
```

## 用户点名的差距（本单要修的）

1. **空白太多**：侧栏行距/分段间距明显大于参考稿——**压缩到参考稿的密度**
   （行高、组间距、区块 padding 全部收紧；以参考稿的视觉密度为准，逐项量）。
2. **输入条控件排布**：访问模式 chip 应在**左侧**（`+` 旁）、模型/用量/发送在**右侧**——
   与参考稿的左右分组一致；当前实现控件位置/分组如有出入，按此对齐。
3. **两处已知未闭合**（不是本单新问题，一并收）：
   `disabledPlaceholder` 指向的"note"在无 profile 状态下**并未渲染**（文案与状态不一致）；
   左下角状态项在**本次构建里仍显示旧词**（源码已改 Service，等下次构建生效——核对即可）。

## 阶段

**A 对照实测（先做）**：先用 wire 播种一个工作区 + 会话（像 P18 冒烟那样），**截 populated 状态**的
输入条与侧栏，与参考稿逐元素量差（间距/字号/行高/图标尺寸），产出差距表进 evidence。

**B 输入条**：按解剖图对齐左右分组与间距；`+` 菜单、访问模式位、模型 chip、用量环、发送的
**位置固定**，内容按各自的可用性如实显示（未知/等待/不可用都照旧纪律）。

**C 侧栏密度**：动作行 → 分组切换 → 两级列表 → 底部账户行的**垂直节奏**收紧；
会话行 = 状态点 + 标题 + 相对时间；项目行 = 图标 + 名 + 计数；分组切换保持 P10 的两个维度。
**保留** P10 的全部既有行为与测试（重排/拖拽/过滤/右键/profile 切换）。

**D 回归与收口**：typecheck + 既有 JS/e2e 用例计数不降；新增"密度对照"截图进 evidence；
更新 status；释放写权。

## 门

| 门 | 断言 |
| --- | --- |
| **G1 对照** | 差距表逐元素：参考稿元素 → 实现 → 量出的差 → 已对齐/不适用 |
| **G2 密度** | 侧栏在"有 3 个项目、每项 3+ 会话"的种子数据下**无大片空白**（截图对照参考稿） |
| **G3 输入条** | 控件左右分组与参考一致；无 profile 时发送禁用且有**可见的**原因（不再是"指向不存在的 note"） |
| **G4 诚实** | 访问模式/用量/推理档在无后端支持时的表现符合各自纪律（不可用/未知/隐藏） |
| **G5 不退化** | typecheck 与既有用例计数不降；保护路径零改动；后端仓零写入；不碰 main、不 merge、不 push |
