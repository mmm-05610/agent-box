# P15 — Skill Hub / MCP Hub + 设置页剪裁（脱离产品范畴的先删）

基线：P14 之后（串行）。配对后端单：**58**（资产库、物化、绑定、探测、来源同步）。

```text
之前
├── settings/       ⚠ 仍有大量脱离我们产品范畴的 section（旧桌面线的遗留）
├── skills          ⚠ 只在后端有槽位/目标的概念，产品面没有"装了什么、用在哪家"
└── MCP             ⚠ 同上：有槽位概念，没有统一管理面
之后
├── Skill Hub       ◀ 资产列表（名称/描述/来源/摘要/修订）→ 安装/更新/删除 → 逐 profile 启用
├── MCP Hub         ◀ server 列表（stdio/remote、命令或 URL、凭据引用）→ 测试连接 → 逐 profile 启用
└── settings        ◀ 每个 section 过一遍台账：保留 / 合并 / **删除**（删除是真删，不是藏起来）
```

## A 设置页剪裁（先做，用户点名）

- **做法**：为每个现有 section 出一行台账：`它服务什么产品能力` → 结论（保留 / 合并 / 删除）；
  **判据**：与"Server + Profile/Session + 家族 + 资产"这套语义无关的，**删除**（真删代码与入口，
  不留半死状态）；**与家族相关但属于别家产品的**（例如某个只服务旧线的运行时面板）→ 删除并记录。
- 门：**G1** 台账齐全，每个 section 有结论；**G2** 删除项在界面上**不存在**且无孤儿引用（无死代码、
  无未用事件源）；**G3** 保留项的既有用例不退化。

## B Skill Hub

- 列表：名称、描述（来自 `SKILL.md` frontmatter 的 `name`/`description`）、来源、摘要、修订、
  安装时间；**目录优先**（可用条目先画，状态异步标注，照 P13 的模式）。
- 动作：安装 / 更新 / 删除（**都是用户动作**，不自动更新）；错误可读且**失败不落地**。
- **逐 profile 启用**：勾选启用哪些 skill；某家**不支持 skill 槽位**时**如实显示"该家不支持"**，
  不做假开关。
- 门：**G4** 未装/已装/可更新三种状态正确；**G5** 不支持的家不出现可点的启用开关（有反例用例）。

## C MCP Hub

- 列表：server 名、传输类型（stdio / remote）、命令或 URL、**凭据引用状态**（已引用/缺失，
  **不显示密钥内容**）、最后测试时间与结果。
- 动作：新增/编辑/删除（stdio 的 `command/args/env` 或 remote 的 URL；env 值来自**凭据引用**）、
  **测试连接**（后端 58 的有界探测；无后端面时按钮**显示不可用**，不做假按钮）。
- 逐 profile 启用，同 B 的纪律。
- 门：**G6** 凭据**零内容**（界面、日志、证据）；**G7** 测试连接失败给出可读原因并**不写入配置**。

## D hooks / commands（有收敛才做）

- **hooks**：后端 58 的结论是**没有成熟收敛** → 本单**不做**统一管理面；
  若要展示，只能**只读展示各家支持情况**（且必须逐家如实），**不提供编辑**。
- **commands（提示片段）**：可复用 skill 的存储/物化机制（同为 markdown 资产）；
  **但必须区分**：我们的斜杠菜单（前端命令面板）与 harness 的斜杠命令（发给模型的文本）**不是一回事**，
  界面上要写清是哪一种。
- 门：**G8** 不做没有后端支撑的管理面；**G9** 若做 commands，界面明确区分两类斜杠语义。

- **不做**写用户原生配置；**不做** hooks 编辑；**不做** wire 变更（只消费 58 的面）。
