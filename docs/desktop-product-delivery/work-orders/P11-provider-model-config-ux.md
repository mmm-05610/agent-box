# P11 — 供应商/模型配置：交互逻辑重做（预设 + 覆盖，取代自由文本表单）

基线：P07 之后（串行）。只改**设置里的供应商/模型配置**与其在会话里的绑定显示；
输入条本身在 P08、会话区在 P09、侧栏在 P10。

```text
之前（现状）
├── agentbox-model-settings.tsx   ⚠ harness / provider / 模型 全是自由文本；一条记录 = 一张表
└── 凭据                          ⚠ 有选择器，但与"供应商"没有语义关联
之后
├── 供应商 = 预设 + 覆盖           ◀ 端点 / 认证方式 / 协议风格 / 凭据环境变量名 一次填对
├── 模型列表                       ◀ 优先从供应商拉取勾选；每条带 名字 / 上下文窗口 / 能力开关
└── 绑定                           ◀ 记录 + 模型 绑到 profile 的模型槽；composer 里选的是"记录+模型"
```

## 目标与三条判断

**目标**：把"配置"从**自由文本表单**改成"**选供应商预设 → 引用凭据 → 拉取/挑选模型 → 测试连接 →
绑定到 profile**"。**尽量用现有组件**（shadcn/radix + 既有表单件），不引新库。

1. **病根是概念缺失**：今天 UI 里"供应商"只是三段手打字符串，没有"供应商 = 一组已知事实
   （base URL / 认证方式 / 协议风格 / 凭据变量名）"的概念。改成**预设 + 覆盖**，自由文本自然消失。
   （我们自己的部署文档早就按这组事实在写：例如 codex 侧 `base_url` / `env_key` / `wire_api`
   是既有字段——参照并不远。）
2. **拉取模型与测试连接是后端动作**（要带凭据出网），必须**有界、可审计、零日志**——那是
   **后端 55** 的范围；本单只做交互与展示，**拉取/测试没有后端面时显示"不可用"**，不做假按钮。
3. **能力与窗口是"声明"，必须有来源**：预设带的、拉取拿到的、或用户手填并**标注为手填**；
   **没有来源就显示未知**（与后端 51/53 同一规矩）。**上下文窗口就是那个上下文百分比的分母**。

## 参照（已取证的一条 + 通行做法）

- **LibreChat `modelSpecs`**（本轮取证）：每条 spec 有 `name`（唯一 id）与 `label`（显示名）、
  `default` / `softDefault` / `showInMenu` / `group` / `groupIcon`、`authType`
  （`override_auth` / `user_provided` / `system_defined`）、一组**能力开关**
  （`webSearch` / `fileSearch` / `executeCode` / `artifacts` / `mcpServers` / `skills`）、
  `conversation_starters`，以及 `preset` 里的 `endpoint` / `model` / `modelLabel` /
  **`maxContextTokens`** / 采样与**推理**项（`reasoning_effort` / `useResponsesApi` 等）。
- 通行做法（本轮**未逐条取证**，仅作形状参考）：供应商预设预填端点与认证；模型**从端点拉取**勾选；
  凭据存密钥库只留引用；"测试连接"按钮给类型化错误；模型带能力/窗口元数据。

## 补：从 cc-switch 学到的（2026-09-16，用户点名）

参照 `farion1231/cc-switch`（MIT，Tauri 2 + Rust + React + SQLite）——九家 AI 编码工具的配置中心。
本轮取证到的**数据模型与交互**，逐条决定"学 / 不学"：

| 它的做法（取证） | 我们 |
| --- | --- |
| **预设库很大**（50+：官方、AWS Bedrock、NVIDIA NIM、社区中转），预设之外才自定义 | **学**：预设目录要可扩展（内置常见几家 + 社区条目作为**数据**而非硬编码逻辑），并提供"从预设导入"一键填端点/认证/协议 |
| **共享配置片段**（Shared Config Snippet）：多条记录重复的部分抽出来复用 | **学**：把"公共片段"做成可复用引用，避免每条记录重复填同一组事实 |
| **"当前生效" + 切换**；**编辑生效中的那条时从 live 反填** | **学**：列表要有"生效中"标记；生效值从**我们的**事实源反填（`config.resolve` 的生效值），**不是**读宿主配置文件 |
| **进口/出口 + 首次导入现有 CLI 配置 + `ccswitch://` 深链** | **半学**：导入/导出**我们自己的记录**要学；**绝不导入用户本机原生配置**（`~/.codex` 一类禁读）；深链是加分项，先不做 |
| **通用供应商**（一份配置同步到多个工具） | **学概念**：一份"供应商事实"可以被多个家族记录引用；但不做"同一份配置同时写进多个 harness 的配置文件" |
| **排序/拖拽分组** | **学**：列表可排序与分组（沿用本仓既有 reorder 件） |
| **数据在 SQLite，称"单一事实来源"** | **我们已经如此**（记录在控制面） |
| **切换时直接写 live 配置文件**，因为"多数工具要重启 CLI 才生效" | **这是它的缺陷，不是特性**：写 live 文件 = **全局只有一份生效状态** → 运行中的进程早已读过旧文件 → **必须重启才生效**，而且它会**改动用户的文件**。
| | **我们的做法免费拿到热切换**：状态（配置与账号）是**受管资产 + 按轮物化**，每轮新进程读新物化 → **换 provider / 换模型 / 换账号都在下一轮生效，且不需要重启、不影响运行中的会话**。所以这一项不是"我们选择不做"，而是"我们做得更好"——见本单门 G6 |
| **官方登录预设 + 切过去跑 logout/login** | **学管理，不学机制**：订阅/官方登录是**账号**而非端点，**独立托管、按轮物化、可热切换**，见 **P12 / 后端 56**（登录由用户在**执行侧**完成，**登录态在控制面**，绝不碰用户本机登录态） |

## 阶段

**A 盘点与对照（不改代码）**：列出当前表单的每个字段 → 新交互里的归属（预设/覆盖/引用/未知），
产出"参考元素 → 我们用什么 → 数据来源"三栏表（进 evidence）。**没有来源的不实现。**

**B 供应商**：预设列表（常见几家）+ 自定义；字段 = 名称、base URL、认证方式（Bearer / 指定 header）、
协议风格（chat / responses / anthropic 风格路径）、**凭据引用**（不内联密钥，只显示"已存在/缺失"）。

**C 模型**：列表（拉取勾选优先，其次手填）；每条带**显示名 / 上下文窗口 / 能力开关 / 推理档**；
能力与窗口标注来源（预设 / 拉取 / 手填）。**拉取面未就绪时按钮显示不可用并说明原因。**

**D 测试连接**：调后端（55）的一次探测；类型化错误翻成可读文案；**不写入任何配置**。

**E 绑定与迁移**：记录 + 模型绑到 profile 的模型槽；composer（P08）里选的是"记录 + 模型"；
既有记录**照常可用**（新字段缺省 = 未知，不阻塞）。

**F 回归与收口**：既有设置页用例不退化；补"无来源即未知""未授权不做假按钮"的反例；更新
status/evidence；释放写权。

## 门

| 门 | 断言 |
| --- | --- |
| **G1 无自由文本关键项** | 端点/认证/协议三项由预设或显式覆盖提供，**不再是三段随手打的字符串** |
| **G2 凭据只引用** | 配置里只有引用；**任何界面、日志、证据里不得出现密钥内容** |
| **G3 无来源即未知** | 窗口/能力没有来源时显示未知；有反例用例；**不得填默认值冒充** |
| **G4 不做假按钮** | 拉取/测试在没有后端面时**禁用并说明**，不得假装成功 |
| **G5 不退化** | 既有设置/会话用例计数不降；`config.describe`/`config.resolve`/`overrides` 的既有消费路径不变；保护路径零改动；后端仓零写入；不碰 main、不 merge、不 push |
| **G6 热切换（有证据）** | 换 provider/model（以及 P12 的换账号）**在下一轮生效**、**不需要重启**、**不影响运行中的会话**；有第一手用例（切完发下一轮，生效值变化；同时运行的另一会话不被改动） |
