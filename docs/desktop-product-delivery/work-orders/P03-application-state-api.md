# P03 — 向下统一用例、状态与客户端边界

遵守[总方针](../master-plan.md)全部授权、保护区、资源与持续执行纪律。
输入：[产品决定](../../night-work-planning/product-decisions.md)；基线见[状态](../status.md)。

范围：src/application/**、store/**、api/**、types/**、lib/**及P02必要调用者。
从上层意图反推窄职责，不先建立通用大框架。遵循现有层序，不增加反向import。
application协调，store只视图/草稿/服务投影，api只传输；身份/Profile/历史不可另造权威数据库。
草稿本机持久化：每项目新会话草稿+每Session输入草稿，带版本；接受回执仅清已发版本。
损坏/新版存储保护，迁移保留原文件/备份，不扫描导入用户真实数据。
发送幂等身份贯穿；未知结果先确认，不能重发成新请求；取消/断连/失败/终态不混淆。
类型与测试可先使用INTERNAL_NOT_WIRE端口；不自行定义后端HTTP协议。
服务真实事件驱动业务投影；禁止用前端运行队列假扮后端队列、用拷贝对话模拟native resume。
移除对Hermes gateway字段/方法的通用业务依赖；尚需旧入口只隔离非默认legacy路径并记账。
验收：延迟/乱序/重复回执、切项目/角色、断连恢复、不支持能力、空服务等反例。
每条纵向切片提交；定向测试+typecheck+层序守卫，已有债务不增加，P03完成后继续P04。

阶段终态：P03_GREEN 或 P03_PARTIAL。
PARTIAL必须拆出等待子项与下一可做项，不默认终止整个goal。
