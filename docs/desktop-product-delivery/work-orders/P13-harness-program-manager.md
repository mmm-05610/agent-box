# P13 — Harness 程序管理（安装 / 更新 / 回滚 / 版本选择）

基线：P11/P12 之后（串行）。配对后端单：**57**（工件目录、版本、下载/构建、校验、回滚）。
参照：**Applite**（Homebrew GUI）的目录模式（见 §参照），以及两个负面事实（见后端 57 §1b）。

```text
之前
└── 每家 harness 的"程序"是不可见的：装在哪、装了几版、有没有新版，界面上一无所知
之后
├── 程序列表        ◀ 每家一行：当前版本 / 已安装的其他版本 / 大小 / 来源 / 安装时间 / 摘要
├── 更新徽标        ◀ 可更新（**异步标注**，不是打开界面就转圈）；点开可选版本
└── 动作            ◀ 安装 / 更新 / 回滚 / 设为当前；长任务显示进度与可读错误
```

## 目标

把"程序"变成**看得见、管得住**的东西：**目录优先**（可用版本先画出来）、**状态异步标注**
（已安装/可更新后补）、**一键动作**（安装/更新/回滚），并且**不阻塞界面**。

## 参照：Applite 的四条可复用交互（本轮取证）

1. **目录优先**：可用条目先落本地目录，"SQLite paints the UI immediately"——渲染**不等**任何后端调用；
2. **异步标注**：已安装 / 可更新由后端状态**反应式补上**，"nothing blocks on the brew CLI"；
3. 分类 + 搜索；**一键**安装/更新/卸载；
4. **导入导出**用于迁移（逐项选择）。

→ 我们照这四条做；**但"导入"只导我们自己的记录**，**绝不导入用户本机配置**（P11 的既有边界）。
另外两个负面事实：**claude-squad 让用户自己更新底层程序**、**vibe-kanban 假设程序已装好且已 sunset**
——说明这一类应用**没人做程序管理**，所以没有现成 UI 可抄，只能借包管理器的形状。

## 阶段

**A 盘点**：列出"一家程序"需要的每个字段 → 对应后端 57 的哪个返回值；**没有来源的不显示**
（例如后端给不出"可更新"，就不画更新徽标）。产出三栏表进 evidence。

**B 列表与状态**：每家一行（当前版本 / 其他已装版本 / 大小 / 来源 / 安装时间 / 摘要）；
**可更新**是后端给的标注，**前端不推断版本大小**；无数据即"未知"。

**C 动作与进度**：安装 / 更新 / 回滚 / 设为当前；长任务（下载或构建）显示**进度与可读错误**；
失败时**明确保留旧版**（后端保证，界面如实呈现）。

**D 与配置的衔接**：程序版本与"当前 profile 用哪版"的关系要**可见**（P11/R12 的记录引用它）；
换版本与换账号/换模型一样**下一轮生效**（P11 的 G6 同一条纪律）。

**E 回归与收口**：既有设置页用例不退化；补"未知不显示""动作失败保留旧版"的反例；更新
status/evidence；释放写权。

## 门

| 门 | 断言 |
| --- | --- |
| **G1 目录优先** | 界面**不等**后端慢调用就能画出列表（目录来自控制面）；有证据（后端未响应时列表仍可见） |
| **G2 状态不猜** | 已安装/可更新**只来自后端**；缺数据即未知；有反例用例 |
| **G3 动作诚实** | 失败**如实报错**并**保留旧版**；**不做**假进度、不做假成功 |
| **G4 换版本下一轮生效** | 与 P11 的 G6 同一条：换版本**不需要重启**、**不影响运行中的会话**，有第一手用例 |
| **G5 不退化** | 既有 JS/e2e 用例计数不降；保护路径零改动；**后端仓零写入**；不碰 main、不 merge、不 push |

## 边界

- 后端（57）负责：目录同步、工件取得与校验、版本目录与引用、回滚、类型化错误；本单只做交互与展示。
- **不做**自动更新（更新永远由用户点）；**不做** wire 变更（只消费 57 的面）。
