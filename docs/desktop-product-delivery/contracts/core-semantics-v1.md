# AgentBox Desktop核心能力合同 v1 — 已批准语义

版本：core-semantics/1。状态：APPROVED_SEMANTICS，2026-09-14。
来源：用户逐批批准的生命周期、远端执行、数据身份、工作区、角色配置、消息运行、审批恢复决定。
这是一份客户端与服务端共同实现的行为合同，不是对现有后端实现的GREEN认证。
HTTP路径、认证引导、序列化与可执行schema由P07整理为单一候选wire，再由后端接单时核对锁定。
前端现在可据此完整实现通用用例、类型、界面与合同测试，不再等待产品语义裁决。

## 1. 职责与数据权威

```text
本机Desktop
├── Renderer                页面、布局、选择、未发送草稿、后端状态投影
└── Electron                本机宿主能力、托管Server基础设施生命周期
本机AgentBox Server
├── 业务持久化              Workspace/Session/Profile/Provider-Model/审批/队列/事件
├── Core与能力扩展          组织执行；Server不实现单个Harness原生协议
└── Harness接入体系         原生配置、事件、审批与续接的差异
远端Worker                  通过受认证双向通道接入本机Server的执行端
└── ~/.agent-box/
    ├── worker/ tools/      可复用程序与依赖缓存
    └── runs/<run>/         临时home/state/tmp，不是另一份业务数据库
```

远端项目仍在原位置。不得写入用户原生~/.claude、~/.codex等目录作为角色权威。
执行需要的原生目录允许存在于受管临时投影，记忆/续接材料按声明取回确认；未回传状态不承诺无损。
秘密单独受控投递，不进普通缓存、事件、日志、备份与通用状态回传包。
Worker通信可复用WSL/SSH标准通道，不要求公网回连或必须TCP；客户端角色与传输建连方向分开。
连接引导实现必须可被独立Server使用；Electron可提供宿主引导便利，不成为执行必要依赖，
不再维护第二套业务连接/执行状态。物理Worker复用不改变Workspace独享逻辑连接与隔离约束。

## 2. 生命周期

- Desktop正常开窗，后台确保托管Server可用；没有Harness仍可开窗与启动Server。
- 只监督/回收自己启动的服务；独立启动的外部Server不因Desktop退出被停止。
- 切项目/会话/页面不停止任务。关闭主窗口可收托盘继续，首次说明；明确退出应用时，
  有任务需确认，再由托管Server停止任务、收尾并退出。不增加永久后台守护服务作为第一版前提。
- Desktop失联但Server仍在：任务继续；缓存标旧，草稿继续编辑，不能假装业务写入成功。
- Server与Worker失联：执行暂时未知，有限重连期后依约回收，不承诺远端长期离线自治。

## 3. 业务对象与修改

Server分配稳定不透明ID；展示名、路径、原生Harness会话ID均不是AgentBox对象身份。
重命名、重连、归档恢复保持ID。Session可切Workspace、同Harness切Profile，身份与历史不改。
是否能真实切换由接入能力与后端确认；前端不模拟上下文搬运或将原生会话ID作业务ID。

| 对象/内容 | 权威与不变量 |
| --- | --- |
| Workspace | Server登记；环境身份+规范化目录识别位置；逻辑连接私有；不同环境相同字符串不是同位置 |
| Session | Server独立对话身份；关联当前Workspace与角色，非Profile子资源；历史保留当时归属 |
| Profile | Server角色资源；静态配置与可积累原生记忆分开；不绑定Session所有权 |
| Provider/Model | Server可复用配置；Harness适用范围、模型槽位、凭据关联明确，不复制秘密 |
| 置顶/名称/归档 | Server业务元数据；跨客户端一致 |
| 布局/选中/搜索/展开 | Desktop交互状态 |
| 新会话/既有会话草稿 | Desktop本机持久化；文本、附件选择、角色与临时覆盖，迟到确认不删新编辑 |

静态配置更新带版本条件，冲突保留用户输入，不静默后写覆盖。创建/执行用请求标识去重；
同标识不同内容拒绝。幂等接受不等于外部副作用exactly-once。
归档与停止/永久删除分离：不删项目文件、不级联删历史/记忆。运行中归档需说明继续运行，
活动入口仍可见。归档角色不允许新选择，已有运行按已确认配置收尾。永久删除需独立确认及引用校验。

## 4. 工作区

侧栏一个平铺项目列表；本地和远端同级。打开只登记/选中并进入草稿，不建Session、不启动Harness。
本地由Electron提供系统目录选择器；远端目录由Worker列举，Desktop呈现。
Server经对应执行端确认环境、路径与访问条件；前端不做Windows/Linux/UNC语义替换。
可读即可浏览；可写和能执行是独立条件，不把只读目录一律拒绝打开。
环境连接、目录可访问、当前角色可运行分开报告，不用一个Verified承诺所有能力。
连接自动准备Worker基础组件；角色确定后按需准备Harness，复用兼容安装，不提权/覆盖用户安装，
不顺便安装项目全部依赖。远端配置入口只在侧栏，不进设置建共享连接管理器。
打开不等于执行信任；项目Hooks/MCP可执行配置不得自动运行或扩大权限；信任由Server绑定环境/工作区。
独立本机Git可复用Electron；远端Git经Server/Worker；为运行准备Worktree由Server组织。
分支字符串不证明目录已切换；执行前核实真实目录，不自动stash/reset或切换共享工作树。

## 5. 角色与动态配置

接入层描述字段、候选值、默认/当前值、适用性与生效时点，Server提供给Desktop。
Desktop只认识有限控件类型与呈现分类，不接收任意JS/HTML、不按Harness名字决定正确性。
完整Profile编辑与运行选项分别描述；未知可选控件明确不可编辑，未知必需/安全项不能忽略后运行。
Provider/Model支持共享选择及原生多槽位，目录里存在不代表验证可用；删除检查引用，不静默替换。
后端计算生效配置：接入默认→Profile默认→明确临时覆盖；安全限制不可被覆盖。
原生项目配置在信任规则下由接入层解释，不能暗中压过已确认选择。
恢复默认是删除覆盖，不是复制默认。运行接受时固定实际配置版本，草稿选择不等于生效。
新会话选择不创建Session。已有会话切换由后端确认，失败保持旧实际状态并显示原因。
运行中默认修改影响下一次发送；即时修改只按声明能力。切角色默认清除旧临时覆盖。
不静默换模型/身份/扩大权限；原生回退需真实呈现并受批准策略约束。

## 6. 消息接受、队列、事件与停止

首次发送是一个业务意图：Server基础校验后一致保存Session、首消息与待执行记录，确认已接受，
再派发。接受前失败保留草稿不造空Session；接受后启动失败保留会话及失败事实。
后续发送关联稳定Session；请求超时查原标识，不换新标识盲目重发。
Server管理队列，一个Session默认一项普通执行。默认follow-up；steer独立能力，不用停止重启冒充。
排队固定提交时角色/配置/内容；尚未派发可撤回，派发竞态由Server裁决。
正常完成继续队列；失败或用户停止暂停后续；异常重启恢复队列记录但不自动派发。
事件归一化：消息/增量、工具及更新、可选计划/产出/用量、审批、配置、状态及结束原因。
接入层解释原生，Server赋稳定身份和顺序持久化，Desktop渲染；不读日志猜终态。
允许声明式独特能力，不透传整包秘密/raw协议让UI解释。Execution只作后台身份，不要求用户理解。
停止是请求→正在停止→真实确认；收尾更新仍可到达。任务同时完成以真实终态为准。
无法确认子进程停止不报已停止。停止不回滚文件/Git/外部动作。
明确重试创建关联旧记录的新尝试；后端自动重试仅限确认安全范围，不能声称所有副作用只发生一次。

## 7. 审批与恢复

Server拥有审批事实；用户经授权客户端作决定。默认仅本次允许/拒绝，更长授权必须准确描述
动作、环境、范围、时限；不以含糊always表示永久，不自动修改Profile。
切角色/工作区不继承旧临时授权。批准的运行策略在后端执行；拒绝工具不必然停止整轮。
审批绑定运行、操作内容、有效状态与版本；多窗口共享一份审批，首个有效决定原子接受。
同决定重试返回已存结果，矛盾决定拒绝；已结束/取消/过期不能授权。关窗口不自动批准，
原生等待已失效不能凭历史重新发送批准。审批过期时间若有必须由后端明确告知。

Server保存可恢复业务事件再发布；允许批量持久化，不把每个心跳永久存储。
事件稳定身份和会话内顺序，重放可重复、应用不重复。快照包含一致游标，与后续订阅无缝衔接。
过旧游标明确要求取新快照，不能静默丢事件；重放只恢复展示，不重做工具/消息/审批。
Desktop重启恢复订阅；Server重启先核Worker运行身份、存活与游标，确认后接管，不重复派发。
Worker/Harness消失则原尝试中断；材料完整且支持原生续接时，可保留Session开启新的尝试。
无法确认原任务存活则待核实，不能启动第二份。原生续接不是复活进程，不承诺未回传状态无损。

## 8. 逻辑能力目录（不是HTTP路由）

字段名可在P07统一编码；下面的信息与行为不可遗漏或换权威。

| 能力 | 用户意图/必要输入 | 必要结果 |
| --- | --- | --- |
| 服务状态/能力发现 | 客户端支持的合同版本与呈现能力 | 服务身份/版本、可用能力、缺失原因；无秘密 |
| 环境准备/浏览 | Workspace私有连接意图或已登记身份、路径、操作标识 | 进度、真实环境身份、目录条目、可访问性、失败原因 |
| 工作区打开/维护 | 已核环境+路径；修改时稳定ID与版本 | 权威Workspace、重复打开识别、归档/恢复状态 |
| 角色/模型维护 | 配置草稿、关联资源、修改版本 | 保存版本、引用关系、配置合法性与可运行性分别报告 |
| 配置描述/解析/切换 | 角色、Workspace/Session、临时覆盖 | 控件描述、生效值、限制原因、何时生效；不隐式启动 |
| 首次发送/继续发送 | 请求标识、消息与附件、角色/配置、Workspace或Session | 接受或拒绝、稳定业务身份、实际配置版本、可查询状态 |
| 查询接受结果 | 原请求标识与所属范围 | 已接受/拒绝/仍未知，不能将未知解释为安全重发 |
| 队列管理 | Session、待处理项身份、操作及版本 | 权威队列、撤回/冲突、暂停/继续事实 |
| 会话历史/订阅 | Session、分页位置/恢复游标 | 快照位置、稳定事件顺序、续流或需重新同步 |
| 停止/审批决定 | 目标运行或审批身份、请求标识、有效版本/选项 | 决定已接受或冲突；实际终态另行确认 |
| 续接/重试 | Session、原尝试、明确用户意图 | 能力校验、关联的新尝试或拒绝，不改写旧失败 |

凭据采集、登录、模型请求授权的安全传输细节在wire中另明确；本合同不授权执行者读取真实材料。
模型/附件ID不得依赖不安全字符串拆分；文件内容读取及投递必须携带环境/范围并校验授权。

## 9. 必测合同场景

1. 无Harness/Server未就绪仍开窗，业务写入诚实不可用。
2. 两个环境同路径不误认；重复打开同位置保留ID；不创建会话。
3. 首发并发重试只接受一份；接受前拒绝/接受后启动失败分开；超时查询不重复派发。
4. 修改Profile版本冲突；运行配置固定；切角色失败保留实际旧值；排队不被后续选择改写。
5. 正常完成继续队列，停止/失败暂停；停止竞态与收尾事件不误报。
6. 两窗口审批竞争，过期/内容改变/取消后批准拒绝；重放不触发审批操作。
7. 快照到订阅之间插入事件仍可见；重复重放不重复；过期游标明确重置。
8. Desktop重启重连不派发；Server重启先核对；Worker消失不假称原执行恢复。
9. 远端只有受管工具及限时现场，结果回传确认与清理分别有证据，零材料进入日志。

## 10. 参考与借鉴边界

- [VS Code远程能力归属](https://code.visualstudio.com/api/advanced-topics/remote-extensions)：位置感知、受管远端组件；不照搬其全部数据与生命周期。
- [Coder架构](https://coder.com/docs/admin/infrastructure/architecture)：执行端连接控制面；未选为整套依赖。
- [Jupyter运行管理](https://jupyterlab.readthedocs.io/en/stable/user/running.html)：界面关闭与执行停止分开。
- [AIP请求标识](https://google.aip.dev/155)、[版本校验](https://google.aip.dev/154)：去重与防旧版本覆盖；不承诺外部副作用exactly-once。
- [ACP配置描述](https://agentclientprotocol.com/protocol/v1/session-config-options)：描述式运行选项，不等于完整Profile表单或Desktop直接接ACP。
- [ACP对话](https://agentclientprotocol.com/protocol/v1/prompt-turn)、[审批](https://agentclientprotocol.com/protocol/v1/tool-calls)、[加载会话](https://agentclientprotocol.com/protocol/v1/session-setup)：呈现/取消/续接能力，不等于任意进程恢复。
- [OpenCode Server](https://opencode.ai/docs/server/)、[配置](https://opencode.ai/docs/config/)、[权限](https://opencode.ai/docs/permissions/)：客户端服务分离与明确配置规则；不复制其always作用域为永久。
- [Pi RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)：steer/follow-up/acceptance分开；本产品停止后的队列策略以本合同为准。
- [SSE恢复位置](https://html.spec.whatwg.org/multipage/server-sent-events.html)：游标机制，不自动提供持久化重放。
- [Temporal事件历史](https://docs.temporal.io/encyclopedia/event-history)：事实持久化与恢复分离；不要求引入工作流引擎。

以上为设计借鉴、非本轮源码抽取资格认定。安装/备份等外围合同另增量编制，不阻塞核心客户端完成。
