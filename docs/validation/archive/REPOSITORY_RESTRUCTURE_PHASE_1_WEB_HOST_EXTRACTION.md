# Repository Restructure Phase 1 — Web Host Extraction
>
> Historical record — describes an earlier architecture or decision input and is not current implementation guidance.

Date: 2026-08-30
Checkpoint: `197c41a`

## Result

Phase 1 closure is complete. `agent-box-web` is an independently buildable
Host package. The root package remains importable and buildable without it,
and the root CLI reports an actionable installation message for `agent-box
web` when the Host is absent.

## Ownership and packaging

- `plugins/agent-box-web/src/agent_box_web/application/` owns Host facade,
  operation persistence, and mutation ownership.
- `plugins/agent-box-web/src/agent_box_web/server/` owns the loopback HTTP API
  and static serving.
- `plugins/agent-box-web/frontend/` contains the production Workbench and its
  i18n/API client/test configuration.
- `plugins/agent-box-web/prototype/` contains only the existing prototype
  files; it is not a Vite input or Python package-data input.
- The package is not registered under `agent_box.plugins`.
- No Web module imports `agent_box_git`, `agent_box_tmux`, `agent_box_codex`,
  `agent_box_harnesses`, or `agent_box_pi`.
- No formal Python source or test imports `agent_box.application` or
  `agent_box.server`.

Static resolution order is explicit override, source
`frontend/dist` for development, installed `agent_box_web/_static`, and the
installed shared fallback. The formal frontend build now writes directly to
`src/agent_box_web/_static` with Vite `emptyOutDir: true`; this is the sole
sync step and removes stale output before every build. The Web wheel contains
`index.html`, `assets/`, `favicon.svg`, `icons.svg`, `logo.png`, and `logos/`;
neither wheel contains `gui-web`, `prototype`, `node_modules`, or a frontend
source `dist` tree.

## Compatibility and remaining work

No import compatibility shim was retained. The in-repository Web tests were
moved to the plugin and use `agent_box_web` imports. The HostApplication/Codex
wiring integration test was moved from
`plugins/agent-box-harnesses/tests/test_codex_wiring.py` to the Web test
suite; Harness tests retain registration, provider, profile projection,
credential, and lifecycle coverage without importing the Web Host. The
browser Harness test was updated to select the existing `<select>` control
exposed by the formal frontend; assertions and product behavior were
unchanged.

## Closure verdict

Both reported acceptance blockers are resolved. The stale Harness import is
gone from formal Python source/tests, and the static pipeline is now
deterministic:

```text
frontend source
  -> npm run build
  -> src/agent_box_web/_static (cleared and regenerated by Vite)
  -> python -m pip wheel plugins/agent-box-web
```

The next planned work remains Harness independence; this closure did not
modify Core semantics or begin Codex/Harness ownership refactoring.

The unrelated dirty worktree changes present before this phase were preserved.
