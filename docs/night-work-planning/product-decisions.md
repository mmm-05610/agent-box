# 产品语义记录（夜间草案）

状态：**DRAFT_NOT_DISPATCHED**。产品决定已记录，尚未授权实施。

## 1. 应用启动与服务/工具就绪分离

- 没有任何 Harness、模型凭据，Desktop 仍应打开正常主界面、侧栏与设置。
- 不再通过启动时的 Hermes 安装/连接向导阻挡整个产品。
- 应用启动、AgentBox 服务连接、执行工具可用、角色可运行是不同事实。
- 服务或执行能力不可用时如实显示状态，限制相应操作，不伪造成功，也不阻断无关界面。
- 哪些现有数据可离线展示、哪些操作依赖服务，待逐项定案，不以移除遮罩冒充后端解耦。

## 2. 工作区拥有连接；设置不管理执行环境

用户纠正：WSL/发行版/用户等执行环境参数只属于侧栏的工作区流程，不进入设置页。

```text
侧栏
└── 工作区（本地与远程同级）
    ├── 添加 → 打开文件夹
    ├── 添加 → 打开远程文件夹
    │   └── 配置远程连接 → 浏览/选择目录 → 打开
    └── 已有远程工作区
        └── 自身连接信息/重连入口

设置
└── 执行工具管理
    ├── 支持的工具及安装/版本状态
    └── 用户主动安装/检查更新/更新
        （不提供 WSL/发行版选择器或连接配置入口）
```

- 一个远程工作区独享其逻辑 Connection，不新增可共享的全局 Connection 管理产品。
- 一般连接参数应不可直接修改；本轮默认保持既有连接身份，不建设通用编辑表单。
- 如后续确需允许特定参数更新，入口只能在对应侧栏工作区，并先明确身份、历史会话和
  重新验证语义；尚未批准“换发行版/换用户但沿用旧身份”等行为。
- 重连/重新验证不等于修改连接；工作区显示名也不等于连接身份。

## 3. 安装/更新是设置内主动能力，必须复用

- 设置页提供已支持 Harness 的安装与更新，不在启动时自动弹出安装门。
- 安装管理必须复用已有项目的实际实现，不仅借鉴 UI 再手写安装系统。
- LinkCode 的 host/assets 等仅是调查线索，尚未选定、未证明可独立复用。
- 适配器版本与原生二进制兼容、安装来源、进行中任务的版本保护等，应由下层管理能力
  承担，不在前端写品牌安装命令，不将工具安装和 Profile 创建混成一个流程。
- WSL 可持久保留执行工具二进制；这不改变 Profile/Session 权威保存在本机的约束。

### 安装目标（已批准，替代此前待选方案）

- 设置中的“Harness安装与更新”仅管理Desktop所在本机，不依赖当前项目，不增加远端目标选择器。
- 删除“设置继承当前项目作为安装目标”的方案，不建设独立的远端工具管理中心。
- 打开远程文件夹：连接、检查运行依赖、缺少则自动准备；显示连接中/准备运行环境/就绪及真实失败。
- 尚未选择角色时只准备连接必需部分；选定角色后按需补对应Harness，不一次安装所有Harness。
- 复用可用且兼容的已有安装；缺失时使用受管安装，不擅自覆盖用户已有版本、不自动提权、不无限重试。
- 远端可保留Worker与Harness二进制；Profile、Session及角色记忆的权威仍在本机。
- 安装管理必须复用现成实现的约束不变；具体依赖来源、兼容判定与实现验收仍待后续派单。
- 本次只批准本小节；前述讨论中的登录/备份等其他待选项不因本次确认自动获批。

## 5. 平铺项目列表与会话草稿（已确认，不重新讨论）

所有项目在同一工作区列表中平铺、同级、同操作；本地/WSL/SSH只是项目背后的连接方式。
禁止 LOCAL/REMOTE 分区、另建远程列表或以连接方式区分产品层级。后续示意图也不再用
“本地项目A / WSL项目B”作为分类标签，避免重新引入歧义。

```text
工作区列表
├── 项目 A
│   ├── 会话 1
│   └── 会话 2
├── 项目 B
├── 项目 C
│   └── 会话 3
└── 项目 D
```

- 打开文件夹或远程文件夹：添加并选中项目，显示空白对话界面，不创建会话、不启动Harness。
- 点击项目本身：进入该项目的新会话草稿，不自动跳进历史会话。
- 点击已有会话：展示对应历史和输入框。
- 首次发送：才创建正式会话，归入当前项目并开始执行。
- 仅选项目、选角色或输入未发送：仍为草稿，不创建正式会话、不启动Harness。
- 空白对话界面的项目选择代表草稿工作上下文；Profile选择代表执行角色，不增加创建向导。
- 这定义产品心智模型，不要求前端绕过后端进行非原子创建；失败/重试及草稿规则见下文。
  会话显示在当前关联项目下，不将未来工作区切换锁死为永久归属。

## 6. Profile 选择与动态配置（已批准）

- 输入框附近显示 Profile 选择框，角色名旁以小图标/小字说明 Harness，不另设一级Harness选择器。
- 每个项目沿用上次选择的Profile；没有历史选择则提示选择，不擅自代选。
- 真正的新草稿从角色基础配置开始，不继承上次会话的临时权限/模型等覆盖。
- 恢复尚未发送的已有草稿则恢复该草稿自己的角色与临时配置，两者不混淆。
- 后端提供当前配置项、可选值、默认值、可用性与禁用原因，前端用通用控件渲染。
- 选角色或切模型后重新取得有效配置；失效参数不静默沿用。前端不按品牌硬编码思考级别/权限。
- 临时修改只影响草稿/会话，不回写Profile；已有会话不跟随其他新草稿的角色选择变化。
- 权限选择是运行意图，后端负责校验和执行约束；UI不能绕过安全策略。
- Session 不绑定 Profile；当前阶段允许在同一 Harness 范围内主动切换 Profile，跨 Harness 切换暂不开放。
  对话历史跟 Session，原生记忆跟角色。切换须经后端确认，不能只改选择框就报告成功。

## 7. 未发送输入的持久恢复（已批准）

- 每项目一份新会话草稿，每个已有会话另有独立输入草稿。
- 保存文字、附件引用、所选角色与临时配置；切换项目/会话或重启应用不丢失、不串线。
- 草稿在本机持久保存，不进入正式聊天历史、不创建Session、不触发执行。
- 发送确认接受后，只清掉本次已发送版本；迟到回执不能清掉等待期间用户新输入的内容。
- 明确拒绝保留输入；结果未知先查状态或以同一幂等身份重试，不能重复创建/执行。
- 恢复时检查附件引用可用性；失效提示，不静默丢弃；发送前重新校验有效配置。

## 8. 常规会话交互默认规则（16项已全部批准）

用户整体批准以下产品规则。它们不等于本轮全部实施，也不授权自写高级Harness功能。
后端尚不支持的动作必须诚实隐藏或禁用，不在前端模仿成成功。

| 编号 | 问题 | 已定行为 |
| --- | --- | --- |
| 1 | 运行时输入 | 始终允许输入、保存草稿；编辑与执行状态分离 |
| 2 | 运行时发送 | 默认排队并显示待发送；仅后端支持时提供立即引导/停止后发送，不伪装为原生steering |
| 3 | 待发送队列 | 输入框上方显示，可撤回到草稿、删除、排序；由后端确认，不假排队；未实现时诚实禁用对应动作 |
| 4 | 停止 | 不等于撤销；先显示正在停止，后端确认后才已停止，保留已有输出和已发生操作 |
| 5 | 切换会话 | 切项目/会话不取消执行；侧栏显示运行/待确认/失败等状态，不要求用户理解Execution |
| 6 | 工具展示 | 对话内简洁卡片，详情展开；错误及待审批必须可见 |
| 7 | 审批 | 会话内卡片展示操作、目标、必要参数及批准/拒绝；授权范围由后端提供，不代批 |
| 8 | 差异化配置 | 按后端能力描述渲染，不写品牌分支或虚假的统一权限档位 |
| 9 | 整理会话 | 置顶、重命名、归档、搜索；归档非删除；永久删除独立确认，不顺带删除用户项目目录 |
| 10 | 重试/分支/回滚 | 重新执行、从此处分支、恢复检查点分开表达；仅真实后端支持时开放，不强造通用实现 |
| 11 | 失败/超时 | 拒绝保留草稿；未知显示正在确认，同请求身份查询/重试，不重复执行 |
| 12 | 断连/重开 | 展示本机历史/草稿，重连补齐事件；断连不直接等于执行失败 |
| 13 | 滚动 | 底部跟随输出；向上阅读不抢滚动，显示新内容/回到底部 |
| 14 | 文件/图片 | 附件预览/移除/发送前校验；路径遵循所属工作区，不能按Windows解释WSL路径 |
| 15 | 配置生效时点 | 显示有效配置；修改默认影响下一条消息，运行中可否修改由后端声明，不悄悄改变当前任务 |
| 16 | 未实现功能 | 不放假按钮、不报假成功；有必要告知时禁用并解释不可用原因 |

### Session与角色的边界

- Session是独立对话身份；Profile是当次选择，不是Session的所有者。
- 每次发送使用当次确认的角色及临时配置；已发生消息保留当时的角色归属，切换不改写历史。
- 原生实例是否重建、上下文如何续接、角色记忆如何换入由后端及Harness接入层负责。
  运行中切换的具体执行时点仍服从后端能力，不凭UI选择绕过运行保护。
- 角色记忆可积累，不等于静态配置被自动修改；前端仅呈现后端支持的查看/编辑/清空能力。
- Profile/Session与角色记忆的权威仍在本机，远端执行不改变归属。

## 10. 登录凭据与数据管理（已批准，实施范围由产品队列承接）

用户确认上一组两块均采用建议A，安装部分以§3最新决定为准。

- 本地使用不要求AgentBox账号；按接入能力提供官方登录/API Key/连接已有登录。
- 允许同一服务多个命名身份，由角色或Provider明确选择；发现已有登录须经用户确认，不自动接管或复制。
- 默认检查本地材料或官方身份接口；付费推理测试单独触发。
- 移除身份先显示受影响配置；不默认撤销账号或退出原CLI。
- 凭据权威归后端，必要系统保护由宿主能力提供；秘密不进入普通配置、日志和通用备份。
- 配置导出与应用数据备份分开；角色配置导出不含记忆和会话。
- 应用备份覆盖配置、会话、草稿、角色记忆和受管资源；排除凭据、项目文件、可重新下载的工具。
  备份含会话/记忆，仍属敏感数据；不宣称可恢复全部工作环境，换机可能需重新登录。
- 配置导入预览，默认新增副本，覆盖须明确选择，不按同名静默覆盖。
- 恢复等待任务结束或用户明确停止；先备份当前状态，不兼容版本拒绝。
- 本机定期备份，数量/空间有上限，展示成功时间与失败；云同步暂不做。
- 以上批准不代表今晚全部实施；具体一致性、格式、加密与现成依赖复用仍须在实施范围中明确。

## 11. Skills与MCP（已批准，前端与服务职责分开）

1. 设置内管理资源，角色内选择；不恢复旧Capabilities或新建侧栏市场。
2. 来源为本地目录、Git或已有兼容目录；不新造市场服务。
3. 共享资源库，角色显式选择；发现不等于所有角色自动启用。
4. 展示真实兼容性，包括脚本依赖、运行平台与权限；名字相同不代表可用。
5. 原生自动加载与手动选择按后端能力呈现，不发明统一执行语义。
6. 加载Skill内容不等于批准其脚本执行，审批仍遵循运行权限。
7. 会话临时变化只有后端支持才开放，不写回角色静态配置。
8. 添加MCP配置不自动启动；测试/使用时由后端按策略启动与管理。
9. 更新由用户触发；不覆盖运行中正在使用的资源版本。
10. 编辑上游资源默认建本地副本；用户自己管理的本地源按明确选择编辑。
11. 删除前展示引用角色，明确解除引用；不静默破坏现有配置。
12. 同名资源显示来源，不按同名覆盖。
13. 项目内发现的资源需信任与确认，不自动导入全局库或角色。

前端只管理选择、呈现与用户意图；解析、安装、启动与生效事实以正式服务合同为准。
复用先查已有调查与固定来源，在许可允许的边界抽取；没有证据的“大家都这样”不算实现依据。
