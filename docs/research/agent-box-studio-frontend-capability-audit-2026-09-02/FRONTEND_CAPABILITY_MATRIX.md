## tabs 隐含不变量（hidden invariants 汇总块）

见 [CURRENT_COMMAND_EVENT_MAP.md](./CURRENT_COMMAND_EVENT_MAP.md)「tabs CAS 协议」一节。核心：

1. `save_opened_tabs` 是 CAS：`expectedVersion` 必须是客户端见过的最后版本，被拒（另一客户端先提交）时无条件采纳服务器真相（tab-store.ts:2148-2177）。
2. `origin`（每窗口随机串）用于回显抑制：自己的广播只吸收为合并祖先，不重新应用（tab-store.ts:2312-2321）。
3. `tabs://changed` 只带 version+origin+tabs；版本严格 `<` 才应用（tab-store.ts:2322）。
4. hydrate 未完成时收到的远端广播进 `pendingRemote` 队列，hydrate finally 中重放（tab-store.ts:2323-2328, 2108-2112）。
5. 启动 `list_opened_tabs` 失败（401/离线）：只恢复本地 drafts，`tabsSnapshotLoaded` 保持 false，禁止不变量修剪/布局 blob 写入/把空集推上服务器（tab-store.ts:2051-2081）。
6. localStorage blob `workspace:tab-groups:v1` 存布局/分组/drafts/activeDraft，是设备本地记忆；后端 OpenedTab 序列是服务器权威；两者在 hydrate 后合并（mergeRestoredDrafts）。
7. tab 稳定性：`conv-{folderId}-{agentType}-{conversationId}`（tab-store.ts:405-411）——agent_type 进入 UI 身份。
8. Web 模式 HTTP command 受 WS-ready 门控（`waitForReady`，web-transport.ts:117-139）：避免 `acp_connect` 之类在断线窗口与 `receiver_count==0` 竞态。
