# Terminology

| Term | Meaning in this study | Not equivalent to |
|---|---|---|
| Remote registry/index | Discovery/search metadata or remote package source | canonical local content |
| Central local store | Cross-project machine-local content, copy, clone, CAS or SSOT | native discovery path |
| User-global directory | Harness-scanned per-user directory | central store in general |
| Project-local directory | Git/worktree-owned skill root | global installation |
| Vendored skill | Remote content copied into a project and then owned locally | live upstream link |
| Activation/selection | Decision to expose/use a discovered skill in a session | installation |
| Runtime projection | Mapping content/refs into a harness-native path or isolated home | content ownership |
| Synchronization | Copy/link/update relation between stores and targets | immutable resolution |
| Skill identity | Name, slug, package, URL or namespaced provider identity | revision/digest |
| Revision | Human/package/git version pointer | content digest |
| Digest | Hash of a defined file tree or artifact | semantic version |

The eight dimensions required by this research are source/store, global scope, project scope, vendoring, activation, projection, synchronization, and trust.
