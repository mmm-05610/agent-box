# BE-LOOP-001：后端协同研究与实施方案

状态：2026-09-21，I 根据用户逐项确认定稿；运行准备尚未验收，未启动执行者。
这是一套新授权的组织方案，不恢复历史编队，不使用 incremental-work-order。

## 目标与权限

Linux native 优先。稳定 Work Core；研究并收敛 Server、执行组合、Harness、
运行环境与资源插件的职责。研究先行、方案批准后实施，交付可追踪的源码检查点。
不能把架构候选、测试通过或源码合入提升为用户验收通过。

I 是唯一用户接口，决定产品取舍、扩权与最终验收。中央协调者 C 执行本方案，
管理四组任务、契约、资源、集成与 review；不得自行扩张产品目标。
禁止 push、修改 publishing main、改动历史树、清理用户数据或停止现有服务。
真实 Harness 模型调用、真实凭据使用不继承旧 C1 授权，需明确的本轮授权。

## 共同设计原则

- 上层表达策略，下层提供机制；同一事实只有一个权威，其他层保存有来源的投影。
- 实现不知道调用者的产品身份；通过必要契约而非具体实现理解下层。
- 超时、未知、确定拒绝和确定完成不可混淆；不得以重试掩盖未知派发。
- 请求、执行、资源的生命周期分离；能力缺失必须如实呈现。
- 优先复用现有代码与成熟外部实现，不建立平行注册、状态和调度体系。
- 每个保留机制给出必要性反例；不以机械地搬入插件作为边界正确的证明。
- 文档、实现、验证三种事实分开标注，外部研究固定来源与版本。

## S：Server 产品服务组

负责 HTTP/Wire 的既有产品行为、产品规范、会话/队列/配置等业务服务和多次执行编排。
先与 E 协商并逐块迁移单次执行的底层协调；接收方实现并验证后才能切换旧路径。
之后按 C 签发的板块任务持续设计、协商、实施、验证和更新规范；不自主堆功能。
不能定义原生 Harness、进程、沙箱语义；不得改公共 Wire 或内核契约。
规范区分草案/批准/实现，任务固定引用版本，不随聊天自动漂移。

## E：执行组合组

研究现有 runtime_composition 与 server/execution，允许探索内部结构，
不预设固定流水线，不新建第二个 Work Core。负责跨能力准备依赖、交接、
补偿、取消与清理协调，向 Core 提交事实、向 Server 提供可靠执行接口。
下层定义自己的能力、约束、资源释放操作及结果；E 不实现 bwrap 参数、
原生 ACP 行为、文件删除策略或另一套进程管理。上层业务策略留在 S。

方案必须列出保留/下沉/上移/复用 Core 四类职责，并经接收方确认。
审查必须包含下沉、下层替换、上层替换、删除和部分失败攻击。
批准标准是在明确场景范围内无未解决的有效重大边界反例，非全局最小性证明。
硬预留两次 Sol：方案定稿核验一次，实施验收一次；可申请追加。

## H：ACP / Harness 接入组

先研读官方 ACP 规范和 SDK、仓库真实接入链，以及代表性客户端和至少两类
Harness 接入实现。固定版本，区分稳定/可选/扩展能力及实际可用证据。
原生 ACP 优先直连，已有适配器优先复用，有必要才自建；不得擅自替换标准。
区分系统 ACP Client、适配器 ACP Agent 端点和额外对外 ACP 网关，
不预先批准把整个后端暴露为 ACP Agent。
尽可能忠实暴露标准、可选和命名空间扩展能力；暴露不代表获得执行权限。
文件/终端回调委托 E/P，用户审批交 S；不得绕过环境与授权边界。
允许插件内实质重构；越出插件和既有批准接入链必须经 C 协商。
先交规范地图、现状地图、复用对照、能力矩阵、方案与验证反例。
C 先审通过，才可选择分配 Sol 或直接批准实施。H 累计最多三次，不预留。

## P：运行环境与资源插件组

研究 Runtime、Sandbox、资源能力的现状与成熟可复用实现，设计后实施。
Runtime 负责进程操作，Sandbox 负责隔离保证，资源插件负责解析/准备/释放。
明确原始资源和投影、拥有和借用、部分失败与重复释放；不得误删用户资源，
不得静默从受限环境退化为裸跑，不得把秘密置于普通配置或日志。
允许调整插件拆分与组合，但先与 C 协商，再由 C 决定是否调用 Sol 后批准。
初期聚焦 local、bwrap、skills、git、artifacts、terminal-session；
Windows/WSL/旧 Web/Studio 不在本轮写入范围。没有自动兜底的“其他所有文件”。

## 写入边界与物理隔离

以下是路径清单生成规则，不是直接赋予整个目录写权限。
启动前 C 必须生成逐路径 allowlist，I 核对；未列出路径一律只读。

| 组 | 候选内部实现区域 |
| --- | --- |
| S | src/agent_box/server 的指定产品模块；排除 execution、bootstrap、公共协议 |
| E | extensions/runtime_composition 与 server/execution 的内部实现；公开契约排除 |
| H | plugins/agent-box-harnesses 内部实现；公共出口/契约单列 |
| P | 上述六个已列举插件的内部实现；公共出口/契约单列 |

公共区：work_core 冻结；resource_contracts、扩展公共 API、capability 定义、
组合协议、execution/protocols.py、bootstrap、Wire、storage、migrations、
根依赖与锁、共享测试配置、门禁、指令文件均由 C 管理，不向执行者开放。
公共接口变更要生产者/消费者确认；Core 语义、公开协议或产品扩权交 I。
各组新增测试与报告独立可写，现有测试逐文件分配；公共测试断言不可弱化。

每组独立 worktree，完整源码只读视图，白名单覆盖可写；单独临时目录和缓存。
不能挂载宿主完整 home、其他树、用户数据、Docker socket 或服务控制入口。
模型访问仅通过必要的专用认证通道，不向执行者提供 Codex 凭据。
共享 Git 管理目录不开放写权限；C 在沙箱外校验修改范围并生成提交。
C 的控制器及挂载/权限配置不对模型执行者可写。
启动前实测跨组写、公共文件写、符号链接绕行、Git 元数据写、预算改写被拒绝；
确认测试也只能访问隔离资源。不满足则不得用全权限模式绕过后宣称隔离成功。

## 接口与信息传递

正式状态唯一落在本轮专用记录目录，聊天只通知任务 ID、状态与记录位置。
每组只有自己的 outbox 可写，inbox/已批准契约只读；C 转录并发布，不共享可改账本。
消息包含 ID、组、任务、基线 SHA、契约版本、类型、摘要、证据路径、所需决定。
消息类型：CHECKPOINT、INTERFACE_REQUEST、REVIEW_REQUEST、BLOCKED、DONE。
C 按消息 ID 幂等处理并回 ACK，不能因重启重复派工或调用 reviewer。

接口变更单写清输入输出、状态权威、失败/重试/清理语义、兼容影响和反例。
双方确认，C 发布固定版本；等待接口时可做夹具和不依赖它的组内工作。
各组不可私下约定后绕开 C 更改批准契约。

## Review 预算

BE-LOOP-001 总预算十次，独立于前端十次；只有 C 的调用入口有权限。
E 两个指定里程碑各预留一次，八次机动；H 单组最多三次。
按风险与价值分配，不按先到先得、不平均分配、不因有余额强行消耗。
一次固定候选审阅调用扣一次，失败也扣；调用前持久化扣减，单实例锁，
恢复/跨日不重置，不能通过自动重试或更换任务 ID 绕过配额。
记录版本、原因、受益组、结果和使用量；共享审阅涉及 H 时计 H 次数。
保留的 E 名额不能被其他组消费；失败耗尽时不得把未完成核验标为通过，交 I 处理。
调用次数不是 token 硬上限。只用用户指定 Sol，实际模型标识需验证。

## 启动顺序

1. C 只做启动准备：核对 dev-0 与 Pi 修复分支 HEAD/dirty 状态，列明差量。
   默认从固定 dev-0 派生；已有 Pi 修复单列审查，不能悄悄变更共同基线。
2. 生成四组路径清单、沙箱配置、契约初始清单、预算账本和启动/停止/恢复入口。
   使用假执行者测试隔离、预算预留、重复消息、崩溃恢复和停止，无模型计费。
3. I 验收启动准备后，C 开启四组研究阶段；旧编队保持停止。
4. S/E 先对齐现有边界；H/P 并行研究，各组提交方案差量和具体反例。
5. C 先审方案，按预算分配 Sol；E 方案必须经过预留核验，才开放实施任务。
6. 按已批准的小任务实施。C 将组内检查点合入隔离候选，验证契约与跨组链路。
   每次集成发布精确 SHA、验证范围、已知缺陷和回退点，不触 publishing main。

## 持续循环与停止

组状态：RESEARCH → DESIGN_READY → CENTRAL_REVIEW → 可选 SOL_REVIEW →
APPROVED → IMPLEMENTING → CHECKPOINT_READY → INTEGRATION_VERIFY → DONE。
被驳回返回对应阶段；无批准任务则 IDLE，不自行扩大范围。
C 循环处理 outbox、依赖、审阅和检查点，使用事件唤醒或有退避的检查，
禁止持续模型空调用。稳定需求下无新增工作不是继续找事做的理由。
用户叫停时不发新任务，只安全停止本轮拥有的进程并保全修改与预算。
已批准任务全部完成时交付；外部阻塞时隔离该任务，推进其他已批准工作；
全部阻塞则落盘等待，不无限重试。最终验收依旧由 I 与用户完成。

中央维护一页状态：基线/集成 SHA、四组阶段、已批准契约、阻塞与所需决策、
验证结果、Sol 已用/预留/机动余额。启动报告必须含进程实况及 status/stop/resume 命令。
