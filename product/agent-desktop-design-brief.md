# Agent Desktop：设计循环目标与场景草案

状态：目标已获用户认可；下列场景与循环参数由 I 提议，待用户查看。
未启动循环、未安装外部框架、未任命新执行者。产品代码只读。

## 用户确认的方向

独立于特定后端、面向 Agent 使用的可扩展 Desktop。对话、工具调用、模型
配置均可以成为能力，但不预设为整个产品的组织中心。
Ordessa 后端可以提供最完整能力，不是所有接入的必需前提。
不预先把 Agent、会话、任务或插件宿主指定为核心答案。
通过场景、反例与删减实验寻找宿主最小机制与扩展领域能力的边界。

## I 提议的场景集

每个场景只规定用户结果，不提前规定内部对象或必须采用哪个 UI。

| ID | 场景 | 需要设计回答的问题 |
| --- | --- | --- |
| S01 | 接入简单 Agent，仅支持文本往返 | 没有 Profile、工作区、工具和恢复能力时能否使用？ |
| S02 | 通过 Ordessa 后端使用 Pi，观察工具与授权并持续交流 | 现有真实链如何映射，哪些能力由扩展承担？ |
| S03 | 启动长任务，离开其页面，稍后查看进度和产物 | 页面生命周期与远端执行生命周期如何区分？ |
| S04 | Agent 只提供任务提交、进度和结果，没有聊天协议 | 是否被迫伪造会话和 assistant 消息？ |
| S05 | 不启动 Agent，独立浏览配置、资源或 Git 变更 | 领域模块能否不依赖活跃会话/运行？ |
| S06 | 多服务同时接入，两个服务返回同名会话或任务 ID | 身份、授权范围、缓存和事件是否会串？ |
| S07 | 新模块为特殊产物提供视图，未安装时仍能查看基础信息 | 扩展选择、默认回退与未知内容如何处理？ |
| S08 | 一个资源模块与执行模块协作，后者可替换 | 怎样交换能力而不共享任意全局状态？ |
| S09 | 连接断开后操作结果未知，重连收到重复/乱序事件 | 谁确认事实、恢复状态、防重复执行？ |
| S10 | 扩展崩溃、关闭或卸载，远端任务仍在运行 | 谁释放订阅/资源，如何保留可解释的运行状态？ |
| S11 | 服务缺少取消、历史或恢复能力 | 如何如实表达不可用，而非伪造支持？ |
| S12 | 移除一个宣称可选的核心领域模块 | 宿主和其他独立模块是否还能工作？ |

S01/S02 为近期真实需求锚点；其余是扩展与故障检验场景，不代表今夜实施范围。
不要求任意第三方不可信代码热加载，不要求兼容所有协议或无限未来能力。

## 评判方式

先满足明确场景与不变式，再比较复杂度；不以文件少或自评分高判胜。
对每个候选列：核心概念、接口操作、状态权威、生命周期、扩展依赖、接入成本、
实现成本和不能覆盖的范围。不能用 execute(any)、万能 context/事件总线
隐藏接口与错误语义后宣布核心最小。

每个核心概念必须给一个“删掉它会失败”的具体场景；若移入扩展仍能满足
全部必需条件，就列作可移除候选。总复杂度包含核心、适配器与扩展作者负担。
允许保留多个不可简单排序的候选，不强行宣称存在唯一最简模型。

## 建议循环（未启动）

1. 首轮至少提出两个结构不同的候选，不以旧 mcode 方案为唯一出发点。
2. 设计者给类型/伪代码、所有权与逐步场景轨迹。
3. 攻击者给具体事件序列、被违反的不变式及最小反例；禁止只给风格意见。
4. 验证者判断成立/不成立/证据不足，必要时在隔离设计目录写小型模型测试。
   模型测试只能证明所建模型，不得冒充实际产品集成通过。
5. 设计者修订并回放所有成立反例；不得删除场景、偷偷降低要求或压制攻击。
6. 做删减攻击与新场景攻击，保存最佳候选、反例账和完整版本，不默认最后版最好。

可借鉴的方法：
- Self-Refine：https://github.com/madaan/self-refine （生成/反馈/修订）
- Reflexion：https://github.com/noahshinn/reflexion （失败反思记忆）
- evaluator–optimizer：https://www.anthropic.com/engineering/building-effective-agents
- 运行控制候选：https://github.com/Kiriketsuki/ralph-loop
以上阅读不代表已验证 Qoder 兼容、已安装或已授权其代码执行。

建议上限：12 轮或 6 小时，先到者停止；这只是预算上限，不需要凑满时间。
连续三轮没有新成立重大反例，且必需场景与删减检查通过，可提前交审。
三轮仅换措辞/重复争论无实质进展则交出争议，不无限循环。
目标冲突或产品取舍不明，记录交 I；其余独立问题可以继续。

角色尽量用独立上下文；同一模型不同角色不等于独立质量证明。
若 Qoder 无独立会话编排机制，先标注此限制，不假装已经启动独立审阅者。
实现调度器前需读本机 Qoder --help，验证真实可用的非交互/会话参数，不猜 CLI。
外部资料每条标实际读过的来源、版本与适用限制；未打开不作证据。
