## 1. 阶段 A — 旧表单字段 → 新归属 → 数据来源

| 旧表单字段（自由文本） | 新归属 | 数据来源 | 结论 |
| --- | --- | --- | --- |
| `displayName`（记录名） | 仍是文本输入 | 用户给记录起的名字，不是连接事实 | **保留输入**（不是 G1 指的关键项） |
| `harness`（手打） | **选择**：服务自身记录已声明的 harness 家族；另设“自定义 Harness（显式覆盖）” | **服务事实**：`providerModels.list` 记录的 `harness` 值 | **实现**（不再手打；空目录时走显式覆盖，首次安装不被卡死） |
| `provider`（手打） | **选择**：预设目录 + 目录里已在用的 provider id；另设“自定义供应商（显式覆盖）” | **客户端目录数据**（`provider-presets.ts`，只有 id/label）+ 服务记录里的 `provider` | **实现** |
| 模型 `modelId` / `displayName` | 输入 + **目录建议**（datalist） | 服务记录里同 provider 的 model id | **实现并如实说明**：模型名是服务校验的对象，wire 没有可勾选的模型目录（后端 55） |
| 凭据 | **只引用**：既有选择器列出本机记录（label 供选、id 供挂），只显示 present/absent | 本机记录（无材料） | **保留**（G2） |
| 端点 URL / 认证方式 / 协议风格 / 凭据环境变量名 | **不收集** | **锁定 wire 上不存在这些字段**（后端 55 的范围） | **不实现、不发明**：表单不为它们造自由文本，也不写 `configuration` 造的键 |
| 上下文窗口 / 能力开关 / 推理档 | **行内显示“未知”并写明来源缺失** | 无（后端 51/53/55） | **如实未知**（G3）；它同时是 composer 用量百分比等待的分母 |
| “拉取模型” / “测试连接” | **禁用按钮 + 原因文案** | 需要服务侧方法（后端 55） | **实现为禁用**，不假成功（G4） |

## 2. 参照决定（LibreChat modelSpecs / cc-switch）

| 参照做法 | 我们的决定 |
| --- | --- |
| LibreChat `modelSpecs` 的 name/label/能力开关/`maxContextTokens` | **形状学**：记录有显示名、模型行有元信息位；但**能力与窗口在 wire 无字段 → 显示未知**，不照搬其预填 |
| cc-switch 预设库很大、共享配置片段、排序分组 | **部分学**：预设作为**数据**可扩展（`PROVIDER_PRESETS`）；排序/分组**不引新件**（本仓既有 reorder 属于侧栏/P10 面，本单不做） |
| 「当前生效」+ 从 live 反填 | **学概念**：生效值来自 **我们的** `config.resolve`（既有事实源），**不读宿主配置文件** |
| 导入/导出、`ccswitch://` 深链 | **不做**：导入导出我们自己的记录属后续能力；深链是加分项，先不做 |
| **切换时直接写 live 配置文件** | **明示不学**（工单已定性为缺陷）：我们的物化按轮进行，见 G6 |
| 官方登录预设 + logout/login | 归 **P12/后端 56**（账号独立托管、按轮物化），本单不碰 |
