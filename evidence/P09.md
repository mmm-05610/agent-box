## 3. 阶段 C — 现在点亮的部分（含本轮修掉的两个真实缺陷）

点亮并锁定（用例为证）：
1. **消息流**：`agentBoxProjectionMessages` 把 `message.delta/final` 投影为 text part（既有用例保持）。
2. **工具失败行**：失败/拒绝的 `tool.update` → `{ error, result }` part，**且本轮新增 `isError: true`**。
3. **失败原因可见**：失败行的原因文本今天能真正渲染出来（见下“缺陷 2”修复）。
4. **状态尾**：运行中尾部显示进行中行（`aui_response-loading`），稳定后消失；`Shimmer` 用于其文案。
5. **pending 语义**：运行中只有最后一条 assistant 消息标 `pending`（其它不冒充）。

### 本轮修掉的两个真实缺陷（P09 点亮过程中发现）

- **缺陷 1（假成功）**：AgentBox 的失败工具调用**没有 `isError`**，于是同一 part 在共享工具行里被渲染成
  **成功的活动行**（正常标题、无错误字形），服务端失败文本完全不可见——正是总方针禁止的“不报错冒充成功”。
  修复：`features/chat/agentbox-chat-view.tsx` 对 `failed`/`denied` 的 part 置 `isError: true`。
  证据：`agentbox-process-view.test.tsx` 断言失败行带 `aria-label="Error"` 字形；投影用例断言 `isError: true`。
- **缺陷 2（失败原因被吞）**：共享工具行里 `view.subtitle` **从不作为可见文本渲染**（它只喂 tooltip 与冗余判断），
  而 error 分支的 `detailSections` 在“summary 与 subtitle 相同”时把 summary 丢弃 → 只有一行错误的失败
  （无输出流可展开）会渲染成“Ran command”+红图标而**永远不说明原因**。
  修复：`components/assistant-ui/tool/fallback.tsx` 不再丢弃与 subtitle 相同的 summary；
  `agentbox-chat-view.tsx` 把 `summary` 与 `resultExcerpt` 合并为 error 文本（服务原文，未改写）。
  证据：`agentbox-process-view.test.tsx` 展开失败行后读到 `exit 1` 与 `bash: no such file`。
