# P04 Electron 宿主边界证据

## 切片 1：main-only wire transport 与诚实 unavailable（2026-09-14）

本切片完成了不依赖后端启动合同的宿主工作：renderer 只提交已验证的 wire 信封；Electron
重建并约束 `/wire/v1/{method}` 目标，未来由 main-process 私有 lifecycle closure 注入 endpoint
与 session token。token 只在 HTTP dispatcher 内成为 Bearer header，不进入 preload 类型、renderer、
URL、响应或日志。

生产当前注册 `unavailableAgentBoxWireDispatcher`。这是刻意的正常状态：具体 artifact/data-root/
动态端口/readiness/token ACL/退出期限尚未锁定，故不猜 spawn 参数，也不回落 `hermes:api`。

```text
apps/desktop/electron/
├── main.ts                              ◀ 仅注册 agentbox:wire:request；无函数声明
├── preload.ts                           ◀ 独立 window.agentBoxDesktop.wire 窄桥
├── ipc/
│   └── workcore-wire-ipc.ts             ◀ 校验 method/path/envelope 一致性；不接 endpoint/header
├── security/
│   └── agentbox-wire-transport.ts       ◀ URL policy + main-only Bearer + timeout/错误边界
├── workcore/
│   ├── lifecycle.ts                     = 六动词基础设施合同；仍不含凭据/Session/Execution
│   └── slot.ts                          = 未安装生产 lifecycle，不制造实现
└── legacy-hermes/                       = 本切片零 import、零 fallback；待后续逐消费者退役

apps/desktop/src/
├── global.d.ts                          ◀ 只暴露 request；无 token/endpoint/header
└── api/agentbox-runtime-client.ts       ◀ 已有生产 client 消费该桥；缺桥即 UNAVAILABLE
```

验证：Electron 2 files / 5 tests passed；三项目 typecheck；改动文件 ESLint 0/0。测试覆盖空连接
不发送、主进程附加 Bearer、401 typed envelope 原样交客户端、危险 endpoint 拒绝、renderer 自选
path/信封不一致在 dispatcher 前拒绝。

阶段仍为 `P04_PARTIAL`：真实 lifecycle、事件订阅桥、优雅退出和默认 Hermes 启动控制流退役待续；
这些不能用测试替身或硬编码 8732 冒充完成。

## 切片 2：不透明事件订阅 IPC seam（2026-09-14）

本切片把未来 lifecycle 所拥有的事件源接到 renderer 的唯一窄桥，但没有虚构 Server 事件地址或
协议。Electron IPC 只广播 `unknown`；preload 同样不把主进程输入冒充已验证合同。renderer 在
进入 reducer 前以 `EventFrameSchema` 校验，非法帧静默丢弃；合法帧复用既有幂等/序列缺口
reducer，发现 gap 时触发服务历史补水。卸载 route surface 会注销 renderer listener，Electron
注册函数也向未来 composition owner 返回源订阅 cleanup。

```text
apps/desktop/
├── electron/
│   ├── ipc/workcore-wire-ipc.ts        ◀ 注入式 opaque source；只向存活窗口广播并返回 cleanup
│   └── preload.ts                       ◀ onEvent(callback) 窄桥；返回 removeListener
└── src/
    ├── global.d.ts                      ◀ frame 保持 unknown，禁止跨信任边界伪造类型保证
    └── app/composition/wiring/
        └── agentbox-main-chat.ts        ◀ schema 校验后入 reducer；gap 才请求 history resync
```

验证：定向 3 files / 18 tests passed；三项目 typecheck 通过；改动文件 ESLint 与
`git diff --check` 在提交前通过。测试覆盖 source 广播、已销毁窗口过滤、source cleanup、非法帧
拒绝、合法帧摄入与 route 卸载退订。

阶段仍为 `P04_PARTIAL`：生产 `subscribeWireEvents` 尚未由真实 Server lifecycle 提供，且默认
Hermes 启动控制流尚未退役。本切片不把缺少生产事件源标为 GREEN，也不以测试 source 作为默认。

## 切片 3：WorkCore 基础设施 supervisor（2026-09-14）

本切片在既有六动词 `WorkCoreLifecycle` 前增加无品牌 supervisor。它只协调
resolve → launch → readiness → shutdown；具体 artifact、启动参数、readiness pattern 与期限全部由
未来 composition 注入。`resolve=null` 是正常 unavailable，且没有 Hermes 或任何其他 fallback。

```text
apps/desktop/electron/workcore/
├── lifecycle.ts                 = 六动词基础设施合同；未扩入产品领域
├── slot.ts                      = 单一 lifecycle 安装位；生产仍未填充
└── supervisor.ts                ◀ 单飞启动、诊断状态、owned-process 幂等回收与竞态门
    ├── ready                    → 必带 opaque connection handle
    ├── unavailable/failed       → 不制造连接、不自动无限重试
    └── shutdown                 → 只回收本次 launch 所拥有的 process
```

Luna 定向验证：WorkCore 2 files / 13 tests passed；Electron typecheck、受影响文件 ESLint、
Prettier 与 `git diff --check` 均通过。覆盖并发 start 单飞、ready handle 复用、null resolve、
launch/readiness/plan 失败、readiness 失败回收、失败不自重试、shutdown 幂等，以及 shutdown 与
延迟 launch/readiness 的竞态；cleanup 失败不覆盖首要 readiness 诊断。

阶段仍为 `P04_PARTIAL`：后端尚未给 Desktop 可锁定的 artifact 解析、动态端口公告/readiness 与
owner 发现合同，因此本切片不猜固定端口或 Server 命令，也不安装 production lifecycle。下一切片
先退役 AgentBox 产品的旧 Hermes 自动启动，再将已锁定的 host connection/event source 接入此 seam。

## 切片 4：renderer Hermes 自动连接退役（2026-09-14）

AgentBox 产品 composition 现在显式以 `legacyGatewayAutostart: false` 安装既有 gateway hook。
禁用分支在读取 `window.hermesDesktop` 之前返回：不 `getConnection`、不创建 HermesGateway、不注册
backend-exit/boot-progress/reconnect/power/online 监听。它只关闭 renderer 内可能由热更新遗留的旧
socket/cache、结束旧 Session loading 并完成旧 boot overlay；`$gatewayState` 不会被伪造为 open，
AgentBox 服务是否可用仍由 `$agentBoxService` 独立呈现。

```text
apps/desktop/src/
├── app/composition/wiring/features.tsx

└── features/runtime/gateway/hooks/use-gateway-boot.ts
    ├── false → 清旧 renderer transport + 结束旧 overlay；零 Hermes bridge 读取
    └── true  → 保留尚有测试/显式消费者的 legacy 实现；不再是产品默认
```

## 切片 5：Electron primary-window Hermes 冷启动退役（2026-09-14）

## 切片 6：按 Session/cursor 所有权隔离的事件 IPC（2026-09-14）

事件桥由进程级广播收紧为 renderer 发起的 Session/cursor 订阅。preload 生成仅用于 IPC 所有权的
subscriptionId；该 id 不进入 Server transport。main 以 `webContents.id + subscriptionId` 持有源
cleanup，只把不透明帧回送发起者；无效输入、源同步失败、sender 销毁、重复退订与坏 cleanup 都不会
泄漏订阅或打断其余 teardown。

renderer 先完成 history hydration，取得非空 `resumeCursor` 后才订阅。每帧 cursor 更新不重建
WebSocket；发现 seq gap 时先停旧源，再补水并从新 cursor 重订阅。旧 Session、非法 frame、卸载后
迟到 hydration 均不能进入当前投影。同步源在返回 cleanup 前报告 gap 的竞态也会补偿释放真实源。

```text
apps/desktop/
├── electron/ipc/workcore-wire-ipc.ts             ◀ sender-owned subscription map；opaque frame relay
├── electron/preload.ts                            ◀ subscribeEvents({sessionId,cursor}) 窄桥
└── src/
    ├── global.d.ts                                ◀ renderer 不见 endpoint/token/subscription owner
    └── app/composition/wiring/agentbox-main-chat.ts
        ├── hydrate → resumeCursor → subscribe
        └── gap → unsubscribe → hydrate → resubscribe
```

Luna 定向验证：Electron IPC 1 file / 4 tests、AgentBox chat 1 file / 8 tests passed；desktop 三项目
typecheck、ESLint（0 error，仅既有 formatting warnings）及 `git diff --check` 通过。

## 切片 7：main-only WebSocket event transport（2026-09-14）

新增 `/wire/v1/event-stream` 生产传输实现：每次订阅从 lifecycle connection closure 读取最新
loopback endpoint/token，HTTP(S) 映射为 WS(S)，Session/cursor 只作编码后的 query；Bearer 只进入
upgrade header，不进 URL、frame、错误或日志。它只解析 JSON 为 `unknown`，不解释 EventFrame，
不重连、不发送自造控制帧；renderer 继续持有 schema/replay/resync 语义。

```text
apps/desktop/electron/security/
├── agentbox-wire-transport.ts                    = 既有 main-only HTTP request transport
└── agentbox-wire-event-transport.ts              ◀ main-only WS event transport；动态 connection closure
    ├── connection null/unsafe/factory failure    → honest unavailable；零 Hermes fallback
    └── cleanup                                   → remove message/error listeners + idempotent close
```

Luna 定向验证：Electron 1 file / 11 tests passed；Electron typecheck、ESLint、Prettier 与
`git diff --check` 通过。覆盖连接轮换、IPv4/IPv6 loopback、URL/header、opaque JSON、非法/迟到消息、
安全错误与幂等 cleanup。

阶段仍为 `P04_PARTIAL`：transport 与 IPC 均已具备，下一步由唯一 main/composition 写入者把它们接到
空的 AgentBox connection slot。后端尚未锁定 Desktop artifact、动态端口/readiness/owner 启动合同，
因此 production slot 仍必须诚实为空；不以固定 8732、测试替身或 Hermes gateway 填充。
