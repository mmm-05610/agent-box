### 3.1 B10 — 失败面板的 legacy 网关设置（**会启动 Hermes**）

链路：`BootFailureOverlay`（本地失败分支）→「Gateway settings」→ `GatewaySettingsView` →
`ConnectionsRegistrySection` →「Test connection」→ `window.hermesDesktop.connections.test`
→ main `ipcMain.handle('hermes:connections:test')`（`electron/ipc/connection-ipc.ts:414`）
→ `entry.kind === 'local'` → **`await startHermes()`**（`connection-ipc.ts:456`）。
`hermes:connections:*` **不在** `hermes:api` 硬门覆盖范围内。

### 3.2 B11 — 状态栏 legacy 连接/网关切换器

### 3.3 B12 — 四个 legacy 数据面视图与入口

### 3.5 第二轮（Windows 原应用验收查出）：连接遮罩与渲染端 legacy 请求

首次 Windows 驱动 18 PASS / 2 FAIL，证据定位到两个真实缺陷：

**(a) 全屏 CONNECTING 遮罩常年覆盖产品壳（P06 硬性阻断项）**
`GatewayConnectingOverlay` 的 `connecting` 在**首帧**成立（`boot.progress < 100`、无 error、
`gatewayState !== 'open'`），随即 `shownRef` 锁存，只有 `gatewayState === 'open'` 才退出——
产品运行期永不发生。实测 25s 后仍为 100% 视口 `[data-glass-opaque]`（`z-(--connecting)`）。
修复：新增**必填** `authority`，agentbox 下渲染 `null`（`gateway-connecting-overlay.tsx:52,131`），
产品组合传 `'agentbox'`。**证据**：`gateway-connecting-overlay.test.tsx` 正反两例（同一首帧状态：
hermes 覆盖 1 个 `[data-glass-opaque]`，agentbox 0 个）；驱动 `no-blocking-overlay` 覆盖率 100% → **0%**。
该状态正是 P02A 当时记为 PENDING 的「healthy 探针被 boot 连接遮罩挡住」——旧假设（把它当沙箱
现象）失效，本轮按产品语义关闭。

**(b) 渲染端仍向 main 发 legacy REST 请求**
驱动的主进程日志显示启动后无导航即出现 `hermes:api` 拒绝 33 行，经临时诊断补丁定位到两条路径：
`GET /api/config`（约每 2s，13 次/25s）与 `GET /api/profiles`（1 次 + 2 重试）。
修复：渲染端唯一入口 `requestHermesApi` 增加权威门（`src/api/legacy-rest.ts`，
`src/api/client.ts`），产品组合根 `applyProductRuntimePolicy()`（`src/app/composition/product-runtime.ts`，
在 `features.tsx` import 期应用）。门控前的 main 侧行为完全一致（`legacyApiAllowed=false` 已拒绝一切
`hermes:api`），故不可能破坏任何今天可用的流程；差别只是请求不再离开渲染进程，且残留调用者
按路径各记录一次（不静默）。
**证据**：`legacy-rest.test.ts`（4）、`product-runtime.test.ts`（3）、驱动
`no-legacy-rest-reached-main`：main 侧拒绝 **0** 行。

## 14.1 三个缺口（暂停原因）与修复

`docs/desktop-product-delivery/status.md` 的接管声明逐条列出；此处是证据侧的对应关系。

### 14.1.1 Appearance 曾是活动 legacy config 路径

`#/settings?tab=appearance` 的「重开上次聊天」与「终端字体」两行经
`useHermesConfigRecord()` / `saveHermesConfig()` 读写 `GET|PUT /api/config`。
`P06.md` §10.1 与 §12.3 曾把它登记为「已知残余」，**归类不准**：它是本端可达的 legacy
控制流，且是**产品面决定**（给页面 authority 或退役该页），不是外围合同缺口。

修复（`apps/desktop/src/features/settings/**`、`wiring/features.tsx`、`types.ts`）：

- `SettingsView` 与 `AppearanceSettings` 取得**必填** `authority: 'agentbox' | 'hermes'`
  （与 `CommandCenterView` / `GatewayConnectingOverlay` / `useDesktopIntegrations` 同一风格），
  生产组合根显式传 `'agentbox'`，**不**从 gateway 状态、缓存或错误推断。
- **组件拆分而非条件 hook**：agentbox 分支根本不构造 Hermes-config 组件
  （`LocalResumeLastSessionSetting` / `LocalTerminalFontSetting` 对
  `HermesResumeLastSessionSetting` / `TerminalFontSetting`），所以「零 legacy 调用」是
  **字面事实**，不是「请求恰好被门拒绝」。测试特意保持 renderer REST 门**打开**再断言 0 次调用。
- Appearance 仍是正式产品页：主题、模式、缩放、通知、快捷键、语言等中立能力一行未减。

### 14.1.2 语言静默不持久化（写失败伪装成功）

`hermesLocalePreference.save()` 在门关时提前返回——切换语言「看起来成功」，重启即丢且不报错。
这违反「写失败必须诚实呈现」。

修复（`src/application/desktop-preferences/**`、`src/main.tsx`）：

- 新增中立的本地 `LocalePreferencePort`（`desktopLocalePreference`，key
  `hermes-desktop-locale-v1`），`main.tsx` 注入它，不再注入 `hermesLocalePreference`
  （后者**保留**给明确 Hermes authority，未改其内部）。
- 写入走 `writeVerifiedPreference`：**写后 read-back 校验**，值没落地就 throw
  （`lib/storage` 的 best-effort 写在此不适用——它无法证明任何事）。
- 失败经由既有 i18n 契约呈现：provider 回滚 locale 并让 `LanguageSwitcher` 弹
  `notifyError`，**不再**把「没有 bridge」说成失败，也**不再**把失败说成成功。

### 14.1.3 bundled Bot Mode 仍默认启用（退役项）

master-plan §4 已把 Bots 群聊/原 Agents 管理入口列为退役项，但 `hermes-bots`
（`shared.ts` 的 `ID = 'hermes-bots'`）无 `defaultEnabled` ⇒ 默认 `true`，发现后
`publishPlugin` 出可启用句柄并 `activate()`，于是 relay、face clock、hide sweep、
group-chat sync、@mention completions、Routines pane、chat-empty、调色板 `New Bot…`、
composer mention middleware 全部运行。

修复（`src/extension/contrib/**`、`app-composition.tsx`）：

- `discoverBundledPlugins(authority)` 取得**必填** product authority，调用方显式传
  `DESKTOP_PRODUCT_RUNTIME`；策略是纯函数 `bundledPluginRetired(id, authority)`
  （`bundled-plugin-policy.ts`，退役集合只有 `hermes-bots`）。
- 退役在**发现/激活边界**执行，位置在 `publishPlugin`（含 activate/deactivate 句柄）与
  `pluginActive` **之前**：agentbox 下该 id 既无 record 也无句柄，`setPluginEnabled` 无处可调，
  用户历史持久化的 `enabled: true` 根本不进入判定；register() 不运行，因此它启动的一切都不存在。
- **磁盘门同策**（主执行者集成时补的洞，子代理报告后判定）：原 shadow 规则只在
  `$pluginRecords[id].kind === 'bundled'` 时生效；产品不再发布 bundled 记录后，
  用户机器上历史独立安装的 `desktop-plugins/hermes-bots/plugin.js` 会经磁盘门复活该面。
  现在 `loadRuntimePlugin` 的必填 `authority` 也走同一策略，拒绝注册并在 Settings 里留下
  文件名带路径的 `hermes-bots:retired` 禁用行（可删除，不是静默忽略）。
- 其它 bundled 插件（`accent`/`kanban`/`radio`）与 disk/runtime 门行为不变；
  没有「agentbox 下禁用所有插件」的机械规则，也没有用调色板黑名单掩盖已激活插件。

### 14.1.4 「重开上次聊天」与终端字体改为 Desktop 本地偏好

两者都不再依赖服务配置（也不再写 `display.resume_last_session`）：

- `hermes-desktop-resume-last-session-v1`，共享 `$resumeLastSession` atom，**默认 true**；
  组合根 import 期同步 hydrate，`ContribWiring` 与 Appearance 开关读同一权威
  （`resolveProductResumeLastSession()` 改为委托该权威，仍是确定 boolean，绝不 `undefined`）。
- `hermes-desktop-terminal-font-family-v1`，hydrate 进既有 `$terminalFontFamily`
  （终端 `use-terminal-font.ts` 直接消费 ⇒ 实时生效），空值 = 内置默认。
- 两条路径均为 **persist-then-publish**：写没落地就不改 atom，失败弹通知，绝不显示「下次启动不会有」的值。
