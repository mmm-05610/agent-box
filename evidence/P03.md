# P03 工作记录 — 中立用例、状态与客户端边界

## 纵切 1（2026-09-14）— 首发/续发幂等身份与未知结果

`sendAgentBoxMessage` 只表达两个 core 业务意图：Workspace 草稿首次发送使用
`sessions.createAndSend`，既有 Session 使用 `sessions.send`。首次成功只采纳服务返回的
`SessionRecord`，前端不预造 Session 身份。明确 `rejected_before_accept` 才释放本次 pending；
传输失败属于 unknown，立即以同一 `requestId` 调用 `sendOutcome.query`，不能改成新 send。

pending identity 使用本机版本化 envelope 持久化。再次触发同一草稿版本只查询原请求；若用户在
unknown 期间已经编辑出新版本，也必须先解决旧请求，不能覆盖 pending 或越过去发送新请求。
返回值携带被解决的 `intentKey`，使上层 CAS 只清对应版本，不会把迟到的旧 accepted 当成新草稿
已接受。损坏或未知 envelope 版本安全降级为空，不扫描或导入用户数据。

```text
apps/desktop/src/
├── application/session/wire-send.ts              ◀ create/continue/query 单一幂等用例
├── store/agentbox-send-intents.ts                 ◀ v1 pending envelope；请求身份跨重试保留
├── store/agentbox-service.ts                      ◀ accepted Session 服务投影
├── api/wire-v1-client.ts                          = validate → host transport → validate
└── types/wire/wire-v1.ts                          = core send/query 合同，无自造 HTTP
```

行为门：`wire-send`、core fixture、service capability 共 3 files / 17 tests passed；修改文件 ESLint
0 error / 0 warning；renderer/electron/e2e 三项目 typecheck 通过。反例覆盖 socket 在 dispatch 后
关闭、连续 unknown、用户在 unknown 期间编辑新草稿、明确拒绝和 accepted Session 采纳。

边界：本纵切尚未接入 Composer 生产调用者；在 P04 宿主 transport 到位前保持服务 unavailable，
不回落旧 gateway。下一纵切实现 server-owned queue、停止状态与历史/事件投影，再由同一个
application hook 接入 P02 Composer。

## 纵切 2（2026-09-14）— 服务队列、停止、审批与历史事件

队列读取只接受 `queue.get` 的完整返回投影；撤回带 item version，只有 `withdrawn` 才移除，
`too_late` 则采纳服务返回的新记录。没有本机删除、排序或自动 drain。停止先显示 requesting，
`stop_requested` 后才投影 stopping；`unconfirmed` 保留原 execution running 事实并单独记录原因，
不把传输不确定写成 stopped。审批的 recorded 回应也不乐观移除卡片，等待 `approval.settled` 事件。

事件 reducer 新增工具状态投影，同时继续按稳定 eventId 去重、按 Session seq 检测缺口。历史恢复
从当前 cursor 请求 snapshot；cursor 过期只允许一次无 cursor 的干净 resync，第二次仍要求 resync
就保持明确 `needsResync`，不拼接或制造历史。空 snapshot 也能只推进 resume cursor。

```text
apps/desktop/src/
├── application/session/
│   ├── wire-session-control.ts                    ◀ queue/stop/approval/history 用例协调
│   ├── wire-session-projection.ts                 ◀ message/tool/execution/approval 纯 replay
│   └── wire-reconnect-plan.ts                     = snapshot + event stream 恢复计划
├── store/agentbox-runtime.ts                      ◀ Session/queue/stop 服务投影，无业务执行
├── api/wire-v1-client.ts                          = 唯一中立 RPC 客户端
└── types/wire/wire-v1.ts                          = core wire 方法与 EventFrame
```

## 纵切 3（2026-09-14）— Composer 权威切换与生产发送用例

Composer 现在显式接收 `runtimeAuthority`。AgentBox 模式仍复用同一个输入、草稿和控件实现，但
busy follow-up 直接进入 application `sessions.send` 边界：不调用 Hermes steer、不执行 Hermes
slash 命令、不写 renderer 本地队列，也不触发旧 clarify/MCP 跳过控制流。输入可用性由上层
AgentBox 服务事实决定，不再读取 `$gatewayState`。Hermes 模式保持原行为，避免尚未迁移的辅助
窗口被隐式改义。

每次 AgentBox dispatch 把银行化后的 `draftVersion` 传给 application caller；caller 以其字符串
作为 durable `intentKey`。只有回应确实接受同一版本时返回 `acceptedForDraft=true`；若正在解决
旧 unknown 请求，即使旧请求最终 accepted，也不能清当前新草稿。busy send 返回 queue id 时，只
异步刷新服务 `queue.get` 投影；刷新失败不反写“发送未接受”。

附件边界只把已有 `refText` 投影成 wire `AttachmentRef`。`path`、preview/data URL 和本机字节从不
序列化；未 stage、仍 uploading/error 或空引用会在 transport 前拒绝，最终工作区归属仍由 Server
检查。

```text
├── application/session/
│   ├── agentbox-composer.ts                      ◀ create/continue、附件投影与 accepted-for-version
│   ├── wire-send.ts                              = durable requestId + unknown query

├── store/composer.ts                             = 版本化草稿与配置上下文

```
