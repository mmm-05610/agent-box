## 2. 阶段 B/C — 本轮改动

新增：
- `features/chat/sidebar/agentbox-sessions/agentbox-actions-row.tsx` — 产品侧栏动作区（新建任务 + 搜索，均为既有路径）。
- `features/chat/sidebar/agentbox-sessions/agentbox-session-status.ts` — 纯函数：由「服务投影 + 服务记录 + 本机游标」推出 `{running, unread}`；归档行一律不标。
- `store/agentbox-session-unread.ts` — 本机已读游标（内存态，文件头写明“不是服务事实”）。
- 测试：`agentbox-session-status.test.ts`（4）、`agentbox-actions-row.test.tsx`（3）、`store/agentbox-session-unread.test.ts`（3）、行内标记 3 例、集成 2 例。

修改：
- `agentbox-session-row.tsx` — 行首字形支持 running；新增 unread 点（带 `aria-label`，文案含“this window”）。
- `agentbox-session-list.tsx` / `agentbox-global-sessions.tsx` — 逐行计算状态、打开行时写本机游标；不新增任何 wire 调用。
- `chat-sidebar.tsx` — 在 nav 之下挂载动作区，**仅 agentbox authority**。
- i18n：`sidebar.agentBoxActions.{newTask,search}` 与 `sidebar.agentBoxSession.{running,unreadLocal}` ×6 语言 + types。

**过程中修掉自己的一个缺陷**：动作区最初挂在 `showSessionSections` 之下——该标志由 **legacy 会话 store** 计算，
于是“只有服务会话”的产品状态会把动作区藏起来（恰是它存在的那种状态）。已改为仅按 authority 挂载，
并在集成用例里用只含服务会话的种子锁定。

## 3.1 顺带修掉：三个 store 边界守卫在 Windows 上**空转**

宽面回归首轮发现 `src/store/{profile-store-purity,session-store-purity,store-boundaries}.test.ts`
共 15 例失败。A/B 复核（把本轮新增的 store 文件移出 Windows 树后重跑）确认**与本轮改动无关**：
三个守卫用 `relative()` 生成模块 id，Windows 下得到 `store\x.ts` 反斜杠写法，而钉住的账本用正斜杠，
于是模块图**恒为空**——「抓到违规」的反向对照正是为此存在的。已修：三个文件统一走
`srcRelative()`（`relative(...).replaceAll('\\','/')`），SELF 一并归一。
修复后 3 files / 34 tests 全通过，且反向对照真实生效（不是放宽阈值）。
本项属 P10 写集内的 `store/**` 测试质量修复，不属于「删测试/降阈值」。

- **自动化段（cron）**：不挂载（其数据面是 legacy `/api/cron`，产品下被硬门拒绝）→ 等 wire cron 能力。
- **插件市场**：无后端面，不做。
- **未读的持久化**：本单是内存游标（窗口内可见性）；跨重启的已读状态需要产品决定（本地持久化 or wire 能力），不擅自扩。
- **profile 分组的 legacy 数据**：产品 authority 下仍取不到 gateway groups（既有事实），本单未改其门控。
- Windows 原应用截图验收不在本单门内（P10 未要求）；体验命令见最终报告。
