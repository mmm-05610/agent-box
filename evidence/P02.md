## slice 3（2026-09-14 接力收口）

失败态真机驱动（`e2e/boot-nonblocking-p02a-driver.mjs`，新增未提交）暴露并驱动了两处**产品缺陷修复**：

1. `src/components/onboarding/index.tsx`：首启向导在**就绪检查未决**（`configured === null`，
   后端不可用时的常态）仍然全屏遮罩，把可用壳挡死。改为：只有**确认“确实需要引导”**
   （`manual || (enabled && configured === false)`）才渲染；未决即不渲染，壳照常可用。
2. `src/components/boot-failure-overlay.tsx`：抑制条件从“onboarding flow 非 idle”收紧为
   “onboarding 真的拥有屏幕且 flow 正在跑”。该条件与 `DesktopOnboardingOverlay` 共用
   `doesDesktopOnboardingOwnScreen(state, enabled)`，自动首启还必须有打开的网关；内部流程状态
   不能替一个实际未渲染的全屏面取得所有权。
3. `src/store/boot.ts`：修复第二个真机首因。`failDesktopBoot()` 已锁定失败后，迟到的
   `running:true/error:null` 主进程进度曾保留 error 却把 running 复活，形成“失败且运行中”的
   不可能状态并隐藏恢复面板。现在通用无错误进度不能复活失败周期；显式重试和成功仍分别通过
   `resumeDesktopBootForRetry()` / `completeDesktopBoot()` 转移。

## B2（2026-09-14）— 按 Workspace/Session 隔离的版本化草稿

草稿存储从全局 `__new__` / 仅文本 v3 提升为本机 v4 envelope。已有 Session 继续使用稳定 lineage
key；尚未创建 Session 的草稿使用 `workspace:<stable workspace id>`，因此本地项目和 WSL 项目、
不同项目之间不会串线。WSL 主行及搜索命中现在与本地项目一样进入空白草稿，但只传递稳定选择
ID：其 Linux 路径不会进入遗留本地主机 `config.get`，环境解析留给 P03/P05 的中立客户端。

每次保存生成单调版本。发送前同步保存本次 payload；accepted 只 compare-and-clear 当时版本，
rejected 也只在没有较新本机编辑时恢复。用户在请求未决期间继续输入或添加附件时，迟到结果不
能删除或覆盖新意图。v4 持久化文本与附件引用，明确去掉 data URL 预览和瞬时上传状态；首次写入
会消费并删除旧 `hermes:composer-drafts:v3` 文本字典，避免升级丢草稿。

## C1（2026-09-14）— Composer 角色与动态临时配置

输入框旁新增受控 Profile 选择器：角色名为主标签，`harness` 仅作为服务返回的不透明小徽标；
界面不存在一级 Harness 选择器，也不按 `codex`/`claude` 等品牌值分派逻辑。新草稿点击角色只把
选择写入本机草稿并读取 `config.describe`，不会调用 `sessions.createAndSend`、创建 Session 或启动
Harness。Workspace 另存最近确认角色；真正的新草稿只继承该角色，不继承上一草稿的临时覆盖。

已有 Session 仅在中立投影中找到服务端记录时开放选择，同 Harness 约束按两个不透明字段是否相等
计算。点击后选择框继续显示旧值，直至 `sessions.switchProfile` 返回 `confirmed`；`rejected` 携带的
旧 Session 重新进入权威投影，不把未确认点击伪装成成功。跨 Harness 和缺服务记录均明确禁用。

`enum`、`string`、`boolean`、`model_slot` 四种有限控件完全由 `ConfigDescriptor` 渲染；
`securityLockedIds` 和 `editable=false` 始终不可编辑，临时时值只进入草稿，不回写 Profile。选角后
重新取描述，先选请求迟到时由当前草稿 Profile 校验丢弃，不覆盖后选意图。
