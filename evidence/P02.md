# P02 工作记录 — 上层产品（从 A 段开始）

## A 段施工前盘点（2026-09-14，P02A 第一刀=启动壳与服务可用性分离）

### 启动门现状（产品决定 §1/§3 的改造对象）

- 组合层挂载：`src/app/composition/wiring/features.tsx`
  - `:1120` `DesktopInstallOverlay`（非辅助窗口时挂载）——首启 bootstrap 进度/失败
    全屏面；active 时显示合理，**bootstrap 完成失败（state.error）后常驻全屏 = 要退役的
    产品门**。
  - `:1149` `BootFailureOverlay`——硬失败恢复面，`visible = boot.error && !boot.running`
    全屏劫持；其注释自证：无它时壳渲染为 "gateway offline"、无 composer、仅 toast。
  - `:1122` `DesktopOnboardingOverlay`（gatewayState==='open' 时启用）——网关就绪后的
    首启配置流，与"无服务也能用"不冲突，本轮不动。
- 状态机：`src/store/boot.ts` `$desktopBoot`（error/running/progress/visible；
  failDesktopBoot 终态、迟到 progress 不得冲掉既有 error——保护逻辑保留）。
- e2e 现有锚点：`e2e/boot-failure.spec.ts`（HERMES_DESKTOP_BOOT_FAKE_ERROR 注入 →
  `waitForBootFailure`）；`e2e/boot.spec.ts`（mock backend 正常启动）。
  改造后 spec 更新为"失败状态诚实可见 + 壳可交互"，不删覆盖。

### A 段第一刀目标（可验行为）

1. bootstrap 失败/无后端时：主壳 + 侧栏 + 设置照常渲染可交互（composer 等服务依赖
   操作按既有离线路径诚实禁用/隐藏）。
2. 失败面改为**非阻塞**：可关闭的失败状态面板（重试/修复/网关设置动作保留，日志可达），
   关闭后状态栏仍诚实呈现服务不可用。
3. DesktopInstallOverlay 仅在 active bootstrap 期间出现；完成后失败不再常驻安装门
   （安装/更新入口归设置——设置侧入口在 D 段接上，先保证不阻塞）。
4. 行为测试（jsdom 组件级）+ e2e spec 更新 + 真实 Electron 截图（无 Harness 场景）。
