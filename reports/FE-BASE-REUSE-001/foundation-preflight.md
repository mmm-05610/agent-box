# 基础扩展实施前对比审计

2026-09-22；基线 desktop-minimal / 4405fb9986；本轮由用户直接批准实施。

## 对比结论

| 面 | 当前 | 本轮 | 为何属于这一层 |
|---|---|---|---|
| 宿主 | 知道 Page、全局页面表、内置 Shell | 仅一个根界面、生命周期、作用域 | 根挂载是 Desktop 渲染所需，不认识布局/业务 |
| 界面 | 单页面自动导航 | 独立 workbench：五区域、整页、UI 插槽 | 布局可替换，无需修改宿主 |
| 操作 | 按钮直接选页 | commands 服务，入口引用命令 | 将来快捷键/命令面板复用它，不新增核心机制 |
| 设置 | 无 | settings 扩展＋绑定式条目 | 展示与数据权威分离，配置/凭据不归此包 |
| 归属 | 宿主自动收页面 | 服务提供 scope-bound 注册接口 | 跨扩展贡献也必须跟调用者退出，不能只清提供者 |
| 契约 | 仅示例独立 Token | 独立 foundation-contracts 工件 | 消费者不依赖实现包 |

## 审计修正与短期压力测试

1. 不向 PluginContext 加 commands/views/settings 等领域字段；通过 Token 服务获取。
2. 注册服务以 forScope(context.resources) 得到只能新增自身贡献的入口；返回释放句柄，自动加入调用方作用域。关闭作用域后的注册拒绝。服务不暴露全局清空/删除接口。
3. 区域/整页、命令项/状态组件、设置字段/自定义区块用判别联合，不靠堆布尔参数表达。
4. 会话列表、对话、执行详情、日志分别消费区域；设置/扩展管理消费整页。工具渲染器由业务服务自己扩展，不新增核心插槽。
5. 快捷键、命令面板、通知、配置持久化可作为服务扩展；拖拽/多实例/布局存储属于 workbench 演进，不属于宿主。
6. 整页隐藏原工作台而不卸载；普通区域切换允许卸载，业务数据由服务持有。背景 inert，返回恢复焦点；独立边界防止坏视图破坏返回入口。
7. 设置订阅可能先于读取返回、读取可能乱序，必须以代际令牌忽略陈旧结果；保存失败不报成功，明确重新读取确认，卸载解除订阅。
8. 根挂载冲突拒绝后者，不替换现有根；无根或坏根显示诊断。默认装配名单来自文件而不是业务 import。

## 稳定性判定

足以作为短期基础：上述已知业务路径不要求新增宿主能力。不能保证未来无需修改：原生网络/文件权限桥、进程隔离、跨版本兼容、可取消激活均未建设；不能靠通用接口掩盖这些缺口。
本轮将宿主 API 升为 2（去掉 pages 是破坏性修改），旧 manifest 明确拒绝，迁移全部仓内示例。不伪称 v1 兼容。

## 界面方向与范围

桌面开发工具，目标是辨认工作区与设置层级。沿用紧凑工具布局，不做营销装饰。
色彩：画布 #f5f7fa，面板 #ffffff，文字 #243247，次级 #64748b，分隔 #dbe2ea，焦点 #315fa8。
字体：系统 sans 标题/正文，monospace 用于诊断 ID；布局以细分隔线、留白和清晰焦点表达区域，不给空区域堆演示卡片。
特色仅为整页返回工作区时保留现场。测试样例不默认启用，无业务数据和真实连接。

验收：类型/构建、生命周期反例、异步设置反例、React 交互、Electron 文件加载/工作台/设置往返与截图。不得把工程通过等同用户验收。
