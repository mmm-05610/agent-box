# Best Candidate (R004 revised, A) — Namespaced resource/event core with explicit cursors, per-namespace action typing, and spawned-resource grants; envelope payload registry, invoke_id, and implicit-live-default removed as non-load-bearing.

## R4.1 Core bet
The host core is a **namespaced directory of resources**, each `(namespace_id, local_id)` plus a seq-ordered replayable event stream plus an adapter-owned open capability map. Host authority is identity, namespace isolation, subscription routing, and per-resource ordering only. "Agent", "session", "chat" are adapter-declared resource **kinds**, never host types. Capability names are adapter-chosen strings with **zero host-defined meaning and zero host behavioural authority**. Under the delete-and-show-a-failing-scenario test this round reduces further than R003: the envelope `payload_schema_id` descriptor store, the `invoke_id` correlation token, and the implicit live-only subscribe default are removed; no required scenario fails without them, and the surviving set is the minimal core that satisfies S01–S12.

## R4.2 Core concepts and operations
**Namespace.** `namespaces.open(descriptor) → NamespaceHandle{ns_id}`; `namespace.teardown(reason)`. `ns_id` host-minted per connect, never service-supplied; reconnect yields a new `ns_id`. Teardown disposes its resources and force-closes every handle subscribed to them. `resource_id = (ns_id, local_id)`; raw-id collision structurally impossible.

**Resource.** `namespace.announce({local_id, kind:string, capabilities:CapMap})` (adapter-origin, host verifies in-namespace uniqueness); `namespace.retire(local_id, reason)`; `directory.list(ns_id, filter{kind?})`; `directory.lookup(ns_id, local_id) → descriptor | ExplicitAbsent`. Content authority = producing adapter; identity/lifecycle = host.

**Event stream.** `subscribe(resource_id, from_cursor:int) → Subscription{close(), onNext(Envelope)}`. **`from_cursor` is mandatory (R004, FE-CE-011):** `from_cursor=cursor.resolve(resource_id)` begins live; `from_cursor=0` replays from first envelope in order. `Envelope{resource_id, seq:int, ts, kind:string, payload_schema_id:string, payload:opaque}`. **`payload_schema_id` is an opaque routing/selection label (R004, FE-CE-008): the host neither registers, gates, nor interprets it — it forwards every envelope.** `seq` host-assigned monotonic per resource. `cursor.resolve(resource_id) → current_seq`. Release: `Subscription.close()`, handle-scope destruction, or namespace teardown.

**Open capability map.** `capabilities.get(resource_id) → CapMap{name→{supported|not_supported|unknown}}`. Host defines no valid names, assigns no behavioural authority, never branches on a CapMap value in routing/replay/lifecycle. Absence of a name = "unknown", never "unsupported".

**ns-scoped action-type declaration (replaces the payload registry).** Action shapes are declared **at registration inside the adapter's own namespace**: `action.register(kind, action_type, params_type:ActionSchema, result_type:ActionSchema)`, keyed by `(ns_id, kind, action_type)`. No `execute(any)`: params/results are concrete declared schemas. Two namespaces using the same `kind`/`action_type`/type name never share a mutable key because the registry is per-namespace (this is the surviving FE-CE-006 isolation — now structural via namespace-local registration, not a gate on a shared payload map).

**Typed action.** `action.invoke(resource_id, action_type, params:ActionSchema) → Result | CapabilityAbsent(action_type) | OutcomeUnknown`. **`OutcomeUnknown` carries no token (R004, FE-CE-010):** the host applies the fixed invariant *an invoke whose outcome is unknown is never auto-resubmitted*; the caller correlates by the synchronous return and decides a fresh re-invoke; adapters that want idempotent auto-retry implement it themselves. `CapabilityAbsent` is returned only when the action is not registered for the resource's kind.

**Result.spawned_resource_id (spawned-resource grant; kept).** `result_type` MAY declare optional `spawned_resource_id:(ns_id, local_id)`. When populated, the host adds it to the invoking handle's accessible set. `SubscriberScope{primary_id:(ns_id,local_id), spawned:set<(ns_id,local_id)>, subscriptionHandle, typedInvoker}`; accessible = `{primary}∪spawned`. Host rejects a spawned id whose `ns_id ≠ primary.ns`. This is not sibling enumeration, not `directory.list`, not cross-namespace access. Retained against the FE-CE-009 same-ns reduction (see §R4.8): the set bounds subscription to host-observed Result ids — the provenance bound that FE-CE-004/005/007 closure rests on.

**Resource-scoped handle.** `handle_for(ns_id, local_id) → SubscriberScope{primary, spawned:∅, ...}`; mints exactly one primary; exposes no `parent`/`sibling`/`enumerateNamespace`/`directory.list`-on-namespace; `directory`/`subscribe`/`invoke` are scope-checked against `{primary}∪spawned`.

## R4.3 Boundary rules
A service adapter: (1) `namespaces.open`; (2) `announce/retire` kind + open CapMap; (3) seq-ordered pump (host assigns seq); (4) `action.register(kind, action_type, params, result)` under its own namespace; (5) explicit `not_supported` CapMap entries for absent features. "No cancel" = `CapMap{"cancel":not_supported}` (informational) AND omit `"cancel"` from the kind's action registry (structural) → `invoke(...,"cancel") → CapabilityAbsent`. `ExplicitAbsent`, `CapabilityAbsent`, `ScopeDenied`, `NamespaceGone`, `OutcomeUnknown` are distinct non-null terminals; absence never inferred from null/timeout. The adapter sees only its own namespace; no adapter-side API names or resolves another namespace's resource.

## R4.4 Extension mechanism
An extension registers a view resolver `{match: kind + payload_schema_id string, component, optional typed action bindings}`; selection exact/most-specific-first; **default fallback** = host-builtin generic view rendering resource kind, registered action names + typed param schemas, CapMap name→state pairs, the last envelope's `payload_schema_id` label (not its content), and *"No dedicated view installed; structured data available via subscription."* Unknown content is never blank and never given a run/agent reading; an unregistered `payload_schema_id` lands in the same fallback (§R4.2). A view receives only host-minted `SubscriberScope` handles. **Pair gesture:** user points at two on-screen resources; host mints `h_A=handle_for(ns_A,a)` and `h_B=handle_for(ns_B,b)` with `from_cursor=cursor.resolve(id)` (explicit live, §R4.2) and hands both over. Core records **nothing** about the pairing. View may render, subscribe via each handle's `{primary}∪spawned`, and invoke registered actions on `{primary}∪spawned`; it may **not** enumerate namespaces, derive a foreign id from a handle, register free-form event names, or hold a global context. Guarantees: resolver absent → generic view; throws → error boundary keeps delivering on still-mounted handles; unmounted mid-operation → host force-closes that view's handles incl. spawned; re-subscription uses explicit `from_cursor=cursor.resolve(id)`.

## R4.5 Scenario trajectories (owner + per-core-step deletion consequence)
**S01 text-only.** 1. `namespaces.open→ns` (host). 2. `announce{kind:"text.stream",CapMap{…cancel:not_supported}}` (adapter). 3. `h=handle_for(ns,text.stream)`; `h.typedInvoker("send",{text})` (extension→host). 4. adapter emits seq 1..n TextDelta; host routes (adapter/host). 5. resolver renders (extension). Delete typed-action → step3 has no typed call (only `execute(any)` = disqualifier) → fails; delete ordered-stream → step4 deltas never arrive → fails; delete namespaces → S01 still works (single service, bare id) → not load-bearing here (fails S06); delete CapMap → S01 still works → not load-bearing here (fails S11). **covered** (core).

**S02 Pi via Ordessa.** 1. `namespaces.open` (host). 2. `announce` kinds `pi.conversation/pi.tool-event/pi.approval` (adapter). 3. view `subscribe(from_cursor=cursor.resolve(id))` → live tool/approval events (host routing). 4. `invoke(approval,"approve",…)`, `invoke(conversation,"send",…)` (typed-action). 5. resolver renders (extension). Delete resource announce/lifecycle → step2 no addressable resource; delete ordered-stream → step3 tools/approvals not watchable; delete typed-action → step4 approve/send undefined, cannot "keep conversing". **covered** (adaptation+extension).

**S03 long task, leave/return.** 1. `subscribe(id, from_cursor=0)` for full history (extension+host). 2. navigate away → `Subscription.close()` (host). 3. remote keeps emitting; adapter keeps announce+envelopes (adapter). 4. return → `directory.lookup` then `subscribe(from_cursor=cursor.resolve(id))`; host replays missed seq in order (host). 5. passive snapshot `invoke("read")→current value` (host+adapter). Delete ordered-replayable-stream → step4 no catch-up; delete resource-directory → step4 lookup impossible; delete typed-action → step5 snapshot path gone. **covered**.

**S04 submit/progress/result, no chat.** 1. `namespaces.open`; `announce{kind:"acme.job"}`; register `submit` (result_type declares `spawned_resource_id`) + `result` (adapter/host). 2. view renders sections from JobProgress/JobResult envelopes (extension). 3. no session/turn/role in any envelope (host+adapter). Delete resource lifecycle → step1 no job to observe; delete typed-action → step1 submit/result undefined; delete ordered-stream → step2 progress never delivered; host-session-object already removed → S04 still passes (confirms it is dead weight). **covered** (core).

**S05 browse config/git, no session.** 1. `announce{kind:"config.tree",CapMap{read:supported}}` (adapter). 2. `directory.list(ns,{kind})` (host). 3. `invoke("read")→snapshot` or live stream (extension+host). Delete resource-directory → step2 fails; delete typed-action → step3 read fails. **covered**.

**S06 two services, same id.** 1. `namespaces.open→ns_A, ns_B` (host, host-minted). 2. both announce `job-1`; keys `(ns_A,job-1)`, `(ns_B,job-1)` distinct (host). 3. Alpha's handle carries ns_A scope; directory/subscribe/invoke scope-checked; ns_B unreachable (host). 4. grant bound to ns → `ScopeDenied` (host). 5. Alpha and Beta each declare an action type "Config" **within their own namespace**; the action registry is per-`(ns,kind,action_type)` so neither constrains the other (host). Envelope `payload_schema_id="Image"` is now an opaque label — no shared descriptor key exists at all (R004). 6. only a user pair presents a second-ns handle. Delete namespaces → step2 collides; delete scope-check → step3-4 leak; delete per-namespace action registry → step5 shares a mutable key → FE-CE-006 reopens. **covered** (core).

**S07 special artefact, view not installed.** `announce{kind:"acme.plot"}`; no resolver matches → generic view renders kind+actions+CapMap+last `payload_schema_id` label + "no dedicated view installed". Delete generic-fallback-view → unknown artefact renders blank. Unregistered `payload_schema_id` lands here identically (gate removed §R4.2). **covered** (core).

**S08 resource + replaceable runner.** 1. ns_R `announce{kind:"runner"}`, register `execute` with result_type declaring `spawned_resource_id` (adapter). 2. ns_D `announce{kind:"data.ref"}` (adapter). 3. `h_D=handle_for(ns_D,ref)` (host). 4. user pair → host mints **independent** `h_R=handle_for(ns_R,runner)` and subscribes it with **`from_cursor=cursor.resolve(id)`** (explicit live, §R4.2/§R4.4); core stores no relationship (user+host). 5. `h_D` receives a **new live** ArtifactReady (not replayed); view calls `h_R.typedInvoker("execute",{ref})` (extension→adapter). 6. Result.spawned_resource_id `(ns_R,job)` → host adds to h_R accessible set → `h_R.subscriptionHandle.subscribe((ns_R,job), from_cursor=cursor.resolve(id))`; progress rendered (host+extension). 7. replace runner: `namespace.teardown` → `h_R.typedInvoker → NamespaceGone`; `h_D` unaffected; user re-pairs to `h_R′`. Delete spawned-resource-grant → step6 job unobservable (FE-CE-004 reopens); delete explicit-cursor pair-mint → step5 replays stale events and auto-executes (FE-CE-005 reopens); delete typed-action → step5 no typed execute; delete namespaces/NamespaceGone → step7 silent mis-bind. **covered** (extension owns cooperation; core permits via two ns-local handles + spawned grant + explicit live cursor).

**S09 drop / unknown outcome / dup-out-of-order.** 1. invoke sent, link drops pre-ack → host returns `OutcomeUnknown` (no token) (host). 2. reconnect: adapter replays; host dedups/reorders by `(ns,resource,seq)`; `cursor.resolve` yields resume (host). 3. fixed never-auto-resubmit invariant → host surfaces `OutcomeUnknown` for explicit user retry; user re-invokes fresh; adapter-owned apply-idempotency prevents double execution. Delete ordered-stream dedup/reorder → step2 duplicates reach view; delete typed-action/invoke → step1 no call to reason about. **partial** — double-execution prevention is host+adapter joint, never pure-host. Not to be marked covered.

**S10 extension crash while remote runs.** 1. coordinating view throws/unmounts → host force-closes **its** handles h_D, h_R incl. spawned (host). 2. ns_D/ns_R remain authoritative (adapters). 3. new view re-subscribes `from_cursor=cursor.resolve(id)` (extension+host). 4. no core pair record → nothing to lose. Delete handle force-close → subscriptions leak, dead view receives, running state unexplainable → fails at 1; delete cursor.resolve/replayable-stream → step3 can't catch up. **covered** (core).

**S11 no cancel/history/resume.** `announce{CapMap{"cancel":not_supported,"history":not_supported,"resume":not_supported}}` (adapter, informational); `invoke(...,"cancel") → CapabilityAbsent` because "cancel" is absent from the kind's action registry (host). Delete open-capability-map → history/resume absence can only be inferred from null/timeout → fake-support disqualifier → fails. A fixed capability enum reopens FE-CE-002, so the open string map is the minimal form. **covered** (core).

**S12 remove an "optional" core domain module.** 1. remove optional adapter → its `namespace.teardown`; other namespaces unaffected (host). 2. remove optional resolver → generic fallback (host). 3. remove paired coordinating view → other single-resource modules untouched (core recorded no pair). Delete namespaces/teardown isolation → step1 teardown touches shared key-space → fails; delete generic-fallback → step2 removed-resolver resource blanks. **covered** (adaptation for adapter removal; core for isolation).

## R4.6 Deletion / reduction experiments
Removed with a passing trajectory: envelope payload descriptor store (FE-CE-008; S06/S07 pass without it), invoke_id (FE-CE-010; S09 dedups ns,resource,seq), implicit live-default (FE-CE-011; pair-mint passes explicit current cursor). Previously removed and still confirmed dead: envelope delivery-gate, typed replay_policy, host-session-object, host-turn/role field, host-event-store, host-resource-directory-B, cross-namespace-edge, persistent-pair-record. Retained because a scenario fails: namespaces (S06), resource-directory (S05), ordered-replayable-stream (S03/S09/S10/S01/S02/S04), open capability map (S11), typed-action (S01/S04/S08/S05), generic-fallback-view (S07/S12), per-namespace action typing (S06/FE-CE-006), spawned-resource-grant (S08/FE-CE-004).

## R4.7 Second-service onboarding cost
(1) `namespaces.open`; (2) `announce/retire` kind + open CapMap; (3) seq-ordered pump; (4) `action.register(kind, action_type, params, result)` under its own namespace (no replay_policy, no envelope payload registration, no invoke_id); (5) declare `spawned_resource_id` in a result schema if the action spawns; (6) explicit `not_supported` CapMap entries. Every `subscribe` passes an explicit `from_cursor` (`cursor.resolve(id)` for live, `0` for full replay). View-only module: one `{match:kind+schema, component}` resolver. Coordinating view: user-pair gesture + handle `spawned_resource_id`. No cross-namespace concept, no knowledge that a CapMap string or an envelope label changes host behaviour (it never does).

## R4.8 Honest cost and non-goals
Weakest: **S09 partial** (host+adapter joint double-execution); S08 cooperation needs a user gesture, not a standing link; transient text as a resource is heavier than a pure broker. **Open, unadjudicated (FE-CE-009):** the spawned-set bounds subscription to host-observed Result ids (a provenance bound); the attack's same-ns subscription rule passes S08 too and is smaller, differing only on same-ns guessed siblings that no S01–S12 result exercises — deferred to a scenario-authority round, not silently relaxed. **D11 growth (deferred):** spawned-set growth within a view lifetime is bounded only by force-close-on-unmount; per-view growth remains an open observation. Non-goals: no cross-namespace joins/edges, no content search, no host turn/role/session model, no host capability vocabulary, no automatic re-pairing, no host-verified apply-idempotency.

## R4.9 Candidate B — demoted, carried open alternative only as history
B (typed-reference graph, persistent cross-namespace edges, host-mediated relay) was demoted in §R003.B.2: its signature primitive has **no failing scenario** (S08 passes on A's ns-local handles + spawned grant), and FE-CE-007 remains a **live, unrepaired isolation break** — the carrier was withdrawn, not the invariant fixed. B is not promoted unless a future required scenario forces standing automatic relay without user initiation; none of S01–S12 does. The two candidates are not genuinely incomparable: A strictly dominates on total cost and on the isolation invariant, so B is retained only as evidence, not blended in.
