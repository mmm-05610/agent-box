# R001 attacker report — dimension D12-authority-boundary

I attacked only D12: does each candidate smuggle a service / model / harness / plugin-host / **conversation / session / run** assumption into the *core* and present it as neutral plumbing? I did not touch ordering (D01), identity (D03), absent-capability UX (D04), fallback rendering quality (D05), adapter burden (D06), extension burden (D07), reduction (D08), dual-truth (D09), cross-module channels (D10), long-run (D11), or lifecycle leaks (D02) — where those surface below I name them and explicitly leave them out of the ledger. The counterexample ledger was empty at round start, so there are no OPEN/DISPUTED rows to replay. Two counterexamples land on Candidate A; Candidate B holds this round (the attempts are recorded).

## FE-CE-001 (major, Candidate A): A's core has no "value" primitive — passive content can only be represented as a conversation-shaped message log

**Event sequence (S05 origin, S03 return-later failure).** A service exposes a *snapshot* — a git diff of the working tree. (1) Adapter `namespaces.open` (host). (2) Adapter `announce{kind:"git.diff"}` (adapter). (3) The view asks for the current diff. Here is the leak: A's core exposes **no** operation that returns a resource's content as a *current value*. `directory.lookup` returns only the `{id, kind, CapSet}` *descriptor* (§A.2); the content exists **only** as envelopes on `stream.subscribe` (§A.2). (4) So the adapter must emit the diff as envelope `seq=1` (adapter). (5) The working tree changes; adapter emits `seq=2` = the new diff (adapter). (6) User leaves the page and returns; the resolver re-subscribes with `from_cursor` and the host replays `seq=1` then `seq=2` in order (§A.2 cursor + §A.5-S03 step 4). (7) A seq log carries **no** "superseded / invalidated" state — ordering *is* the only content-truth the host guarantees (§A.1 "per-resource event ordering"). The returning page therefore sees the old diff (`seq=1`) presented inside the live timeline with no core marker that it was replaced.

**Invariant broken.** A.1: "the host owns only directory, subscription, namespacing and event delivery; 'agent', 'session' and 'chat' are resource kinds declared by adapters, never host types," and "a resource has its own identity and lifecycle independent of any view or conversation." The plan's neutrality test: "Any step that materialises an assistant message, a session object, or a workspace to satisfy the core is a major counterexample." A cannot materialise a *passive value* without materialising it as an **append-only, seq-ordered, cursor-resumable message log** — which is precisely the assistant-message/conversation stream shape. The core's *definition* of "observable thing" (identity + replayable event stream) imports the conversation-log shape and then forces it onto S05's non-conversation data and S03's return-later reading.

**Minimal version.** Give the core a `snapshot`/`read-value(resource_id) → current content` op with an `invalidate` signal instead of per-item seq replay. With that, a `git.diff` resource exposes its current value; S05 browses it and S03's return-later pulls the *current* diff — no message-log machinery, no stale-as-live. Remove that value op (back to stream-as-sole-content, as A is written) and the leak returns. So "content is representable only as a seq log" is the smuggle, and it is *not* required by S04, S05 or S11 (each of which A claims to satisfy on other grounds). Contrast with B, where the same S03 return pulls a *current* adapter buffer, not a host-replayed log — confirming the defect is A's core event-plane choice, not a shared fact.

**User-visible consequence.** On S03 (return later for progress and artefacts) applied to a browsable passive resource: the user is shown a superseded diff/tree as part of the current timeline with no "replaced" marker, i.e. silent loss of truth. On S05: "browse config without a session/run" is satisfied *only* by modelling the config file as a live, resumable event stream — the run/message shape the brief's S04 was written to forbid, smuggled into the core's sole content primitive.

## FE-CE-002 (minor, Candidate A): the core fixes a session-recovery capability vocabulary and renders it agent-shaped

**Event sequence.** (1) Adapter `announce{kind:"config.tree"}`. (2) No resolver installed → the host-builtin generic view renders it (§A.4): "kind, capability set, declared actions and a **last-envelope summary**." (3) A's core `CapSet` is a fixed tagged union `cancel/history/resume` (§A.2) — the exact recovery features of an interactive agent session. (4) So a read-only config item is presented by the *core* with a cancel/resume capability strip and an invoked-latest-output affordance — a live invokable agent.

**Invariant broken.** Same A.1 claim: the host has **no** content authority and ships no interpretation of a resource. Yet the core `generic-fallback-view` (declared core in §A.9) *interprets* a resource as "thing-with-outputs-you-can-invoke-and-resume," and `capability-declaration` (core) *names* a session-run recovery taxonomy instead of treating capability names as opaque adapter strings. That is a run/agent reading baked into the core while the core is billed as neutral plumbing.

**Minimal version.** Make `CapSet` an open map `{capability_name:string → {supported|not_supported|unknown}}` with adapter-chosen names, and have the fallback render the raw payload schema plus an "install a view for details" line. The agent-strip disappears; S07 (unknown content not blank) still holds — so the run-shaped rendering is not required, it is smuggled. Non-blocking (config is still browsable), hence **minor**.

## Candidate B — D12 taken up, held

I wrote the two settle-scenarios against B's declared ops and could not smuggle a conversation/session/run object into its core. **S04**: `job.submit.request` + `job.progress.stream` + `job.result.request` are three typed ports with **no** message type shaped like a chat turn (§B.5-S04) — no core concept materialises a session/assistant. **S11**: absence is structural (no `*.cancel.request` port to bind) and the explanatory layer is an *adapter-declared* port whose `msg_type` B leaves concrete but unnamed by the core (§B.2, §B.3), so unlike A, B's core fixes **no** capability vocabulary. I also tested the "plugin-host smuggled into core as neutral" angle on `builtin-default-view-provider`: it *is* in B's core, but B names the impurity openly ("a mild materialisation B would rather not carry," §B.4) instead of dressing it as neutral broker plumbing, so it is an *admitted* core concept for the verifier to weigh, not a *smuggle-as-neutral* — the S07 default-render responsibility is genuinely required of the always-present component, and penalising it would soften S07. The residual event-plane cost in B is *relocated to adapters* (admitted, §B.8) — that is a D06/D01 finding, which I deliberately do not file here. Result: no D12 counterexample against B; it is the cleaner candidate on the literal authority-boundary test this round.
