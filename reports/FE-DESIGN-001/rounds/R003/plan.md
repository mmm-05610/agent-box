**Candidate A — core bet.** The host core is a namespaced directory of resources, each an addressable `(ns_id, local_id)` plus a seq-ordered replayable stream plus an adapter-owned open capability map, with authority limited to identity, namespace isolation, subscription routing and per-resource ordering. **Candidate B — core bet.** The host core is a typed reference graph with persistent, host-stored cross-namespace edges and a relay path, so cooperation survives view lifecycle without a re-pair gesture. **Strongest objection:** FE-CE-007 shows `edges.list` leaks foreign-namespace ids to a scoped handle, defeating isolation, and the existing cross-namespace-edge deletion result already shows S08 passes without any core edge mechanism — so B's signature primitive may be both a security defect and non-load-bearing. **Settling evidence:** either a B revision that removes the foreign-id leak in `edges.list` while keeping standing relay, or a demonstration that S08 genuinely requires the core edge (which A's R.5-S08 trajectory currently contradicts).
