# R006 Integration Report (A lineage) — closing D01-order-dedup

Three major counterexamples hold against the saved candidate this round: FE-CE-012 (host dedup key `(ns,resource,seq)` is vacuous because `seq` is host-assigned monotonic-per-resource, so no two envelopes for a resource can collide), FE-CE-013 (the boundary rule tells the adapter to dedup by the host-assigned `seq`, which the pump interface never returns to it — unimplementable, or a core-internal leak), and FE-CE-014 (the host "reordering" by its own arrival-order `seq` is identity, so S09's out-of-order premise has no core correction). The verifier confirmed all three. None is softened below: I state the exact edit that makes each sequence impossible, where it lands, and I replay the whole ledger.

**FE-CE-012 — the change that makes it impossible.** Delete the claim, not paper over it. The candidate asserted a core dedup capability the data model structurally forbids. The correct resolution is to test the claim's necessity: if the host dedup is removed, does any S01–S12 trajectory fail? It does not — the adapter can (and per the scenario, "events arrive duplicated") dedup with its own protocol-level stable id. So host dedup is non-load-bearing. The revised candidate (§R6.2, §R6.5-S09) removes "host dedups/reorders by `(ns,resource,seq)`" entirely; the host `seq` is re-described honestly as a **monotonic stream index assigned in pump-arrival order**, used only for cursor resume and per-resource delivery ordering, never as a dedup predicate. With the vacuous predicate no longer asserted, FE-CE-012's sequence cannot be constructed against the candidate.

**FE-CE-013 — the change.** The boundary rule's dedup key referenced a value the adapter cannot observe. §R6.3 item 7 / §R6.7 item 7 are rewritten so the adapter dedups and orders by **its own stable event id** (the key it already holds from its protocol), and pumps events in remote-stable logical order; the host-assigned `seq` is explicitly excluded from the adapter's dedup key. The pump interface stays return-free, so no core-internal leaks into the adapter contract. The instruction becomes implementable, closing FE-CE-013.

**FE-CE-014 — the change.** Withdraw the word "reorders" from the core's S09 vocabulary. Out-of-order correction is adapter-primary (§R6.3 item 3: adapter pumps in remote-stable order). The core contributes only: (a) the fixed never-auto-resubmit invariant, (b) `cursor.resolve` as a resume point, (c) monotonic per-resource ordering of what it actually received — i.e. the host will not itself scramble the order it was given. S09's user outcome is still met, but by the adapter with the core supplying structural, non-inert guarantees. FE-CE-014's identity "reorder" is gone, so its sequence is impossible.

**FE-CE-009 — CLOSED by a run experiment, not prose.** The R006 Model2 experiment encoded two models and ran S08 steps 4–6 plus a same-ns sibling probe through both: Model2 (same-namespace subscription scope, no accumulated set) passed S08 and preserved S06 isolation, while Model1's spawned set only restricted same-ns sibling access that no S01–S12 trajectory exercises. That is the necessity argument the R006 directive demanded (safety is not necessity; this is necessity). The spawned set is removed from the core; the invariant text is unchanged ("extensions cannot derive foreign ns ids from their own handle"), now enforced structurally by `resource.ns_id == handle.ns_id`.

**S09 coverage.** With the above, S09 owner is restated truthfully as **adaptation-primary, core structural**: named owner per step, per-part deletion consequence, never "later." This also resolves the directive's `without_an_owner=1` row — S09 was the ownerless-but-feasible row; it now has a named owner. S09 moves from `partial` to `covered` (honest joint attribution, not a fake core guarantee).

**FE-CE-001 re-played (not assumed).** Directive surface 1 asked whether static config/git read is forced to invent cursor/subscribe/replay. T-Static (§R6.6) shows a current value obtained by `invoke("read")→Result` with no subscription, cursor or stream; the rejected FE-CE-001 conclusion stands against the R006 bytes.
