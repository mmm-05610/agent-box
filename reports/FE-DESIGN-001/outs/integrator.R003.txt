# Best Candidate (R003 revised) — Namespaced resource/event core; payload-descriptor store, invoke_id, implicit-default-subscribe and spawned-set removed under D08 minimality; same-ns subscription scope as the cooperation-access primitive

## R.1 Core bet

The host core is a **namespaced directory of resources**, each an addressable service-scoped identity `(namespace_id, local_id)` plus a seq-ordered replayable event stream plus an adapter-owned **open** capability map. Host authority is identity, namespace isolation, subscription routing, and per-resource event ordering, plus an opaque ns-scoped **action-type** registry so every call is typed (no `execute(any)`). "Agent", "session", "chat" are adapter-declared resource kinds, never host types. Capability names are adapter-chosen strings with **zero host-defined meaning and zero host behavioral authority** — the host never reads a CapMap value to change delivery, replay, or routing. **This round's reduction (D08) deletes four R002 carry-overs that no required scenario still needs: the ns-scoped payload-schema descriptor store (FE-CE-008), `invoke_id` on `OutcomeUnknown` (FE-CE-010), the implicit default-subscribe cursor (FE-CE-011), and the per-handle spawned-id set, replaced by a single same-namespace subscription-scope rule (FE-CE-009).** S08 cooperation needs no cross-namespace primitive and no accumulated id set: two ns-local handles, a user pair gesture whose mint supplies an explicit live cursor, and a same-ns subscribe scope are sufficient and structurally isolated.

## R.2 Core concepts and operations

**Namespace.** `namespaces.open(service_descriptor) → NamespaceHandle{ns_id}`; `namespace.teardown(reason)`. Host-authoritative; `ns_id` host-minted per connect, never service-supplied; reconnect yields a new `ns_id`. Teardown disposes all resources under it and force-closes every handle scoped to that namespace. Every `resource_id` is `(namespace_id, local_id)`; raw-id collision across services is structurally impossible.

**Resource.** `namespace.announce(descriptor{local_id, kind:string, capabilities:CapMap})` (adapter-origin only; host verifies uniqueness within namespace); `namespace.retire(local_id, reason)`; `directory.list(ns_id, filter{kind?}) → [descriptor]`; `directory.lookup(ns_id, local_id) → descriptor | ExplicitAbsent`. Content authority = producing adapter; identity/lifecycle authority = host.

**Event stream.** `subscribe(resource_id, from_cursor:int) → Subscription{close(), onNext(Envelope)}`. **`from_cursor` is mandatory and explicit (R003, FE-CE-011 — no implicit default).** `from_cursor=0` replays full history from first seq; `from_cursor=cursor.resolve(id)` begins at the current position (live-only catch-up). `Envelope{resource_id, seq:int, ts, kind:string, payload_schema_id:string, payload:opaque}`. **`payload_schema_id` is an opaque string on the envelope; the host forwards every envelope and refuses none (R003, FE-CE-008 — no delivery gate, no payload-schema descriptor store). Host never interprets payload.** `seq` monotonic per resource, host-assigned on ingest. `cursor.resolve(resource_id) → current_seq`. Unsubscribe = `Subscription.close()`; host also closes on handle-scope destruction and on namespace teardown.

**Open capability map.** `capabilities.get(resource_id) → CapMap{capability_name:string → {supported|not_supported|unknown}}`. The host defines no valid names, assigns no behavioral authority, and never branches on a CapMap entry in delivery/replay/routing/lifecycle. Absence of a name = "unknown", never "unsupported".

**ns-scoped action-type registry (the only host type store).** `action.register(kind, action_type:string, params_type:RegisteredType, result_type:RegisteredType)`; the param/result `RegisteredType`s are declared per namespace and keyed `(ns_id, name)`. Two namespaces may declare the same bare type name with different shapes; neither constrains the other, and the action type is the resource's namespace's to look up. This registry is load-bearing: typed actions must reference it (no `execute(any)`), and it is where FE-CE-006 isolation lives (a shared bare-name key would bleed). The former **payload-schema descriptor store is removed** (FE-CE-008): no host reader remained for it.

**Typed action.** `action.invoke(resource_id, action_type:string, params:RegisteredType) → Result{result_type} | CapabilityAbsent(action_type) | OutcomeUnknown`. **`OutcomeUnknown` carries no token (R003, FE-CE-010); correlation is by the synchronous call site.** **Fixed host invariant (R003, FE-CE-003/009): an invoke whose outcome is unknown is never auto-resubmitted by the host.** The host returns `OutcomeUnknown` and the user/extension decides a retry as a fresh invoke; adapters that want idempotent auto-retry implement re-invocation themselves (they own apply-idempotency). With no auto-replay branch there is no string the host keys behavior on — the covert channel is gone by construction, not by moving it to a field. `CapabilityAbsent` is returned only when the action_type is not registered for the resource's kind.

**Resource-scoped handle (the cooperation primitive).** `handle_for(ns_id, local_id) → SubscriberScope{primary_id, ns_id, subscriptionHandle, typedInvoker}` — minted by the host for any view's primary resource and for each half of a user pair gesture. It carries exactly one primary `(ns_id, local_id)` and exposes no `parent`, no `sibling`, no `enumerateNamespace`, no `directory.list` on the namespace.

**Same-namespace subscription scope (replaces the spawned-id set; R003, FE-CE-009).** Every `subscribe`/`invoke` routed through a handle is scope-checked by a single rule: the target `(ns, local_id)` must satisfy `ns == handle.ns_id`. A handle may therefore subscribe and invoke any resource **within its own namespace** and is denied any foreign-namespace resource (`ScopeDenied`). There is no accumulated `spawned` set and no Result-triggered id append. The no-enumeration property is preserved: a handle still exposes no `directory.list`/`enumerateNamespace`, so it can only reach a same-ns id the extension already holds (e.g. from a `Result`'s declared field or from its own primary). Foreign-namespace isolation (FE-CE-007 class, S06) is unchanged because `ns_D != ns_R`.

## R.3 Boundary rules

A service adapter translates its protocol into: (1) `namespaces.open`; (2) `announce/retire` resources with kind + open CapMap (adapter-chosen names, no host vocabulary); (3) `action.register(kind, action_type, params_type, result_type)` per operation, declaring param/result `RegisteredType`s under its own namespace; (4) a seq-ordered event pump (host assigns seq on ingest), emitting envelopes whose `payload_schema_id` is a label string; (5) explicit `not_supported` CapMap entries for absent features. To state "this service does not support cancel": set `CapMap{"cancel": not_supported}` (informational) AND omit `"cancel"` from the kind's action registry (structural) → any invoke returns `CapabilityAbsent`. `ExplicitAbsent`, `CapabilityAbsent`, `ScopeDenied`, `NamespaceGone`, `OutcomeUnknown` are distinct non-null terminal states; absence is never inferred from null, timeout, or missing messages. The adapter sees only its own namespace; there is no adapter-side API to name, target, or resolve a resource in another namespace. There is no `replay_policy` to learn, no delivery-gate registration step, and no token lifecycle to manage.

## R.4 Extension mechanism

An extension registers a view resolver `{match: kind + payload_schema_id (strings on the envelope), component, optional typed action bindings}`. Selection: exact kind/schema match, most-specific-first. **Default fallback** is the host-builtin generic descriptor view rendering: resource kind, registered action names with typed param schemas, CapMap entries as plain labelled name→state pairs, last envelope's `payload_schema_id` **as a label string**, and the line *"No dedicated view installed; structured data available via subscription."* Unknown content, and an envelope with an unregistered schema label, are never blank and never given a run/agent reading (the gate removal in FE-CE-008 routes them to this same fallback).

An extension receives only the host-minted `SubscriberScope` handle(s). A coordinating view gets its ordinary handle plus, if the user paired, a separately-minted handle. **Pair gesture:** user points at two on-screen resources and says "drive B from A"; host mints `h_A = handle_for(ns_A, a)` and `h_R = handle_for(ns_R, b)`, and **subscribes the secondary handle with `from_cursor=cursor.resolve(id)` at mint time** — the live-only position that closes FE-CE-005 is an explicit host-chosen cursor, not an implicit default. The core records **nothing** about the pairing: closing the view, tearing down a namespace, or reloading the page cannot resurrect it. The extension may render, subscribe/invoke within `{target | target.ns == handle.ns}`, and act on same-namespace resources it holds ids for. It may **not**: enumerate namespaces, derive a foreign id, register free-form events, or hold a global context. Guarantees: resolver absent → generic view; throws → host error-boundary keeps delivering on still-mounted handles; unmounted mid-operation → host force-closes **that view's** handles, resources stay authoritative, re-subscription uses explicit `from_cursor=cursor.resolve(id)`.

## R.6 Deletion / reduction experiments

**Removed this round (no required scenario fails without them):** ns-scoped payload-schema descriptor store (FE-CE-008); `invoke_id` (FE-CE-010); implicit-default-subscribe (FE-CE-011); per-handle spawned-id set, replaced by same-ns subscription scope (FE-CE-009). **Retained because a scenario fails without them:** namespaces (S06), resource-directory (S05), ordered-replayable-stream (S03/S09/S10 delivery), open-capability-map (S11), typed-action (S01/S04/S05/S08), generic-fallback-view (S07/S12), ns-scoped action-type registry (S06/FE-CE-006), same-ns subscription scope (S08/FE-CE-004), pair-mint explicit cursor (S08/FE-CE-005). **Confirmed still-removed:** host-session-object, host-turn/role field, host-event-store, host-resource-directory-B, cross-namespace-edge, persistent-pair-record, envelope payload delivery-gate, typed replay_policy — each with a passing trajectory without it.

## R.7 Second-service onboarding cost

Attach a different-protocol service: (1) `namespaces.open`; (2) `announce/retire` kind + open CapMap (adapter-chosen names); (3) `action.register(kind, action_type, params, result)` with param/result `RegisteredType`s declared under your namespace; (4) seq-ordered pump (host assigns seq); (5) explicit `not_supported` CapMap entries for absent features. Five items. No delivery-gate registration, no replay_policy, no token lifecycle, no spawned-set append, no cross-namespace concept to learn. View-only module: one `{match:kind+schema, component}` resolver. Coordinating view: user-pair gesture + read same-ns resource ids off invoke Results — no protocol code, no knowledge of other adapters' internals.

## R.8 Honest cost and non-goals

Charged costs: ns-local handle mint with `target.ns==handle.ns` scope-check; user-facing pair gesture whose host mint supplies an explicit live cursor; `NamespaceGone` stale-handle semantics; one opaque ns-scoped action-type registry. **This round's accepted loosening:** FE-CE-009 reduction drops provenance-bounded subscribe for a same-ns rule; the no-enumeration property stays, and hiding ungranted same-ns resources from a handle is **not** a claim any S01–S12 needs. **Other trade-offs:** removing `replay_policy` costs adapters a host-declared safe auto-resubmit (they re-invoke themselves); removing the delivery gate costs host-side refusal of unknown-schema envelopes (fallback renders them identically); `invoke_id` removal means retry correlation is by call site only. Weakest: S09 partial (host+adapter joint double-execution); S08 cooperation needs a user gesture, not a standing link; transient text modelled as a resource is heavier than a pure broker; same-ns subscribe permits reaching a guessed same-ns sibling (accepted — bounded to one namespace, no enumeration). Non-goals: no cross-namespace joins/edges, no content search, no host turn/role/session model, no host capability vocabulary, no automatic re-pairing after namespace replacement, no host-verified apply-idempotency.

## R.9 Candidate B — demoted (not the best candidate)

B (typed-reference graph, persistent cross-namespace edges, core relay) is **demoted** this round under D08 (planner: fix FE-CE-007 or demote). Its signature primitive — the persistent cross-ns edge — has **no failing scenario**: S08 is fully served by A's two ns-local handles + pair gesture + spawned-id-in-Result + same-ns subscribe. Worse, `edges.list` leaks core-stored foreign-namespace ids to a scoped handle (FE-CE-007), which removing requires host foreign-id resolution — the data-authorized mint A's pair gesture exists to avoid — so there is **no revision that keeps B's benefit and closes FE-CE-007**. B's claimed advantage (edge persistence survives view lifecycle for auto-reconnect) fails because host-minted per-connect `ns_id` makes any stored `target_namespace_id` stale on runner replacement; the user must re-pair anyway. FE-CE-007 is accepted as fatal and remains **OPEN** against B — demotion withdraws the carrier, it does not repair the invariant. B returns only if a future required scenario demands standing automatic relay without user initiation; no current S01–S12 does. B is retained as an open alternative record, not blended into the core.
