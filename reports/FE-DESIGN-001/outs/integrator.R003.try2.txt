# Best Candidate (R003 integrated) — Namespaced resource/event core with explicit-cursor replay, same-namespace scope, no payload-type gate, no auto-replay, no invoke token

## 1 Core bet

The host core is a **namespaced directory of resources**, each an addressable `(namespace_id, local_id)` plus a seq-ordered replayable event stream plus an adapter-owned **open** capability map. Host authority is identity, namespace isolation, subscription routing, and per-resource ordering only. "Agent", "session", "chat" are adapter-declared kinds, never host types. Capability names are adapter strings with **zero host behavioral authority**. The host **never auto-resubmits** an unknown-outcome call (fixed invariant, not a policy field), **never interprets payloads** (no delivery gate), **never tracks spawned ids** (a handle may subscribe/invoke any resource within its own namespace), and **never supplies an implicit subscription position** (`from_cursor` is mandatory). S08 cooperation needs no cross-namespace primitive and no grant bookkeeping: two user-paired ns-local handles plus the same-namespace subscription rule.

## 2 Core concepts and operations

- **Namespace.** `namespaces.open(descriptor)→NamespaceHandle{ns_id}`; `namespace.teardown(reason)`. `ns_id` host-minted per connect, never service-supplied; teardown disposes resources and force-closes handles. `resource_id=(ns_id,local_id)`; raw-id collision structurally impossible.
- **Resource.** `namespace.announce({local_id,kind,capabilities:CapMap})` (adapter-origin, host checks in-ns uniqueness); `namespace.retire(local_id,reason)`; `directory.list(ns_id,filter{kind?})`; `directory.lookup(ns_id,local_id)→descriptor|ExplicitAbsent`. Content authority=adapter; identity/lifecycle=host.
- **Event stream.** `subscribe(resource_id, from_cursor:int)→Subscription{close(),onNext(Envelope)}` — **from_cursor mandatory**: `0`=from-first replay, `cursor.resolve(resource_id)`=live/return-later catch-up. `Envelope{resource_id,seq,ts,kind,payload_schema_id,payload}`. `seq` host-assigned monotonic per resource. **No delivery gate:** the host forwards every envelope regardless of whether `payload_schema_id` is registered; it never interprets payload. Dedup/reorder keyed `(ns,resource,seq)`. Release=`Subscription.close()` or handle-scope destruction; teardown force-closes.
- **Open capability map.** `capabilities.get(resource_id)→CapMap{name→{supported|not_supported|unknown}}`. Host defines no valid names, assigns no behavioral authority, never branches on a value. Absence="unknown".
- **ns-scoped action-type registry.** `register_type(ns_id,schema_id,descriptor)` **for action params/results only**. Keyed by ns so two services sharing a bare kind/type name do not share a mutable host key. There is **no payload-schema store**; `payload_schema_id` is a resolver label, not a registry entry.
- **Typed action + never-auto-resubmit.** `action.register(kind,action_type,params_type:RegisteredType,result_type:RegisteredType)`; `action.invoke(resource_id,action_type,params)→Result|CapabilityAbsent(action_type)|OutcomeUnknown`. `OutcomeUnknown` carries **no token**. Fixed invariant: the host never re-sends an unknown-outcome call; the user/extension decides a **fresh** invoke; adapters that want idempotent auto-retry implement re-invocation themselves. No `replay_policy` field, no CapMap string toggles host behavior. `CapabilityAbsent` only when action not registered for the kind.
- **Same-namespace subscription-scope handle (the cooperation/isolation primitive).** `handle_for(ns_id,local_id)→SubscriberScope{primary_id,subscriptionHandle,typedInvoker}`. Accessible = **all `(ns,local_id)` with `ns==primary_id.ns`**. `directory/subscribe/invoke` via the handle reject any target whose ns ≠ handle.ns with `ScopeDenied`. Exposes no `parent`, no `enumerateNamespace`, no cross-ns target, no foreign id. This single rule yields both S08 spawned-job observability (job is same-ns) and S06/FE-CE-007 foreign isolation.

Distinct non-null terminals: `ExplicitAbsent, CapabilityAbsent, ScopeDenied, NamespaceGone, OutcomeUnknown`. Absence never inferred from null/timeout.

## 3 Boundary rules (adapter obligation)

A service adapter: (1) `namespaces.open`; (2) `announce/retire` kind+open CapMap; (3) `register_type(ns_id,schema_id,descriptor)` **only for action param/result types**; (4) seq-ordered pump (host assigns seq); (5) `action.register(kind,action_type,params,result)` — **no replay_policy**; (6) explicit `not_supported` CapMap entries for absent features. "No cancel" = `CapMap{"cancel":not_supported}` (informational) AND omit `"cancel"` from the kind's action registry (structural) → `invoke(...,"cancel")→CapabilityAbsent`. The adapter sees only its own namespace; there is no adapter API to name/target another namespace's resource.

## 4 Extension mechanism

A view registers a resolver `{match: kind + payload_schema_id, component, optional typed action bindings}`; selection exact/most-specific-first; **default fallback** = host generic descriptor view rendering kind + registered action names with typed param schemas + CapMap name→state pairs + last envelope's `payload_schema_id` label + the line *"No dedicated view installed; structured data available via subscription."* Unknown content is never blank and never given a run/agent reading; an unregistered-schema envelope lands in this generic view identically (no gate). A view receives only host-minted `SubscriberScope` handles. Coordinating view: its primary handle plus, on user pair gesture, a separately-minted second handle whose `subscribe` the **host** mints with `from_cursor=cursor.resolve(id)` (live; no stale replay). Core records **nothing** about the pairing. Guarantees: resolver absent→generic view; throws→error boundary keeps delivering on still-mounted handles; unmounted mid-op→host force-closes that view's handles; re-subscription uses explicit `from_cursor=cursor.resolve(id)`. Extensions may not enumerate namespaces, derive a foreign id, register free-form events, or hold a global context.
