# 更正：R012 停止依据失效，R013 起继续（不篡改历史）

## 1. 被更正的内容

`STOP-STATE-R012.md` 原按 `control/product/agent-desktop-design-brief.md` 第 64 行
"建议上限：12 轮或 6 小时，先到者停止"把 R012 记为**预算截止**。**该依据已失效**：
用户此前已取消总轮数与总时长上限，现行 `control/design-loop/RUNBOOK.md` 的"停止与恢复"节
明文写着：

> **无总轮数、无总时长上限**；唯一的上界是单次调用超时与连续失败阈值（那是故障保护，不是轮数）。

⇒ **R012 不是预算耗尽，不得再按轮数停止**。用户本次明确授权从 R013 继续。

## 2. 处理方式（保留历史）

`STOP-STATE-R012.md` 的正文**一字未改**，仅在其顶部加了一条指向本文件的更正提示。
旧简报中与 RUNBOOK 冲突的 12 轮/6 小时上限自此不再作为停止依据；
**仍有约束力**的是旧简报第 65–66 行（连续三轮无新成立重大反例可提前交审；
三轮仅换措辞则交出争议）、第 78 行（停止状态为候选待审/预算截止/需决策，
不自行宣布最终架构锁定），以及 RUNBOOK 的三条不可违反规则。

## 3. 空转禁令仍然有效

无总轮数上限 **不等于** 允许空转。仍适用的约束：
- 每轮必须产出新成立的反例或新的删减，否则视为空转；
- 发现产品取舍无法自行决定时，**只暂停该问题**并给出具体选项，其余工作继续；
- 不为凑轮数消费 Sol 额度；不更换指定 reviewer 模型。

## 4. 用户对三条实质问题的裁定（本轮据此执行）

1. **R012 评审的未决项必须进入收敛判定**。不得出现 `open_major=0` 而实质缺陷只躺在待办里
   ⇒ 评审的 S08 判破、S09 冲突及其余有效缺口，本轮**正式立为反例行**（见 `counterexamples.tsv`），
   由机检门与收敛判定一并计入。
2. **`FE-CE-007`**：保留为已淘汰候选 B 的历史缺陷，**不冒充修复、不阻塞 A**，
   无需为"结案"另等用户。
3. **"核心不能自行判断 Agent 运行状态"不是缺陷**。核心只消费权威声明；
   声明缺失或不确定时必须**如实展示**；**禁止**为了让默认界面好看而把业务语义吸收进核心。

   属于"必须如实展示"的缺口，要补渲染规则（补在回退视图，不补在核心语义）。
