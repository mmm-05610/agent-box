# R007 指示（权威材料，逐字交给角色）

## 必须先解的那一处矛盾（唯一目标）

同一份候选文本现在对**同一机制**给出两种互斥承诺：

- `S03` / `S10` 依赖：`subscribe(from_cursor = cursor.resolve(id))` → **宿主重放错过的流**；
- `S08` step5 写的是：新事件是 live、**不重放**。

这不是措辞问题。要求：给出一套**自洽**的重放语义，并说明它按什么维度取值
（例如：按资源 kind？按订阅者声明？按 cursor 是否存在？），然后**在所有场景轨迹上逐条重述**
受影响的那一步，使读者无法再构造出"同一情形两种结果"的序列。

若你选择"两种都存在"，必须给出**决定用哪一种的具名归属者与判定输入**，否则就是矛盾没解。

## 本轮重点攻击面

1. 上述重放语义在 S03 / S08 / S10 三条轨迹上是否还留下可构造矛盾（给事件序列）。
2. 缺少专用视图时，**默认展示是否真的能让人行动**：不是"不空白"，而是
   配置浏览能看到当前值、Git 变更能看出改了什么、长任务能看出还在不在跑。
   给出具名渲染输入与点击后果。
3. **适配器成本**：接入一个新服务必须写几件东西、必须知道哪些核心内部；
   恢复与去重责任落在谁身上，能不能更便宜。给清单和计数。

## 三条接入轨迹必须继续走通（不许退化成散文）

T-Pi（Pi 会话，含工具与授权）、T-Boring（无聊天长任务，离开页面数小时后回来）、
T-Static（不启动任何 agent 的配置 / Git 浏览）。每条给有序步骤 + 每步归属者 +
删除该步核心机制后哪一条场景失败。

- **最小接口草图**：真实类型与签名，不接受"某接口提供某能力"式描述。

  （本轮至少编码：同一 cursor/订阅声明下，S03 与 S08 两种承诺是否会同时发生）。
  实验只能证明所编码的模型，**不得写成产品或协议已验证**。

  不能靠"它能防某个越权"。
