# 原生调度尚未实测的行为（约束 7：不以"参数存在"代替证据）

本轮**薄控制器只补**受控启动/停止、审批状态转换、幂等消息、原子预算、检查点（约束 5），
**未重写原生唤醒/会话系统**。以下原生能力我核到了 help/接口存在，但**没有在本轮做端到端实测**，
不得据此宣称"四组已运行"或"崩溃可自动接管"：

| 行为 | 现状证据 | 未测点 / 风险 |
| --- | --- | --- |
| `/loop`(Skill) / `ScheduleWakeup` 动态续跑 | 接口/技能在册（qodercli 1.1.60） | 未测真机长时唤醒、退避、跨进程存活；本轮控制器不自建 tick，空闲零模型调用已测（`CTL-no-tick-spin`） |
| durable cron（`CronCreate` durable=true） | 工具在册，声明"persist & survive restarts" | 未测真实重启后是否续触发；与 `be-loop.sh resume` 的关系未端到端验证 |
| 会话恢复 `--resume/--continue/--fork-session/--list-sessions` | help 实测存在 | 未测真实 `qodercli` 会话崩溃后精确续接（真会话=真模型，本轮禁） |
| 重复启动（同组二次 `start`） | 控制器有 pid 存活判重（代码） | 未测真机两个并发 `start`/两个控制器的竞态；`--all` 幂等仅 FAKE 层面测 |
| 重叠触发（wake 未结束又来一次） | 无 | **完全未测**：需真调度器与真会话，属正式启动阶段验证 |
| stop 语义 | `stop` 只杀本控制器拥有 pid，已测不伤他人（`CTL-stop-own-only`） | 未测真 `qodercli` 子进程树/`--die-with-parent` 在真负载下的完整回收 |
| 真四组 bwrap 内 `qodercli` 进程 | 同一沙箱画像下 fake 进程隔离全过 | 真进程需网络出口(G1)与最小暴露认证(G2)，**缺口未闭合前未测** |

结论：控制器**逻辑层**行为已用假执行者/假 reviewer 实测（36 项）；**原生调度与真模型会话**的恢复/重叠/长时行为
**留待 I 批准后、正式启动阶段用真机验证**，本轮不虚报。
