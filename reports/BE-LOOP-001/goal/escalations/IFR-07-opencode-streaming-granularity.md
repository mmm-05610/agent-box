# IFR-07（交 I）— OpenCode SSE 流式粒度：产品是否必须保证实时逐字增量？

来源：BE-LOOP-001 / H 组 `goal-H-008` §3 新缺陷 **X17**（仪器 `harness/tests/sse-defect-evidence.test.mjs` 7/7 确定性、含正向对照）。C 已径行处理工程面（批 **增量1c 子集 (b)**：SSE 缓冲 done 冲刷 / pump 错误不吞不无界清 / 残帧不跨轮，`approvals/H-increment1c-sse-framing.md`，均纯可见性/收敛、无新公开枚举）。**唯下列是产品取舍，C 不代 I 定。**

## 事实（measured，非真机对端主张）
若上游 SSE 分帧出现（末帧缺边界 / CRLF / 残帧连累下一帧 / 中途 reader 抛错 / 排空窗提前收摊 / 残帧跨轮），**文本仍完整**（权威记录补发），但：
- **增量性丢失**：用户看着一个字不弹、最后整段刷出（非流式观感）。
- **归因错位**：出口 `tail.outcome` 把「我们没解出分帧」与「该模型不流式」混为 `record-only`，产品侧无法区分（真修需新增判别值，可能触公开投影 M-1 → 已列增量2/待 S 判）。
（②的 CRLF、③⑦残帧是否真由上游 OpenCode 发出=外部对端行为，未测；H/C 均不主张为已成立。）

## 需 I 裁定（一条）
**产品对 Harness 输出的流式契约是什么？**
- (A) **必须保证实时逐字增量流式**（分帧失败=必修缺陷，需 1c 扩到含归因判别 + 可能公开 `tail` 形状变更，经 M-1/S）；或
- (B) **文本完整即可、流式粒度为尽力而为**（分帧退化=可接受降级，X17 记为已知行为、1c 子集已足、不再升级归因判别）。

C 倾向不代答：(A) 会扩公开 `tail` 面、涉产品 UX 承诺；(B) 关乎是否放弃真流式体验。二者皆为产品级取舍。H 明确拒绝以「其实没影响」自关此事实——处理正确。

## 不阻塞项
增量1c 子集 (b)（纯可见性/收敛）C 已放行，无论 (A)/(B) 都应做。IFR-07 只决定：是否进一步做归因判别 + 是否触公开 `tail`/流式 UX 承诺。与 IFR-01/06 并行、不互斥。
