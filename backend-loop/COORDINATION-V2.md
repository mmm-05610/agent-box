## 1. 单一任务板与权限

C 在 reports/BE-LOOP-001/goal/task-board.md（相对 control）维护唯一当前任务板。
每行含任务 ID、owner、批准范围/基线/契约链接、阶段、提交或材料摘要、依赖、下一动作。
长历史保留链接，不继续把当前状态淹没在时间线里。只有 C 改板与审批；组写自身 reports/outbox。
ACK 只是收件，不是批准。C 可批准职责内的设计、内部契约与实现，不逐项向 I 求批。
Core/公开 wire 语义、产品范围、数据保留/迁移及真实 Harness 计费调用仍按既有边界交 I。
Profile 独立能力任务 BE-PROFILE-001 本轮仍为研究/提案，未获 I 批准不可迁移实现。

## 2. 每个任务的循环

领取并 ACK（核对任务/基线/文件范围/契约）→研究或实施→验证→HANDOFF_READY→C 验收集成。
每组最多一个活动实施任务；依赖等待时可做 C 指定的无冲突研究。
提供方与消费方确认公共契约，C 发布版本并指定公共文件单写者；不各自猜测后并行修改。
每次阶段变化先落状态与消息再继续；长任务约每 15 分钟报告实质进展，禁止空报告刷屏。
C 每个调度周期先收取四组 outbox、ACK 并处理依赖，再做自己的工作。
消息用唯一 ID，回复引用 ID；重复收件不重复派工/集成/消费审阅。

## 3. 交接与接管

HANDOFF_READY 必须包含精确提交或文件清单与摘要、测试环境/命令/结果、已知问题，
并明确该任务停止写入。优先由组自行提交，明确路径暂存，不 add -A。
授予 C 常设的有限代提交权：仅对已批准任务、明确停止且交接的文件，核对差量/摘要/
暂存区无他人内容后，按清单提交；不得混入其他任务或改变语义。记录代提交者与来源。
会话不响应不等于停止：超过约 20 分钟无进展先提醒，两周期仍无回复标为疑似停滞，
不凭超时原地写入/杀进程。必要时 C 可将同一批准任务的稳定快照转移至新隔离工作树，
前后摘要必须一致，原树保留；先记录 owner 转移，旧组恢复后须重新 ACK，不再写旧任务。
无法确认快照稳定或所有权时，阻塞该任务并上报 I，不扩大权限。

## 4. 等待不是完成

一项待 I 决定不能阻塞所有组；C 拆出不依赖该决定的已授权工作推进。
组无任务时报告 IDLE，使用已有原生唤醒能力等候，不重复重审已完成工作、不开假任务。
阶段交付不自动结束整体 goal；C 确认本批验收且无后续任务才完成。用户暂停/停止优先。
原生唤醒不可用、会话关闭或确需外部授权时如实报告，不能宣称仍在自动协作。
全部可授权路径均耗尽时，C 汇总唯一待决清单交 I；不要求执行者直接找用户。
