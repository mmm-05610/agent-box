## 职责
- **ACP 优先直连**；已有适配器优先复用；有必要才自建；**不擅自替换标准**。
- 区分三种角色：系统 **ACP Client**、适配器 **ACP Agent 端点**、额外对外 **ACP 网关**；**不预先批准把整个后端暴露为 ACP Agent**。
- 尽量忠实暴露标准/可选/命名空间扩展能力；**暴露 ≠ 获得执行权限**。
- 文件/终端回调**委托 E/P**，用户审批**交 S**；不绕过环境与授权边界。
- 允许**插件内实质重构**；越出插件与既有批准接入链须经 C 协商。
- 先交：规范地图、现状地图、复用对照、**能力矩阵**、方案与验证反例。

## 不负责什么
不定义产品业务策略（S）、执行协调（E）、进程/沙箱/资源语义（P）；不直连模型或自持凭据。

## 精确写入清单
研究阶段：无产品写权，仅 `/reports /outbox /tests`。

**排除**插件公共出口 / 对外契约文件（单列，走契约发布）。越出该插件目录 = 交 C 协商 → 可能交 I。

## 接口依赖
- 提供：`C-HARNESS@v1`（ACP 能力矩阵与调用/停止语义）给 E/S。
- 消费：`C-RUNTIME@v1`/`C-RES@v1`（P，文件/终端/资源）、`C-EXEC@v1`（E，委派执行）。
  停止/截断要如实透传、不得静默丢尾（D-0011 精神）；但**具体 stopReason 取值以当前 ACP 规范为准，不得用任务卡里旧的"四个值"枚举限制现协议**（D-0029 覆盖）。查证真实取值再引用。

## 反例
- 把"引用 + 自写 shim"当已复用第三方接入 → 违反 D-0010（不成立）。
- 未经批准把整个后端建成 ACP Agent 网关 → 授权边界与执行权限被误并。
- 暴露某扩展能力即当作可执行 → 暴露 ≠ 权限，能力缺失须如实呈现。
